Convolutional Neural Networks

A plain neural network sees a photo as one long list of numbers and forgets which pixel sat next to which. A CNN keeps the picture a picture: it slides small learned filters across it, finds edges, then textures, then shapes — and only at the very end hands a compact summary to an ordinary dense network to decide cat or dog. CNN 01 / 11 · The Problem
Why not a plain ANN?
Flattening a photo throws away the one thing that makes it a photo
Dense layer on pixels no notion of "neighbouring pixels"

The ANN from topic 01 takes a list of features. To feed it an image you must flatten the grid into one long row. Below, the same little shape is drawn twice — the second copy just moved 2 pixels right and 1 down. Watch both grids flatten into rows:

The same shape, nudged — as a Dense layer sees it
🚨 To a Dense layer these are two unrelated inputs. Each input neuron is wired to one fixed pixel position. Move the cat and completely different neurons light up — the network has to learn "cat in the top-left", "cat in the middle", "cat bottom-right"… as separate facts.

And it's expensive. The lesson resizes photos to 64 × 64 × 3 = 12,288 numbers. Wire that straight into Dense(128):

$$12{,}288 \times 128 + 128 = 1{,}572{,}992 \text{ weights — in the first layer alone}$$
🔍

Idea 1 — look locally

An edge or an eye is a small pattern. A neuron only needs a 3×3 patch to spot it, not the whole image.

♻️

Idea 2 — share the weights

An edge detector useful in the top-left is just as useful bottom-right. Use the same 9 weights everywhere.

💡 Those two ideas are the whole of convolution. One small filter, slid across every position, finds its pattern wherever it is — with 9 weights instead of 1.5 million.
CNN 02 / 11 · The Input
Images are numbers
A colour photo is three stacked grids — red, green and blue
shape = (height, width, channels) → (64, 64, 3) in the lesson

Every pixel stores three intensities from 0 to 255: how much red, green and blue light. Stack the three grids and you get a 3-D array — a tensor. Hover the picture to read its numbers, or split it into channels:

Live Demo — a 16×16 picture, pixel by pixel
Hover a pixel.
🧮 Why the lesson divides by 255. ImageDataGenerator(rescale=1./255) maps every value from 0–255 into 0–1. Large raw inputs make the first layer's sums huge and the gradients jumpy; small, similar-sized inputs train faster and more stably. The same rescale must be applied at prediction time — that's the test_image / 255.0 line in the notebook.
CNN 03 / 11 · The Core Operation
Convolution
Slide a small window, multiply, add up, write one number — repeat
Conv2D(filters, kernel_size=3) kernel / filter kernel = filterA small grid of weights (here 3×3). These 9 numbers are what the layer learns — exactly like the weights of a Dense neuron. feature map feature mapThe output grid. Each cell says how strongly the filter's pattern appears at that spot of the image.

Here's an 8×8 image of the letter L (1 = ink, 0 = paper). The 3×3 filter sits on a patch, multiplies each pixel by the weight on top of it, adds the 9 products, and writes the total into the output. Then it moves one step and does it again:

Live Demo — convolution, one position at a time
$$\text{out}[i,j]=\sum_{a=0}^{2}\sum_{b=0}^{2}\text{img}[i{+}a,\,j{+}b]\cdot K[a,b]\;+\;b$$
💡 Read the output map. With the vertical-edge filter, the L's upright stroke shows up as two columns: −3 along its left edge and +3 along its right edge. The horizontal foot only appears at its far end. Switch to the horizontal filter and it's the other way round: the foot's top and bottom edges light up and the upright stroke nearly disappears. Same image, different filter, different feature.
📐 Why the output is 6×6, not 8×8. A 3-wide window fits in an 8-wide image only 8 − 3 + 1 = 6 times. In the lesson: 64 − 3 + 1 = 62, so the first Conv2D outputs 62×62. (Keras' default is padding='valid' — no border added. Appendix A1 shows the other options.)
CNN 04 / 11 · Many Filters
Filters & feature maps
filters=32 means 32 different detectors, each producing its own map
Conv2D(filters=32, kernel_size=3, activation='relu') → 32 feature maps

Nobody hand-writes the filters. They start random and backpropagation tunes them exactly like Dense weights. Below are the 8 real filters from the first layer of a small CNN trained on handwritten digits (the live demo on panel 11). Pick a digit and watch every filter scan it:

Real learned filters → their feature maps
positive weight / activationnegative
💡 ReLU on a feature map is the same max(0, z) from topic 01, applied to every cell: "pattern present" stays, "opposite of pattern" becomes 0. Toggle it above — the red regions vanish.

With a colour image each filter is not 3×3 but 3×3×3 — one 3×3 slice per channel, all summed into a single output number. So the lesson's first layer has:

$$(\underbrace{3\times3}_{\text{kernel}}\times\underbrace{3}_{\text{RGB}}+\underbrace{1}_{\text{bias}})\times\underbrace{32}_{\text{filters}} = 896 \text{ parameters}$$
🔁 Compare with panel 01: 896 parameters for a layer that scans the whole 64×64 photo, versus 1.57 million for a Dense layer that sees it once. That saving is weight sharing.
CNN 05 / 11 · Downsampling
Max pooling
Keep the strongest response in each 2×2 block, throw the rest away
MaxPooling2D(pool_size=2, strides=2) → half the height, half the width 0 trainable parameters

This is the L's feature map from panel 03 after ReLU. A 2×2 window jumps two cells at a time and keeps only the biggest number. Nothing is learned here — it's a fixed rule:

Live Demo — 2×2 max pooling, stride 2

Smaller

62×62 → 31×31 is 4× fewer numbers for every later layer to process.

Shift-tolerant

If the edge moves by one pixel inside the 2×2 block, the max is unchanged — small shifts stop mattering.

Wider view

The next 3×3 filter now covers what used to be a 6×6 area — it can see bigger shapes.

📌 Odd sizes round down. In the lesson the second conv layer outputs 29×29; pooling gives ⌊29 / 2⌋ = 14, and the last row and column are simply dropped.

Where do those 813 thousand parameters live?

🔎 The surprise: 98.7% of the weights sit in one Dense layer. The convolutions — the part that actually "sees" — cost about ten thousand parameters. Shrinking what reaches Flatten (more conv/pool blocks, or GlobalAveragePooling2D) is the usual way to make a CNN smaller and less prone to overfitting.
CNN 07 / 11 · The Decision
Flatten & the Dense head
From a stack of feature maps to a single probability
Flatten() → Dense(128, 'relu') → Dense(1, 'sigmoid') → P(dog)

Flatten just unrolls the 3-D block into one row, reading position by position and, at each position, every channel. Here's a tiny 3×3×3 block unrolling — the lesson does the same with 14×14×32:

Flatten — order of unrolling
🧠 Now it's topic 01 again. Those 6,272 numbers are no longer pixels — they're "how much fur-texture here, how much pointy-ear there". From here on it's an ordinary ANN: Dense(128, relu) combines them, and one sigmoid neuron outputs a number between 0 and 1.

What does that one output number mean? flow_from_directory numbers the class folders alphabetically:

folderlabelsigmoid output reads as…
cats/0close to 0 → cat
dogs/1close to 1 → dog
⚠️ Don't guess — print it. training_set.class_indices returns {'cats': 0, 'dogs': 1}. If someone renamed the folders dog/ and kitten/, the meaning of "> 0.5" would silently flip. The notebook hard-codes 'dog' for > 0.5 without checking.

Why one sigmoid neuron and binary_crossentropy, not two softmax neurons? For exactly two classes they're equivalent: P(cat) is simply 1 − P(dog). One neuron is the leaner way to say it.

CNN 08 / 11 · More Data for Free
Data augmentation
Every epoch, every photo arrives slightly flipped, zoomed or sheared
ImageDataGenerator(rescale, shear_range, zoom_range, horizontal_flip)

8,000 training photos is not many. Augmentation creates a slightly different version of each photo every time it is loaded, so the network can't memorise exact pixels — it has to learn "cat-ness". Every epoch Keras reports two pairs of numbers: accuracy / loss on the photos it trains on, and val_accuracy / val_loss on the 2,000 test photos it never learns from. These are the notebook's real values:

trainingvalidation (test_set)
📉 Overfitting, visible in the numbers. Training loss falls every single epoch (0.69 → 0.21). Validation loss bottoms out at 0.456 in epoch 14 and then drifts up to 0.54 — while validation accuracy flattens around 78–79%. After epoch 14 the model is getting better at the 8,000 photos it has seen, not at photos in general.

✅ Fixes to try

  • EarlyStopping(monitor='val_loss', patience=3, restore_best_weights=True) — stop and keep epoch 14's weights.
  • Dropout(0.5) before the Dense layer — where 98.7% of the weights are.
  • Real augmentation (a working shear, rotation) — see panel 08.

⚠️ A naming trap

  • The notebook passes test_set as validation_data. If you then pick the epoch count or settings by watching it, the test set is no longer an unbiased final exam.
  • Cleaner: split a validation set off the training folder, keep test_set for one final evaluate().

⚠️ Four things to fix in the prediction cells.
  1. plt.imshow is used but matplotlib.pyplot is never imported — add import matplotlib.pyplot as plt.
  2. The model is saved and reloaded into model, then never used — predictions still call cnn. Use model.predict to prove the saved file works.
  3. The two cells hard-code a different percentage formula each (p·100 vs 100 − p·100). That only works because the author already knew the answers. A function should pick the formula from the prediction.
  4. "100.00%" is the sigmoid's confidence, not a guarantee — with 79% validation accuracy, roughly 1 in 5 confident answers are still wrong.
python — one function for any photo
import numpy as np
import matplotlib.pyplot as plt
from keras.preprocessing import image

def predict_photo(model, path, class_indices):
    img = image.load_img(path, target_size=(64, 64))
    x = np.expand_dims(image.img_to_array(img) / 255.0, axis=0)
    p = float(model.predict(x, verbose=0)[0][0])        # P(class 1)
    names = {v: k for k, v in class_indices.items()}     # {0: 'cats', 1: 'dogs'}
    label, conf = (names[1], p) if p > 0.5 else (names[0], 1 - p)
    plt.imshow(image.load_img(path)); plt.axis('off'); plt.show()
    print(f"{label} {conf:.2%}")

predict_photo(model, '.../single_prediction/cat_or_dog_1.jpg', training_set.class_indices)

Wrapping Up
Pros & cons
Where CNNs shine, and what they still can't do for you

✅ Strengths

  1. Uses the grid structure: local patterns, found anywhere in the image.
  2. Weight sharing — far fewer parameters than a Dense net on raw pixels.
  3. Learns its own feature hierarchy: edges → textures → parts → objects.
  4. Pooling gives tolerance to small shifts.
  5. Works on anything grid-shaped: photos, X-rays, spectrograms of sound, satellite tiles.

⚠️ Weaknesses

  1. Needs many labelled images — 8,000 photos gave only ~79% in the lesson.
  2. Not naturally rotation- or scale-invariant: it must see those variations (augmentation).
  3. Expensive to train; GPUs make the difference between minutes and hours.
  4. Still a black box — hard to say exactly why it said "dog".
💡 In practice. With a small dataset like the lesson's, the usual move is transfer learning: take a CNN already trained on millions of photos (e.g. MobileNet, ResNet), keep its convolution blocks, and train only a new Dense head. Accuracy on cats vs dogs typically jumps well above 90%.

python — the lesson model in the current Keras style
from keras import Sequential, Input, layers, callbacks, utils

train = utils.image_dataset_from_directory('dataset/training_set', image_size=(64, 64),
                                          batch_size=32, label_mode='binary')
test  = utils.image_dataset_from_directory('dataset/test_set', image_size=(64, 64),
                                          batch_size=32, label_mode='binary')

cnn = Sequential([
    Input(shape=(64, 64, 3)),
    layers.Rescaling(1./255),
    layers.RandomFlip('horizontal'), layers.RandomZoom(0.2),
    layers.Conv2D(32, 3, activation='relu'), layers.MaxPooling2D(2),
    layers.Conv2D(32, 3, activation='relu'), layers.MaxPooling2D(2),
    layers.Flatten(),
    layers.Dropout(0.5),
    layers.Dense(128, activation='relu'),
    layers.Dense(1, activation='sigmoid'),
])
cnn.compile(optimizer='adam', loss='binary_crossentropy', metrics=['accuracy'])
cnn.fit(train, validation_data=test, epochs=25,
        callbacks=[callbacks.EarlyStopping(monitor='val_loss', patience=3, restore_best_weights=True)])
📌 Note on Rescaling inside the model. Because the model now divides by 255 itself, prediction code must pass raw 0–255 pixels — don't divide twice. That's the main trap when switching from the lesson's style.
