Your First CNN — Cats vs Dogs with Keras

Lesson 1 fit a single neuron to nine numbers. This lesson trains a real image classifier: 8,000 photos of cats and dogs, two convolution blocks, a dense head, and a single sigmoid output that says "dog" or "cat". We load the photos straight from folders, augment them on the fly, train for 25 epochs, read the training log for signs of overfitting, and finally ask the model about two photos it has never seen.

ImageDataGenerator: Rescaling & Augmentation

Two generators: one for training (scales and randomly alters each photo), one for testing (only scales).

from tensorflow.keras.preprocessing.image import ImageDataGenerator # Training data generator with augmentation train_datagen = ImageDataGenerator( rescale=1./255, # Normalize pixel values to [0,1] shear_range=0.2, # Apply a slight diagonal transformation (shear) zoom_range=0.2, # Apply random zoom-in effect horizontal_flip=True # Flip images horizontally ) # Testing data generator — only normalization, no augmentation test_datagen = ImageDataGenerator(rescale=1./255)
argumentwhat it actually does
rescale=1./255Multiplies every pixel by 1/255, so 0–255 becomes 0–1. Small inputs keep the gradients stable.
shear_range=0.2Random shear angle between −0.2° and +0.2° — in degrees.
zoom_range=0.2Random zoom factor in [0.8, 1.2], picked separately for width and height.
horizontal_flip=TrueMirrors the photo left↔right half of the time.
Why augment at all? 8,000 photos is not many for a network with 800,000 weights. A fresh random flip/zoom every time a photo is loaded means the model rarely sees the exact same pixels twice, so it has to learn "cat-ness" instead of memorising particular images.
shear_range=0.2 does almost nothing. Keras documents shear_range as an angle in degrees, so 0.2 tilts a 64-pixel image by about a fifth of a pixel at the edge — invisible. For a shear you can actually see, use something like shear_range=10. The augmentation demo in the deck lets you compare 0.2 with 20 side by side.
Never augment the test set. test_datagen only rescales. The test set should measure the model on photos exactly as they'll arrive in real use.

flow_from_directory: Folders Become Labelled Batches

training_set = train_datagen.flow_from_directory( '/content/dataset/CNN_dog_cat_dataset/dataset/training_set', target_size=(64, 64), batch_size=32, class_mode='binary' ) test_set = test_datagen.flow_from_directory( '/content/dataset/CNN_dog_cat_dataset/dataset/test_set', target_size=(64, 64), batch_size=32, class_mode='binary' )
Found 8000 images belonging to 2 classes. Found 2000 images belonging to 2 classes.
argumentmeaning
directoryEach sub-folder is one class. No CSV, no label column.
target_size=(64, 64)Every photo is resized to 64×64 on load, whatever its original size or shape.
batch_size=32Each step hands the model 32 photos: a tensor shaped (32, 64, 64, 3).
class_mode='binary'One label per photo, 0 or 1 — matches a single sigmoid output.
Which class is 1? Keras numbers the folders alphabetically: cats → 0, dogs → 1. So the model's output is P(dog). You can confirm it in one line:
print(training_set.class_indices)
{'cats': 0, 'dogs': 1}
64×64 is small on purpose. A 64×64×3 photo is 12,288 numbers; a 256×256×3 photo is 196,608. Small images train much faster on a free Colab GPU — at the cost of fine detail (whiskers, fur texture) the model can no longer see.

Building the Model: Two Conv + Pool Blocks

from keras.models import Sequential from keras.layers import Conv2D, MaxPooling2D, Flatten, Dense cnn = Sequential() # first convolution layer cnn.add(Conv2D(filters=32, kernel_size=3, activation='relu', input_shape=[64, 64, 3])) cnn.add(MaxPooling2D(pool_size=2, strides=2)) # second convolution layer cnn.add(Conv2D(filters=32, kernel_size=3, activation='relu')) cnn.add(MaxPooling2D(pool_size=2, strides=2))
piecemeaning
Conv2D(filters=32, ...)32 different learned filters slide over the image; each produces its own feature map.
kernel_size=3Each filter looks at a 3×3 patch at a time (3×3×3 on a colour image).
activation='relu'Every value in the feature maps goes through max(0, z) — negative responses become 0.
input_shape=[64, 64, 3]Only on the first layer: height, width, colour channels.
MaxPooling2D(2, strides=2)Keeps the largest value in each 2×2 block — halves height and width. No weights.

Follow the shape of one photo through the two blocks:

layeroutput shapeparameters
input(64, 64, 3)0
Conv2D 32 · 3×3(62, 62, 32)(3·3·3 + 1) · 32 = 896
MaxPooling2D(31, 31, 32)0
Conv2D 32 · 3×3(29, 29, 32)(3·3·32 + 1) · 32 = 9,248
MaxPooling2D(14, 14, 32)0
$$\text{out} = n - k + 1 \qquad 64 - 3 + 1 = 62$$

With the default padding='valid', a 3×3 filter fits 62 times across a 64-pixel row. Pooling then halves, rounding down: ⌊29/2⌋ = 14.

Why two blocks? The first block's filters see 3×3 pixels — enough for edges and colour changes. After pooling, the second block's 3×3 filters cover a much wider patch of the original photo, so they can combine edges into textures and parts: fur, ears, eyes. See it happen live in the deck's Live CNN demo.
The notebook's output shows a UserWarning: "Do not pass an input_shape/input_dim argument to a layer…". It still works. The current Keras style is to start with cnn.add(Input(shape=(64, 64, 3))) and drop input_shape from the Conv2D.

Flatten & the Dense Head

# Flatten cnn.add(Flatten()) # Fully Connected cnn.add(Dense(units=128, activation='relu')) cnn.add(Dense(units=1, activation='sigmoid')) # because this is binary classification
layeroutput shapeparameters
Flatten(6272,)0  ·  14·14·32 = 6,272
Dense 128 relu(128,)6272·128 + 128 = 802,944
Dense 1 sigmoid(1,)128 + 1 = 129
whole model813,217
From here on it's Lesson 1 again. Flatten unrolls the 14×14×32 block of feature maps into one row of 6,272 numbers, and the rest is an ordinary ANN. The convolution blocks are the "eyes"; the dense layers are the "brain" that decides.
$$\hat p = \sigma(z) = \frac{1}{1+e^{-z}} \in (0, 1)$$

One sigmoid neuron outputs P(class 1) = P(dog). P(cat) is simply 1 − p̂, so a second output neuron would add nothing.

Where the weights live. 802,944 of the 813,217 parameters — 98.7% — sit in the single Dense(128) layer. The convolution layers that actually "see" cost about 10,000. That imbalance is a big part of why this model overfits (topic 10).

Compile & Fit

cnn.compile(optimizer='adam', loss='binary_crossentropy', metrics=['accuracy']) cnn.fit(x=training_set, validation_data=test_set, epochs=25)
argumentmeaning
optimizer='adam'Adam with its default learning rate (0.001).
loss='binary_crossentropy'The cost function for one sigmoid output and 0/1 labels.
metrics=['accuracy']Also report the fraction of photos classified correctly. Not used for training.
x=training_setThe generator: no separate y is needed — labels come with each batch.
validation_data=test_setAfter each epoch, measure loss and accuracy on the 2,000 test photos.
epochs=2525 full passes over the 8,000 training photos.
$$L = -\big[\,y\log\hat p + (1-y)\log(1-\hat p)\,\big]$$

Binary cross-entropy: tiny when a dog (y=1) gets p̂ near 1, huge when the model is confidently wrong.

Why "250/250"? 8,000 photos ÷ 32 per batch = 250 batches. Each batch is one forward pass, one backpropagation, one Adam update — so one epoch is 250 weight updates, and the whole fit is 6,250. At ~27 seconds an epoch, training took about 11 minutes.

Save & Load the Trained Model

Eleven minutes of training disappears when the Colab session ends — unless you save it to Drive:

from tensorflow.keras.models import load_model # 1. Save the trained model to a file cnn.save('/content/drive/MyDrive/cat_dog_cnn_model.keras') # 2. Load the saved model model = load_model('/content/drive/MyDrive/cat_dog_cnn_model.keras')
What the .keras file holds: the architecture, all 813,217 trained weights, and the compile settings (optimizer state included). Next session you skip straight to load_model(...) and predict — no re-training.
The notebook loads the file into model, but every prediction afterwards still calls cnn.predict(...) — the original in-memory model. To actually prove the saved file works, predict with model.

This is overfitting. Training loss falls every epoch, all the way to 0.21. Validation loss is lowest at epoch 14 (0.456) and then climbs. Validation accuracy stops improving around 79% while training accuracy keeps rising to 91%. After epoch 14 the model is getting better at the 8,000 photos it has seen, not at photos in general.

Keras can stop at the right epoch for you and keep the best weights:

from keras.callbacks import EarlyStopping stop = EarlyStopping(monitor='val_loss', patience=3, restore_best_weights=True) cnn.fit(x=training_set, validation_data=test_set, epochs=25, callbacks=[stop])
Other things worth trying: Dropout(0.5) right after Flatten (where 98.7% of the weights are), augmentation that actually changes the photo (a real shear, small rotations), or a third Conv + Pool block so less reaches the big Dense layer.
A subtle point. The notebook uses test_set as validation_data. If you then choose the number of epochs by watching it, the test set has helped pick the model and is no longer a fully independent final exam. The clean version splits a separate validation set off the training folder.

A Cleaner Prediction Function

The two prediction cells are the same code copied twice, each with a print line that only works for its own photo. One function replaces both, uses the reloaded model, and reads the class names from class_indices instead of assuming them:

import numpy as np import matplotlib.pyplot as plt from keras.preprocessing import image def predict_photo(model, path, class_indices): img = image.load_img(path, target_size=(64, 64)) x = np.expand_dims(image.img_to_array(img) / 255.0, axis=0) p = float(model.predict(x, verbose=0)[0][0]) # P(class 1) names = {v: k for k, v in class_indices.items()} # {0: 'cats', 1: 'dogs'} label, conf = (names[1], p) if p > 0.5 else (names[0], 1 - p) plt.imshow(image.load_img(path)); plt.axis('off'); plt.show() print(f"{label} {conf:.2%}") folder = '/content/dataset/CNN_dog_cat_dataset/dataset/single_prediction/' for name in ['cat_or_dog_1.jpg', 'cat_or_dog_2.jpg']: predict_photo(model, folder + name, training_set.class_indices)
dogs 100.00% cats 76.55%
"100.00%" is not a guarantee. It's how sure the sigmoid is, not how often it's right. With about 79% validation accuracy, roughly one confident answer in five is still wrong. A model can be very confident and very wrong at the same time.
Going further. With only 8,000 photos, the usual next step is transfer learning: start from a CNN already trained on millions of images (e.g. MobileNetV2), keep its convolution layers, and train only a new dense head. On cats vs dogs that typically pushes accuracy well above 90%.
