main.py: Assembling the App

main.py contains no endpoints at all. It creates the app object and connects the pieces:

main.py
from pathlib import Path from fastapi import FastAPI from fastapi.staticfiles import StaticFiles import messages import users from database import init_db STATIC_DIR = Path(__file__).parent / "static" app = FastAPI(title="Messages API", version="1.5") @app.on_event("startup") def startup(): init_db() @app.middleware("http") async def no_cache_frontend(request, call_next): response = await call_next(request) if request.url.path == "/" or request.url.path.endswith(".html"): response.headers["Cache-Control"] = "no-cache" return response app.include_router(users.router) app.include_router(messages.router) # Frontend (mounted last so API routes take priority) app.mount("/", StaticFiles(directory=STATIC_DIR, html=True), name="static")
LineWhat it does
STATIC_DIR = Path(__file__).parent / "static"An absolute path to static/, built from this file's own location. The app works no matter which folder you start Uvicorn from (as long as Uvicorn can import main).
FastAPI(title=…, version=…)The application. The title and version appear at the top of /docs. "1.5" hints at how many rounds of vibe-coding it took.
@app.on_event("startup")Runs init_db() once, when Uvicorn starts and before the first request, so the tables always exist.
@app.middleware("http")A middleware wraps every request. call_next(request) runs the normal route, then this code edits the response on its way out.
include_router(...)Plugs in the endpoints defined in users.py and messages.py.
app.mount("/", StaticFiles(..., html=True))Serves files from static/. html=True means a request for / returns index.html.
Why the mount comes last. FastAPI checks routes in the order they were added. A mount at / matches every path. If it came first, GET /messages would look for a file called static/messages, find none, and return 404. Routers first, catch-all last.
Why the no-cache middleware? While vibe-coding you edit index.html constantly. Browsers cache HTML, so a refresh could show the old page. Cache-Control: no-cache tells the browser to check with the server every time. API responses are left alone.
Newer FastAPI versions mark on_event as deprecated (it still works). The modern form is a lifespan function. See topic 12.

database.py: Connection & Tables

A connection per request

database.py
import sqlite3 from contextlib import contextmanager from datetime import datetime, timezone DB_PATH = "messages.db" @contextmanager def get_db(): conn = sqlite3.connect(DB_PATH) conn.row_factory = sqlite3.Row try: yield conn conn.commit() finally: conn.close() def now() -> str: return datetime.now(timezone.utc).isoformat()

Every endpoint uses it the same way: with get_db() as db: db.execute(...).

  • @contextmanager turns the function into something you can use in a with block. The code before yield runs on entry, and the code after it runs on exit.
  • row_factory = sqlite3.Row lets rows be read by column name: row["name"], and dict(row) gives a dictionary. That's what makes User(**dict(row)) work later.
  • conn.commit() runs only if the block finished without an exception. If an endpoint raises HTTPException halfway through, the commit is skipped and close() discards the half-done changes. Each request is all-or-nothing.
  • now() stores time as an ISO-8601 string in UTC, e.g. 2026-10-18T17:37:05.239049+00:00. SQLite has no real date type, and this format sorts correctly as text.

Creating the tables

def init_db(): with get_db() as db: db.execute( """ CREATE TABLE IF NOT EXISTS users ( id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL UNIQUE COLLATE NOCASE, password_hash TEXT NOT NULL, created_at TEXT NOT NULL ) """ ) db.execute( """ CREATE TABLE IF NOT EXISTS sessions ( token TEXT PRIMARY KEY, user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE, created_at TEXT NOT NULL ) """ ) db.execute( """ CREATE TABLE IF NOT EXISTS messages ( id INTEGER PRIMARY KEY AUTOINCREMENT, sender TEXT NOT NULL, content TEXT NOT NULL, created_at TEXT NOT NULL, updated_at TEXT NOT NULL ) """ )
SQLMeaning
IF NOT EXISTSSafe to run on every start: an existing table is left alone, data included.
INTEGER PRIMARY KEY AUTOINCREMENTSQLite chooses the id (1, 2, 3…) and never reuses a deleted one. That's why POST doesn't send an id.
UNIQUE COLLATE NOCASENo two users may share a name, and "Itay" and "itay" count as the same name, both for the constraint and for WHERE name = ?.
REFERENCES users(id)A foreign key: each session belongs to a user.

Migrations: changing tables that already have data

columns = [r["name"] for r in db.execute("PRAGMA table_info(messages)")] if "user_id" not in columns: db.execute("ALTER TABLE messages ADD COLUMN user_id INTEGER REFERENCES users(id)") user_columns = [r["name"] for r in db.execute("PRAGMA table_info(users)")] for column, kind in (("avatar", "BLOB"), ("avatar_type", "TEXT"), ("avatar_preset", "TEXT")): if column not in user_columns: db.execute(f"ALTER TABLE users ADD COLUMN {column} {kind}")

This is the history of the vibe-coding session, preserved in code. The first version had only messages with a free-text sender. Users came later, then avatars. CREATE TABLE IF NOT EXISTS never changes an existing table, so for databases created by older versions the code asks SQLite which columns exist (PRAGMA table_info) and adds the missing ones with ALTER TABLE … ADD COLUMN.

sqlite> SELECT id, user_id, sender, content FROM messages LIMIT 3; 3|NULL|itay|hello ← posted before accounts existed 4|1|itay|hi 5|1|itay|how are you ?
The f-string in the last ALTER TABLE is safe only because column and kind come from a fixed tuple in the code. Table and column names can't be ? parameters. Never build SQL this way from user input.

users.py: Passwords & the Logged-in User

Never store the password, only a salted hash

users.py
def hash_password(password: str) -> str: salt = secrets.token_hex(16) digest = hashlib.pbkdf2_hmac("sha256", password.encode(), salt.encode(), 200_000).hex() return f"{salt}${digest}" def verify_password(password: str, stored: str) -> bool: salt, digest = stored.split("$", 1) candidate = hashlib.pbkdf2_hmac("sha256", password.encode(), salt.encode(), 200_000).hex() return hmac.compare_digest(candidate, digest)
  • Hash: a one-way function. You can turn "1234" into the digest, but you can't turn the digest back into "1234". If the database leaks, the passwords don't.
  • Salt: 16 random bytes, different per user. Two users with password "1234" get completely different hashes, so precomputed "rainbow tables" are useless.
  • 200,000 rounds of PBKDF2 make each guess deliberately slow, around 0.1 s. That's nothing for one login, but a disaster for an attacker trying billions of guesses.
  • The stored value is salt$digest in one column. verify_password splits it, re-hashes the typed password with the same salt, and compares.
  • hmac.compare_digest takes the same time whether the first character or the last one differs, so response timing reveals nothing.

Who is calling? current_user

def current_user(authorization: Optional[str] = Header(None)) -> dict: if not authorization or not authorization.lower().startswith("bearer "): raise HTTPException(status_code=401, detail="Not logged in") token = authorization[7:].strip() with get_db() as db: row = db.execute( "SELECT u.id, u.name, u.created_at FROM sessions s JOIN users u ON u.id = s.user_id " "WHERE s.token = ?", (token,), ).fetchone() if row is None: raise HTTPException(status_code=401, detail="Invalid or expired session") return {**dict(row), "token": token}
  • Header(None): the parameter name authorization is matched to the HTTP header Authorization (headers are case-insensitive, and underscores become dashes).
  • The header must look like Bearer Xq3vN8…. [7:] cuts off the 7 characters of "Bearer ".
  • One SQL JOIN goes from token → session row → user row. No matching session means 401.
  • The token is returned too, because /logout needs to know which session to delete.

This function is not an endpoint. Endpoints ask for it:

@router.post("/messages", ...) def create_message(msg: MessageCreate, me: dict = Depends(current_user)): ... # only runs if current_user() returned a user
One function guards 9 endpoints. Every endpoint with Depends(current_user) is protected. The token check is written once, and FastAPI runs it before the endpoint body. It also shows up in /docs as an authorization header field.

users.py: Pydantic Models (the API's Contract)

Each model is a class describing the shape of some JSON. FastAPI uses models in two directions: to validate what comes in and to shape what goes out.

users.py
AvatarField = Field(None, max_length=700_000, description="Uploaded image as a data URL (data:image/...;base64,...)") PresetField = Field(None, description="Id of a ready-made face from GET /avatars") class Credentials(BaseModel): name: str = Field(..., min_length=2, max_length=30) password: str = Field(..., min_length=4, max_length=128) class UserCreate(Credentials): avatar: Optional[str] = AvatarField avatar_preset: Optional[str] = PresetField class UserPatch(BaseModel): name: Optional[str] = Field(None, min_length=2, max_length=30) password: Optional[str] = Field(None, min_length=4, max_length=128) avatar: Optional[str] = AvatarField avatar_preset: Optional[str] = PresetField class AvatarPreset(BaseModel): id: str url: str class User(BaseModel): id: int name: str created_at: str has_avatar: bool class LoginResult(BaseModel): token: str user: User
ModelDirectionUsed by
CredentialsinPOST /login: name + password, both required (... means required).
UserCreateinPOST /users, PUT /users/{id}. Inherits name + password and adds two optional avatar fields.
UserPatchinPATCH /users/{id}. Everything optional, because a PATCH sends only what changes.
UseroutEvery response that returns a user.
LoginResultoutPOST /login: a token plus a nested User.
Look at what User does not have: password_hash and the avatar bytes. The response model is a whitelist. Even if a query returned the hash, response_model=User would drop it before the JSON leaves the server. Separate in/out models are how an API avoids leaking data.
Why max_length=700_000 for a 500 KB image? The avatar arrives as base64 text, which is about 4/3 the size of the raw bytes: 500 KB × 4/3 ≈ 667 K characters, plus the data:image/png;base64, prefix. Pydantic rejects anything far too large (422) before it is even decoded. The exact 500 KB check happens after decoding (topic 7).

users.py: The /users Endpoints

Three helpers the endpoints share

users.py
USER_COLUMNS = "id, name, created_at, (avatar IS NOT NULL OR avatar_preset IS NOT NULL) AS has_avatar" def fetch_user(db, user_id: int) -> User: row = db.execute(f"SELECT {USER_COLUMNS} FROM users WHERE id = ?", (user_id,)).fetchone() if row is None: raise HTTPException(status_code=404, detail="User not found") return User(**dict(row)) def require_self(me: dict, user_id: int): if me["id"] != user_id: raise HTTPException(status_code=403, detail="You can only modify your own account")

USER_COLUMNS selects exactly the four fields of the User model. has_avatar is computed by SQL (a 0/1 that Pydantic turns into false/true), so the image bytes are never loaded just to list users. fetch_user turns "not found" into a 404 in one place. require_self turns "not you" into a 403.

Read

@router.get("/users", response_model=List[User]) def list_users(): with get_db() as db: rows = db.execute(f"SELECT {USER_COLUMNS} FROM users ORDER BY id").fetchall() return [User(**dict(r)) for r in rows] @router.get("/users/me", response_model=User) def get_me(me: dict = Depends(current_user)): with get_db() as db: return fetch_user(db, me["id"]) # ... /users/{user_id}/avatar (topic 7) ... @router.get("/users/{user_id}", response_model=User) def get_user(user_id: int): with get_db() as db: return fetch_user(db, user_id)
Order matters: /users/me is declared before /users/{user_id}. Routes are tried top to bottom. If {user_id} came first, GET /users/me would match it with user_id = "me", fail the int conversion, and return 422. Put fixed paths before parameterised ones.

The frontend calls GET /users/me when the page loads. If a token in localStorage still works, you're logged straight back in.

Create: POST /users

@router.post("/users", response_model=User, status_code=status.HTTP_201_CREATED) def create_user(user: UserCreate): name = user.name.strip() mime, data = decode_avatar(user.avatar) if user.avatar else (None, None) preset = check_preset(user.avatar_preset) if user.avatar_preset and not data else None with get_db() as db: if db.execute("SELECT 1 FROM users WHERE name = ?", (name,)).fetchone(): raise HTTPException(status_code=409, detail="That name is already taken") cur = db.execute( "INSERT INTO users (name, password_hash, created_at, avatar, avatar_type, avatar_preset) " "VALUES (?, ?, ?, ?, ?, ?)", (name, hash_password(user.password), now(), data, mime, preset), ) return fetch_user(db, cur.lastrowid)
  1. Validate everything before touching the database: decode the uploaded avatar (or check the preset id). An uploaded photo wins over a preset.
  2. SELECT 1 … WHERE name = ?: is the name taken? Thanks to COLLATE NOCASE this also catches "ITAY" vs "itay". If so, 409 Conflict.
  3. INSERT with the hashed password. ? placeholders, never f-strings, keep it safe from SQL injection.
  4. cur.lastrowid is the id SQLite just generated. Read the row back and return it with 201 Created.

Change: PUT vs PATCH

@router.put("/users/{user_id}", response_model=User) def replace_user(user_id: int, user: UserCreate, me: dict = Depends(current_user)): require_self(me, user_id) with get_db() as db: save_user(db, user_id, {"name": user.name.strip(), "password": user.password}) db.execute( "UPDATE users SET avatar = NULL, avatar_type = NULL, avatar_preset = NULL WHERE id = ?", (user_id,), ) save_user(db, user_id, {"avatar": user.avatar, "avatar_preset": user.avatar_preset}) return fetch_user(db, user_id) @router.patch("/users/{user_id}", response_model=User) def update_user(user_id: int, user: UserPatch, me: dict = Depends(current_user)): require_self(me, user_id) fields = user.model_dump(exclude_unset=True, exclude_none=True) if "name" in fields: fields["name"] = fields["name"].strip() with get_db() as db: save_user(db, user_id, fields) return fetch_user(db, user_id)

This is the PUT/PATCH difference from the deck, in real code:

  • PUT takes a full UserCreate (name and password required), wipes the avatar, then sets whatever avatar was sent. If none was sent, the user ends up with none: the resource is replaced.
  • PATCH takes a UserPatch. model_dump(exclude_unset=True, exclude_none=True) returns only the fields the client actually sent. {"avatar_preset": "15006…"} becomes a one-key dict, so only the avatar changes.
def save_user(db, user_id: int, fields: dict): if "name" in fields: taken = db.execute( "SELECT 1 FROM users WHERE name = ? AND id != ?", (fields["name"], user_id) ).fetchone() if taken: raise HTTPException(status_code=409, detail="That name is already taken") db.execute("UPDATE users SET name = ? WHERE id = ?", (fields["name"], user_id)) db.execute("UPDATE messages SET sender = ? WHERE user_id = ?", (fields["name"], user_id)) if "password" in fields: db.execute( "UPDATE users SET password_hash = ? WHERE id = ?", (hash_password(fields["password"]), user_id), ) if fields.get("avatar"): mime, data = decode_avatar(fields["avatar"]) db.execute( "UPDATE users SET avatar = ?, avatar_type = ?, avatar_preset = NULL WHERE id = ?", (data, mime, user_id), ) elif fields.get("avatar_preset"): db.execute( "UPDATE users SET avatar = NULL, avatar_type = NULL, avatar_preset = ? WHERE id = ?", (check_preset(fields["avatar_preset"]), user_id), )

One helper serves both PUT and PATCH: it updates only the keys present in fields. Note AND id != ?: renaming yourself to your own name is not a conflict. Renaming also rewrites sender on all your old messages, because the name is stored twice (see topic 12).

Delete & check: DELETE HEAD

@router.delete("/users/{user_id}", status_code=status.HTTP_204_NO_CONTENT) def delete_user(user_id: int, me: dict = Depends(current_user)): require_self(me, user_id) with get_db() as db: db.execute("DELETE FROM sessions WHERE user_id = ?", (user_id,)) db.execute("DELETE FROM users WHERE id = ?", (user_id,)) return Response(status_code=status.HTTP_204_NO_CONTENT) @router.head("/users/{user_id}") def head_user(user_id: int): with get_db() as db: fetch_user(db, user_id) return Response(status_code=status.HTTP_200_OK)
Why delete sessions by hand when the table says ON DELETE CASCADE? SQLite ignores foreign keys unless each connection runs PRAGMA foreign_keys = ON, and get_db() never does. The explicit DELETE FROM sessions makes sure the deleted user's tokens stop working.

HEAD returns 200 or 404 (from fetch_user) with no body. FastAPI doesn't create HEAD routes automatically, which is why they are written out.

users.py: Avatars (Upload or Pick a Face)

Uploaded photos arrive as data URLs

users.py
MAX_AVATAR_BYTES = 500_000 DATA_URL_RE = re.compile(r"^data:(image/(?:png|jpeg|webp|gif));base64,(.+)$", re.S) def decode_avatar(data_url: str): match = DATA_URL_RE.match(data_url) if not match: raise HTTPException(status_code=422, detail="Avatar must be a PNG, JPEG, WebP or GIF image") try: data = base64.b64decode(match.group(2), validate=True) except (binascii.Error, ValueError): raise HTTPException(status_code=422, detail="Avatar image data is corrupted") if len(data) > MAX_AVATAR_BYTES: raise HTTPException(status_code=413, detail="Avatar image is too large (max 500 KB)") return match.group(1), data

A JSON body can only carry text, so the browser crops the photo to 256×256 on a canvas and sends it as a data URL: data:image/jpeg;base64,/9j/4AAQ…. The regex checks the type and captures the MIME type (group 1) and the base64 text (group 2). b64decode(validate=True) turns it back into bytes and rejects junk. The bytes go into a BLOB column. Three different failures, three precise status codes: wrong type 422, corrupted 422, too big 413 Payload Too Large.

Ready-made faces

AVATAR_PRESETS = [ "1534528741775-53994a69daeb", "1500648767791-00dcc994a43e", "1494790108377-be9c29b29330", # ... 10 Unsplash photo ids ... ] def preset_url(preset: str, size: int = 256) -> str: return f"https://images.unsplash.com/photo-{preset}?w={size}&h={size}&fit=crop&crop=faces&q=80" def check_preset(preset: str) -> str: if preset not in AVATAR_PRESETS: raise HTTPException(status_code=422, detail="Unknown avatar preset") return preset @router.get("/avatars", response_model=List[AvatarPreset]) def list_avatar_presets(): return [AvatarPreset(id=p, url=preset_url(p)) for p in AVATAR_PRESETS]

A preset is stored as just its id (avatar_preset column). check_preset makes sure the id is on the list, so a client can't point your app at an arbitrary URL.

Serving the picture: three possible answers

@router.get("/users/{user_id}/avatar") def get_avatar(user_id: int, if_none_match: Optional[str] = Header(None)): with get_db() as db: row = db.execute( "SELECT avatar, avatar_type, avatar_preset FROM users WHERE id = ?", (user_id,) ).fetchone() if row is not None and row["avatar"] is None and row["avatar_preset"]: return RedirectResponse(preset_url(row["avatar_preset"]), headers={"Cache-Control": "no-cache"}) if row is None or row["avatar"] is None: raise HTTPException(status_code=404, detail="No avatar") etag = '"' + hashlib.sha1(row["avatar"]).hexdigest() + '"' headers = {"ETag": etag, "Cache-Control": "no-cache"} if if_none_match == etag: return Response(status_code=status.HTTP_304_NOT_MODIFIED, headers=headers) return Response(content=row["avatar"], media_type=row["avatar_type"], headers=headers)
SituationResponse
user picked a preset307 redirect to the Unsplash URL. The browser follows it on its own, so <img src="/users/2/avatar"> just works.
no such user / no avatar404. The frontend falls back to a coloured initial.
uploaded photo, first time200 with the raw image bytes and media_type (e.g. image/jpeg). Not JSON: an endpoint can return any content type.

The chat page polls every second and redraws avatars. ETag + 304 means each repeat costs a few header bytes instead of a full image download.

users.py: Login & Logout

users.py
@router.post("/login", response_model=LoginResult) def login(credentials: Credentials): with get_db() as db: row = db.execute( "SELECT * FROM users WHERE name = ?", (credentials.name.strip(),) ).fetchone() if row is None or not verify_password(credentials.password, row["password_hash"]): raise HTTPException(status_code=401, detail="Wrong name or password") token = secrets.token_urlsafe(32) db.execute( "INSERT INTO sessions (token, user_id, created_at) VALUES (?, ?, ?)", (token, row["id"], now()), ) return LoginResult(token=token, user=fetch_user(db, row["id"])) @router.post("/logout", status_code=status.HTTP_204_NO_CONTENT) def logout(me: dict = Depends(current_user)): with get_db() as db: db.execute("DELETE FROM sessions WHERE token = ?", (me["token"],)) return Response(status_code=status.HTTP_204_NO_CONTENT)
  • One message for both failures. "Wrong name or password", whether the name doesn't exist or the password is wrong. A message saying "no such user" would let anyone discover which names are registered.
  • secrets.token_urlsafe(32): 32 cryptographically random bytes, about 43 URL-safe characters. Unguessable, unlike random or a counter.
  • Every login adds a session row, so you can be logged in on your laptop and your phone at once. Logout deletes only this token. The other device stays logged in.
  • Login and logout use POST, not GET. They change server state (create or delete a session), and passwords must never appear in a URL, where they would end up in browser history and server logs.
POST /login {"name": "itay", "password": "1234"} → 200 {"token": "Xq3vN8bQ0pJ…r2Lw", "user": {"id": 1, "name": "itay", "created_at": "…", "has_avatar": false}}
Is /login RESTful? Not strictly, because it's a verb in the URL. A purist would write POST /sessions (create a session) and DELETE /sessions/current. /login and /logout are a very common, readable compromise.

messages.py: The /messages Resource

The second router follows exactly the same pattern as /users, and it is short enough to read in one go.

Models & helpers

messages.py
router = APIRouter(tags=["messages"]) class MessageCreate(BaseModel): content: str = Field(..., min_length=1, max_length=2000) class MessagePatch(BaseModel): content: Optional[str] = Field(None, min_length=1, max_length=2000) class Message(BaseModel): id: int user_id: Optional[int] sender: str content: str created_at: str updated_at: str def fetch_message(db, message_id: int) -> Message: row = db.execute("SELECT * FROM messages WHERE id = ?", (message_id,)).fetchone() if row is None: raise HTTPException(status_code=404, detail="Message not found") return Message(**dict(row)) def fetch_own_message(db, message_id: int, me: dict) -> Message: msg = fetch_message(db, message_id) if msg.user_id != me["id"]: raise HTTPException(status_code=403, detail="You can only change your own messages") return msg

user_id: Optional[int] is needed for the old messages from before accounts existed (they have NULL). fetch_own_message is the ownership rule in four lines: 404 if the message doesn't exist, 403 if it isn't yours.

GET /messages: filter, limit, offset

@router.get("/messages", response_model=List[Message]) def list_messages( sender: Optional[str] = None, limit: int = Query(100, ge=1, le=1000), offset: int = Query(0, ge=0), ): sql, params = "SELECT * FROM messages", [] if sender: sql += " WHERE sender = ?" params.append(sender) sql += " ORDER BY id DESC LIMIT ? OFFSET ?" params += [limit, offset] with get_db() as db: return [Message(**dict(r)) for r in db.execute(sql, params).fetchall()]
  • Arguments that aren't in the path and aren't models are query parameters: /messages?sender=itay&limit=20&offset=40.
  • Query(100, ge=1, le=1000): default 100, must be 1…1000. ?limit=5000 gets a 422, so nobody can ask for the whole table in one call.
  • The SQL is built up step by step, but the values still go in through params. Only fixed SQL text is concatenated.
  • ORDER BY id DESC: newest first. LIMIT/OFFSET is pagination: page 3 of 20 is limit=20&offset=40.

GET one · POST create

@router.get("/messages/{message_id}", response_model=Message) def get_message(message_id: int): with get_db() as db: return fetch_message(db, message_id) @router.post("/messages", response_model=Message, status_code=status.HTTP_201_CREATED) def create_message(msg: MessageCreate, me: dict = Depends(current_user)): ts = now() with get_db() as db: cur = db.execute( "INSERT INTO messages (user_id, sender, content, created_at, updated_at) " "VALUES (?, ?, ?, ?, ?)", (me["id"], me["name"], msg.content, ts, ts), ) return fetch_message(db, cur.lastrowid)
The client never says who it is. The request body is only {"content": "…"}. user_id and sender come from me, which the server derived from the token. There is no field you could fake to post as someone else.

All three write endpoints start with fetch_own_message, so the ownership check can't be forgotten. Each edit sets updated_at. The frontend compares it to spot edited messages and makes the bubble flash. A message has only one editable field, so PUT and PATCH behave alike here. The difference is that PATCH accepts {} (no change), while PUT requires content.

static/index.html: api() & Polling

The frontend is about 1,000 lines of HTML, CSS and JavaScript in one file, with no framework. Most of it is looks: the aurora theme, SweetAlert dialogs, the avatar picker. Every conversation with the server goes through one function:

static/index.html: the only place that calls fetch()
let token = null, me = null, pollTimer = null, polling = false; try { token = localStorage.getItem("aurora_token"); } catch (e) {} async function api(path, { method = "GET", body } = {}) { const headers = { "Content-Type": "application/json" }; if (token) headers.Authorization = `Bearer ${token}`; const res = await fetch(path, { method, headers, body: body ? JSON.stringify(body) : undefined }); if (res.status === 204) return null; const data = await res.json().catch(() => ({})); if (!res.ok) { const err = new Error(typeof data.detail === "string" ? data.detail : Array.isArray(data.detail) ? data.detail.map(d => d.msg).join(", ") : `Request failed (${res.status})`); err.status = res.status; throw err; } return data; }
  • Relative paths ("/messages"): the page was served by the same Uvicorn, so requests go to the same host and port. No CORS needed.
  • The token from login lives in localStorage and is attached to every request. The server is stateless, so the client has to keep proving who it is.
  • 204 has no body, so there's nothing to parse.
  • Errors in one place: any non-2xx becomes a thrown Error carrying the server's detail. A plain HTTPException gives a string. A 422 from Pydantic gives a list, whose msgs are joined. The dialogs just show e.message.

"Live" chat by polling

const POLL_MS = 1000; function startPolling() { stopPolling(); let tick = 0; const run = () => { poll(); if (tick++ % 5 === 0) refreshMembers(); }; run(); pollTimer = setInterval(run, POLL_MS); } async function poll() { if (polling) return; polling = true; try { render(await api("/messages?limit=200")); } catch (e) { console.warn("poll failed", e); } finally { polling = false; } }

Every second the page asks for the latest 200 messages, and every fifth tick it also refreshes the member list (GET /users). The polling flag stops requests from piling up if the server is slow. render() compares the result with what's on screen, keyed by message id: new ids slide in, missing ids fade out, and a changed updated_at flashes the bubble. After you send, edit or delete, the page calls poll() at once instead of waiting for the next tick.

What to Improve Next

The app works, and it was built quickly. Reading it carefully shows what a second round of vibe-coding could ask for. Each item is a good exercise and a good prompt for Claude:

1. Sessions never expire. A token is valid until logout, forever. sessions.created_at is stored but never checked. Fix: in current_user, reject tokens older than, say, 7 days (AND s.created_at > ?).
2. Unlimited login attempts. Nothing stops a script from trying thousands of passwords on /login. Fix: count failures per name/IP and answer 429 Too Many Requests for a while.
3. Foreign keys are switched off. Add conn.execute("PRAGMA foreign_keys = ON") in get_db() so ON DELETE CASCADE actually works. Then decide what happens to a deleted user's messages: right now they stay, pointing at a user_id that no longer exists.
4. The name is stored twice. messages.sender copies users.name, which is why renaming must also run UPDATE messages SET sender = …. A JOIN in list_messages would make the copy unnecessary (the column is left over from version 1, before accounts existed).
5. Polling re-downloads everything. Each open tab fetches 200 messages every second, even when nothing changed. Cheaper: GET /messages?after_id=532 to fetch only new ones. Best: a FastAPI WebSocket that pushes new messages the moment they're posted.
6. Legacy messages can't be edited by anyone. Rows with user_id = NULL fail msg.user_id != me["id"] for every user. Fine for a demo, but a migration could match them to users by sender.
7. on_event("startup") → lifespan. The current FastAPI style:
from contextlib import asynccontextmanager @asynccontextmanager async def lifespan(app: FastAPI): init_db() # runs on startup yield # anything after yield runs on shutdown app = FastAPI(title="Messages API", version="1.6", lifespan=lifespan)
Your turn. Pick one item, write the prompt you'd give Claude (name the file, the endpoint, the status code, the rule), apply it, and prove it works in /docs or Postman. That loop (design → prompt → read → test) is the real skill this lesson is about.
