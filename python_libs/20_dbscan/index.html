Above: the ε circle crawling along two crescents, tracing each one a single step at a time. The five points still grey at the end are the ones nothing could reach — DBSCAN labels them -1.

Density-Based Spatial Clustering of Applications with Noise. Every clustering model so far has measured the distance to a centre — which quietly assumes every cluster is a round blob. Give one a pair of interlocking crescents and it has no choice but to slice them in half. DBSCAN throws the centre away and follows density instead: it walks from point to point through crowded regions, so a cluster can be any shape you like. And it is the first model on this course allowed to answer "this point belongs to nothing".

DECK 20 · 01 / 08 · The problem
Why distance-based clustering fails
Some shapes have no centre

Distance-based algorithms assume that every cluster is symmetric and round. It is never stated out loud — it just falls out of measuring how far each point is from a centre. When the data contains clusters shaped like crescents or rings, they fail to identify them correctly.

The two ends of one crescent are further apart than the two facing sides of different crescents — so any model judging by distance to a centre has to get this wrong.
⚠️ Notice this is not a tuning problem. There is no K, no linkage and no scaling that rescues a centre-based model here — the assumption itself is what is broken.

DBSCAN is a clustering algorithm based on density. Unlike K-Means or hierarchical clustering, it does not look for clusters by distance to a centre, but by how densely packed the points are in a region of space. It knows how to identify clusters of any shape, and it also marks unusual points as outliers.

✅ The DBSCAN result. Run it on the same data and it separates differently-shaped clusters correctly and identifies the noise. All in all it is much more flexible and better suited to real situations.
DECK 20 · 02 / 08 · The idea
Core, border and outlier
One radius, three kinds of point

DBSCAN sorts every point in the dataset into exactly one of three kinds. Everything the algorithm does follows from this classification.

The green point has enough neighbours inside ε to be a core. The red point sits inside a core's radius but has too few of its own — it joins, but cannot recruit. The grey point at the far right is reachable from nobody.
KindDefinition
Core PointA point that has enough points around it within a range of ε. It starts the cluster and can draw other points into it.
Border PointA point found within the range of a core point, but which does not have enough points around itself to be a core point. It belongs to the cluster but does not create one.
Outlier PointA point not connected to any core point and belonging to no cluster. It is considered noise — and DBSCAN knows how to identify it and leave it alone.
📌 This is the feature, not a bug. Every other clustering model on this course must assign every row to some cluster, so a single freak measurement gets forced into a group and drags its centroid with it. DBSCAN can simply decline.
DECK 20 · 03 / 08 · The idea
Density reachability and connectivity
How a cluster bends around a corner
Density reachable

A point \(p\) is density-reachable from a point \(q\) if \(p\) is found within a range of ε from \(q\), and \(q\) is a core point. This is a one-directional relationship — \(q\) can reach \(p\), but not necessarily the other way round.

Density connected

Two points are density-connected if there exists a chain of core points that joins them — in other words, if you can get from one to the other through a continuous path of core points.

🔗 This is the whole trick. DBSCAN never asks "is this point near the centre?" It only ever asks "can I walk to this point, one small ε step at a time, without ever leaving a crowded region?" A crescent is dense all the way along its length, so the walk succeeds — even though the two ends are nowhere near each other. A centre is never needed, so a shape is never assumed.
📌 Note what the one-directional part buys you: a border point can be reached but cannot reach onwards. That is exactly what stops a cluster leaking out through its own thin edges into the empty space beyond.
DECK 20 · 04 / 08 · The idea
The DBSCAN algorithm
Seven steps
1
Mark all the points as unvisited.
2
Choose a random point.
3
If it has enough neighbours — start a cluster.
4
Expand the cluster according to all the reachable points.
5
If it does not have enough neighbours — mark the point as noise.
6
Move on to the next point.
7
Finish when you have gone over all the data.
Visual steps — ε = 1, MinPts = 3
With MinPts = 3 the green point qualifies as core: itself plus 2 neighbours inside ε makes 3.
⚠️ MinPts includes the point itself. With MinPts = 3, a point needs itself plus two neighbours inside ε to become a core point. Getting this off by one is the single most common reason a hand-worked DBSCAN disagrees with sklearn.
💡 Step 5 is not final. A point marked noise early on can still be picked up later as a border point, if some core point turns out to reach it. Only points that nobody ever reaches stay noise at the end.
DECK 20 · 05 / 08 · The two knobs
Epsilon and MinPts
Two numbers, and everything depends on them
Epsilon (ε)

Determines the radius around each point. It affects how many points enter that point's "neighbourhood".

Small valueMany points will be classified as noise
Large valueAll the points will turn into one single cluster
MinPts

The minimum number of points that must be in a point's neighbourhood (radius ε) for that point to be considered a core point.

SmallMany clusters, a little noise
LargeFew clusters, a lot of noise
🎯 Finding optimal parameters. You can use the elbow method to find the optimal value of ε according to a pre-defined number of outliers — for example, "we want 3 outliers".
  • Perform several runs with different ε values and check at which value you get exactly 3 outliers.
  • You can go over the same idea for MinPts too.
  • Rule of thumb: MinPts = 2 × the number of features.
⚠️ ε is measured in the units of your columns. That makes scaling even more critical here than in K-Means: with an unscaled table, a single ε means "a huge distance" in one column and "a microscopic distance" in another, and there is no value that works for both.
DECK 20 · 06 / 08 · The two knobs
The elbow for eps
Sweep it, and count the outliers

Rather than guess ε, run DBSCAN across a range of values and record how many points come back as noise at each one:

python
eps_range = np.linspace(0.1, 2.0, 20)
number_of_outliers = []

for eps in eps_range:
    dbscan = DBSCAN(eps=eps, min_samples=5)
    labels = dbscan.fit_predict(two_blobs_outliers)
    number_of_outliers.append(np.sum(labels == -1))

plt.figure(figsize=(10, 6))
plt.plot(eps_range, number_of_outliers, 'o-', linewidth=2)
plt.xlabel('Epsilon')
plt.ylabel('Number of outliers')
plt.title('Elbow Method: Number of Outliers vs Epsilon')
plt.grid(True)
plt.show()
Outliers collapse quickly as ε grows, then flatten out. Past the bend, raising ε stops removing noise and starts gluing genuine clusters together.
📊 Same shape, different question. The K-Means elbow in deck 17 plotted inertia against K. This one plots the number of outliers against ε. The reasoning is identical — find where the steep improvement stops — but you are reading a completely different quantity.
DECK 20 · 07 / 08 · In code
Blobs, moons, rings
The notebook, and label -1

Three datasets, each a different shape:

cluster_blobs.csvRound blobs with scattered noise around them
cluster_moons.csvTwo interlocking crescents
cluster_circles.csvA ring inside a ring
python
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
import seaborn as sns
from sklearn.cluster import DBSCAN

plt.style.use('seaborn-v0_8')

two_blobs_outliers = pd.read_csv('cluster_blobs.csv')

# Default DBSCAN parameters
# Missing scale
model = DBSCAN(eps=0.5, min_samples=5)
labels = model.fit_predict(two_blobs_outliers)

sns.scatterplot(data=two_blobs_outliers, x='X1', y='X2',
                hue=labels, palette='bright')
plt.show()

print(f"Number of outliers: {np.sum(labels == -1)}")
print(f"Percentage: {100 * np.sum(labels == -1) / len(labels):.2f}%")
output
Default DBSCAN outliers:
Number of outliers: 62
Percentage of outliers: 4.13%

labels [0 0 1 ... 0 0 1]
🏷️ Read the labels array. DBSCAN does not return a cluster number for every point the way K-Means does. Cluster numbers start at 0, and -1 means "this point is noise" — it belongs to nothing. That is why counting outliers is simply np.sum(labels == -1). No other model on this course has a label for "none of the above".
⚠️ The comment # Missing scale is deliberate — the data was not scaled before fitting. Since ε is a radius measured in the units of the columns, an unscaled table makes a single ε mean different things in different directions. It still works here because both columns happen to be on a similar scale; on a real table it would not.
💡 There is no predict. DBSCAN has fit_predict and nothing else — you cannot ask a fitted DBSCAN which cluster a brand new point belongs to. Density is a property of the dataset as a whole, so adding a point can change the answer for its neighbours. That is a real limitation compared with K-Means.

🧭 How to choose. Round, well-separated groups and you know roughly how many? K-Means. Want to see the structure and decide the number afterwards, on a table small enough to afford it? Hierarchical. Odd shapes, or real noise you need excluded rather than absorbed? DBSCAN.
📌 The trade DBSCAN makes. It stops asking you for the number of clusters — but it asks you for ε and MinPts instead, and those are harder to guess than K. It has not removed the tuning problem, it has moved it. The elbow in panel 06 is how you get it back under control.
