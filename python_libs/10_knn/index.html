KNN 01 / 08 · The Algorithm
The idea
Tell me who your neighbors are, and I'll tell you what you are
KNeighborsClassifier(n_neighbors=K) K K — how many neighbors voteThe only real hyper-parameter. K=1 asks the single closest point; K=5 asks the five closest and takes the majority. → a class label

K-Nearest Neighbors is a classification method that is simple and intuitive, yet effective. It lets us classify a new data point based on known data points.

There is no formula in the traditional sense — no β to learn, no curve to fit. KNN works by doing three things:

1 · Measure

Calculate the distance between the new point and every existing point.

2 · Sort

Find the K points with the smallest distances.

3 · Vote

Assign the majority class among those K points to the new point.

🎯 The problem we want to solve. Suppose we have data about different kinds of fruit — apples, oranges and bananas — with features such as color, size and weight. Now a new fruit arrives and we want to know which kind it is.

KNN 02 / 08 · The Mathematics
Euclidean distance
Pythagoras, one dimension at a time
d = np.sqrt(((p - q) ** 2).sum()) p, q p and q — two data pointsEach one is a row of features: a fruit is (weight, size, color). n n — the number of featuresHow many columns each point has. The formula does not care whether n is 2 or 200. → one non-negative number

The most common distance measure used in KNN is the Euclidean distance — the plain straight-line distance you would measure with a ruler:

$$d(p, q) = \sqrt{\sum_{i=1}^{n} (p_i - q_i)^2}$$

Where p and q are two data points, n is the number of features, and \(p_i\), \(q_i\) are the values of the i-th feature for points p and q.

Written out per dimension it is nothing but Pythagoras, repeated:

$$\textbf{2D:}\quad d = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}$$ $$\textbf{3D:}\quad d = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2 + (z_2 - z_1)^2}$$ $$\textbf{nD:}\quad d = \sqrt{\sum_{i=1}^{n}(x_{2i} - x_{1i})^2}$$
📐 Read the pattern: subtract → square → add them all up → square root. Adding a feature only adds one more (…)² inside the root. Nothing else changes.

A worked example straight from the lesson. Three known points p, one query point q = (4, 5):

pΔxΔyΔx² + Δy²d = √
(1, 4)319 + 1 = 10√10 = 3.162
(2, 7)2−24 + 4 = 8√8 = 2.828
(3, 3)121 + 4 = 5√5 = 2.236 ← nearest

💡 Why square, then root? Squaring kills the sign — a distance of −3 makes no sense — and it punishes big gaps more than small ones. The square root brings the number back to the original units.
Appendix A1 · The Code
np.linalg.norm
The whole square-root formula in one call
np.linalg.norm(vector) → float — the length of the vector = √(v₁² + v₂² + … + vₙ²)

You never have to type the square root by hand. Subtract the two points to get a difference vector, then ask NumPy for its length — that is the Euclidean distance:

$$\|v\| = \sqrt{v_1^2 + v_2^2 + \dots + v_n^2} \qquad\Longrightarrow\qquad d(p,q) = \|\,p - q\,\|$$
MathsPythonWhat it is
\(p - q\)p - qThe difference, feature by feature
\((p_i - q_i)^2\)(p - q) ** 2Every gap squared
\(\sum (p_i - q_i)^2\)((p - q) ** 2).sum()Added up into one number
\(\sqrt{\sum (p_i - q_i)^2}\)np.linalg.norm(p - q)The distance — all of the above
python — three ways, one answer
import numpy as np

p = np.array([1, 2, 3])
q = np.array([4, 6, 3])

# 1 - the long way
d = np.sqrt( ((p - q) ** 2).sum() )

# 2 - the short way (identical result)
d = np.linalg.norm(p - q)

# 3 - by hand: √[(-3)² + (-4)² + (0)²] = √25 = 5.0
print(d)      # 5.0
📌 np.linalg.norm([1, 2, 3]) is \(\sqrt{1^2 + 2^2 + 3^2} = \sqrt{14} = 3.742\). The word norm simply means "length of the vector" — and the length of p - q is the distance from p to q.
⚠️ Order does not matter: norm(p - q) == norm(q - p). The squares erase the sign, so distance is always symmetric and never negative.
KNN 03 / 08 · The Trap
Why normalize
Without scaling, the biggest column silently wins
x_norm = (x - x.min()) / (x.max() - x.min()) → every column lands in [0, 1] min → 0 · max → 1

Look at the ranges in our fruit table. They are wildly different — and Euclidean distance adds them all up in the same sum:

Featureminmaxrangeshare of the distance
Color20250230dominates everything
Weight11518065a small voice
Size6137practically ignored

A 100-point difference in color contributes \(100^2 = 10{,}000\) to the sum. A 3 cm difference in size contributes \(3^2 = 9\). The size column may as well not exist. The fix is Min-Max normalization — squeeze every column into the same 0…1 range:

$$x_{norm} = \frac{x - \min(x)}{\max(x) - \min(x)}$$

The worked example from the lesson — a column that runs from 20 to 250, and the value 200:

$$\frac{200 - 20}{250 - 20} = \frac{180}{230} = 0.78$$

250 (the max)(250 − 20) / 2301.00

KNN 04 / 08 · sklearn
MinMaxScaler
fit_transform on the data, transform on the new point
from sklearn.preprocessing import MinMaxScaler fit_transform fit_transform(X)fit = learn each column's min and max. transform = apply the formula. Use it once, on the training data. transform transform(X_new)Scale only — reuses the min and max already learned. This is what you call on the new point. → ndarray in [0, 1]

sklearn does the Min-Max formula for every column at once. There are two methods and the difference between them is the single most common beginner mistake:

✅ fit_transform(df)

  1. Finds min and max of every column
  2. Remembers them inside the scaler object
  3. Scales the data with them
  4. Call it once, on the training data

⚠️ transform(new)

  1. Does not look for new min / max
  2. Reuses the ones learned in fit
  3. Only scales
  4. Call it on every new point you predict
⚠️ If you call fit_transform on the new fruit, it becomes the min and the max of its own one-row table — every value turns into 0 and the distances are garbage. The new point must be measured with the same ruler as the training data.
python — normalize the table and the new fruit
from sklearn.preprocessing import MinMaxScaler

min_max_scaler = MinMaxScaler()      # creates numbers between 0 and 1
df_norm = df.copy()

######## STEP 1 - normalize the DataFrame
# fit_transform - find min + max, then scale
df_norm[['Weight', 'Color', 'Size']] = min_max_scaler.fit_transform(
                                      df_norm[['Weight', 'Color', 'Size']])

######## STEP 2 - normalize the new fruit with the SAME scaler
new_fruit = pd.DataFrame({'Weight': [155], 'Color': [220], 'Size': [8]})

# transform - scale only
new_fruit_norm = min_max_scaler.transform(new_fruit[['Weight', 'Color', 'Size']])
print('new_fruit_norm', new_fruit_norm)
# new_fruit_norm [[0.61538462 0.86956522 0.28571429]]

You can also scale one column at a time — same result, more typing:

df_norm['Weight'] = scaler.fit_transform(df['Weight'].values.reshape(-1, 1))

KNN 05 / 08 · sklearn
KNeighborsClassifier
fit stores, predict votes, predict_proba shows the tally
KNeighborsClassifier(n_neighbors=3, weights='distance') n_neighbors n_neighbors — that's KHow many nearest points get a vote. Default is 5. weights weights — how loud each vote is'uniform' = everybody equal. 'distance' = closer neighbors count more. See Appendix A2. → .predict() · .predict_proba() · .classes_

Now the same job in sklearn. Notice how little there is: build the feature matrix, scale it, hand it to the model.

python — the full pipeline
import numpy as np
from sklearn.preprocessing import MinMaxScaler
from sklearn.neighbors  import KNeighborsClassifier

# Fruit data
colors      = np.array([200, 50, 220, 240, 250, 230, 30, 40, 20])
sizes       = np.array([7, 7, 6, 9, 8, 9, 12, 13, 11])
weights_g   = np.array([150, 160, 140, 170, 165, 180, 120, 130, 115])
fruit_types = np.array(['apple', 'apple', 'apple',
                        'orange', 'orange', 'orange',
                        'banana', 'banana', 'banana'])

# Create feature matrix
X = np.column_stack((colors, sizes, weights_g))
y = fruit_types

# Normalize data
scaler   = MinMaxScaler()          # create
X_scaled = scaler.fit_transform(X)   # activate

k = 3                                  # number of neighbors
model = KNeighborsClassifier(n_neighbors=k, weights='distance')

model.fit(X_scaled, y)                  # store the points

# New fruit to classify
new_fruit        = np.array([[220, 8, 155]])
new_fruit_scaled = scaler.transform(new_fruit)

prediction    = model.predict(new_fruit_scaled)
probabilities = model.predict_proba(new_fruit_scaled)

print(model.classes_)
print(probabilities)
print(f"Prediction: The new fruit is a {prediction[0]}")
output
['apple' 'banana' 'orange']
[[0.39084138 0.         0.60915862]]
Prediction: The new fruit is a orange
CallWhat it doesReturns
model.fit(X, y)Stores the points. No maths happens here.the model
model.predict(X_new)Measures, sorts, votes.array of labels
model.predict_proba(X_new)The vote share per class.array (n_rows, n_classes)
model.classes_The column order of predict_proba — alphabetical.array of labels
model.kneighbors(X_new)Which neighbors were used, and how far.(distances, indices)
⚠️ Read the probabilities against classes_, never against your own order. sklearn sorts the labels alphabetically: ['apple' 'banana' 'orange']. So 0.391 is apple, 0.0 is banana, 0.609 is orange.
💡 Banana gets exactly 0.0 — not because bananas are impossible, but because no banana was among the 3 nearest neighbors. With KNN, a class that does not make the shortlist gets zero.
KNN 06 / 08 · The Hyper-parameter
Choosing K
Too small and it twitches, too large and it blurs
k = int(np.sqrt(len(X))) prefer an odd K → a good starting point, not a law

K is the one knob you actually turn. Four points to remember:

#RuleWhy
1Small K — more sensitive to noise, but can catch local patternsK=1 lets a single mislabeled point rewrite a whole region
2Large K — more stable, but may miss local patternsthe boundary smooths out and small clusters get swallowed
3Prefer an odd Kto avoid a tie in the majority vote (2 classes)
4\(K = \sqrt{n}\) is a good starting pointn = number of samples; then tune with cross-validation
$$K \approx \sqrt{n}$$

Watch what K actually does to the map. The background is painted with the class KNN would predict at every point — that is the decision region:

🔍 Spot the noisy apple. One apple has color = 50 — a green apple sitting deep inside banana territory. At K = 1 it carves out its own little island. Raise K and its neighbors outvote it: that is exactly what "sensitive to noise" means.
⚠️ With 9 samples, \(\sqrt{9} = 3\) — so K=3 is the textbook starting point for this dataset. Push K to 9 and every point in the plane sees all the data, so the model always answers the most common class. That is the extreme of "too large".
Appendix A2 · The Vote
uniform vs distance
One neighbor, one vote — or louder the closer you stand
weights='uniform' weights='distance' → changes predict_proba, sometimes predict
weightsMeaningWeight of neighbor i
'uniform'All points in each neighborhood are weighted equally\(w_i = 1\)
'distance'Weight points by the inverse of their distance — closer neighbors of a query point have a greater influence than neighbors further away\(w_i = \dfrac{1}{d_i}\)

With 'distance', the probability of a class is its share of the total weight:

$$P(c) = \frac{\sum_{i \in c} \frac{1}{d_i}}{\sum_{i=1}^{K} \frac{1}{d_i}}$$

Let's reproduce sklearn's [[0.39084138 0. 0.60915862]] by hand. The three nearest neighbors of our fruit were:

NeighborClassd1 / d
#0apple0.184085.4323
#4orange0.201704.9579
#3orange0.285003.5088
total weight13.8990
$$P(\text{apple}) = \frac{5.4323}{13.8990} = 0.3908 \qquad P(\text{orange}) = \frac{4.9579 + 3.5088}{13.8990} = 0.6092$$
✅ Exactly sklearn's output: 0.39084138 and 0.60915862. And banana is 0.0 — no banana in the top 3, so no weight at all.

With 'uniform' the same three neighbors give a much blunter answer — 1 apple, 2 oranges out of 3:

💡 When does it matter? 'distance' is the safer default when your classes are unbalanced or the neighbors are at very different distances — a neighbor sitting almost on top of the query point should not have the same say as one at the edge of the neighborhood. It also breaks ties automatically.
⚠️ If a query point sits exactly on a training point, \(d = 0\) and \(1/d\) is infinite. sklearn handles this by returning that point's class with probability 1.
KNN 07 / 08 · The Verdict
Pros & cons
What KNN is great at, and where it falls apart

✅ Advantages of KNN

  1. Simple to implement and easy to understand — three steps, no training maths
  2. No assumptions about the shape of the data — it is non-parametric; no straight line, no bell curve required
  3. Effective on data with complex decision boundaries — the boundary can be as wiggly as the data demands
  4. Works for both classification and regression — vote, or average

⚠️ Disadvantages of KNN

  1. Slow at prediction time on large datasets — every prediction measures against every stored point
  2. Requires careful data normalization — otherwise the largest-range column decides everything
  3. Sensitive to outliers and noise — especially with small K
  4. Requires a smart choice of K — the result genuinely depends on it
  5. High memory requirement — the entire training set must be kept
📊 The trade-off in one line. Linear and logistic regression spend time in fit and are instant at predict. KNN is the mirror image: fit costs nothing, predict pays the whole bill — every single time.
StageLogistic RegressionKNN
fitslow — optimizes βinstant — just stores X, y
memory after fita few numbersthe entire dataset
predictinstant — one dot productslow — n distances per row
needs scalinghelpsmandatory
decision boundarya straight lineany shape at all
💡 Use KNN when the dataset is small-to-medium, the features are all numeric and comparable after scaling, and the boundary between classes is clearly not a straight line. It also makes an excellent baseline — if your fancy model cannot beat KNN, something is wrong.

Appendix A3 · Beyond Pythagoras
Other distances
Manhattan, Minkowski, and the metric parameter
KNeighborsClassifier(metric='minkowski', p=2) p p — the Minkowski orderp=1 is Manhattan, p=2 is Euclidean (the default). Anything in between is legal too. → a different notion of "close"

Euclidean is the default, not the law. All the common metrics are special cases of one general formula — the Minkowski distance:

$$d(p, q) = \left( \sum_{i=1}^{n} |p_i - q_i|^{\,p} \right)^{1/p}$$
pNameFormulaPicture
1Manhattan / city-block\(\sum |p_i - q_i|\)walk along the streets
2Euclidean (default)\(\sqrt{\sum (p_i - q_i)^2}\)fly straight through
∞Chebyshev\(\max_i |p_i - q_i|\)only the worst feature counts
python — switching the metric
from sklearn.neighbors import KNeighborsClassifier

# Euclidean - this is the default
euclid = KNeighborsClassifier(n_neighbors=3, metric='minkowski', p=2)

# Manhattan
manhat = KNeighborsClassifier(n_neighbors=3, metric='manhattan')   # == p=1

# by hand with NumPy
np.abs(p - q).sum()             # Manhattan
np.linalg.norm(p - q)             # Euclidean
np.abs(p - q).max()             # Chebyshev

Appendix A4 · The Other Half
KNN Regressor
Same neighbors — average them instead of counting votes
from sklearn.neighbors import KNeighborsRegressor → a number, not a label

KNN is one of the few algorithms that works for both classification and regression — that was advantage #4 on the pros list. The only thing that changes is step 3:

StepClassifierRegressor
1 · Measureidentical — Euclidean distance to every point
2 · Sortidentical — keep the K smallest
3 · Combinemajority vote of the labelsmean of the values
$$\hat{y} = \frac{1}{K}\sum_{i=1}^{K} y_i$$
python — predict a number
from sklearn.neighbors import KNeighborsRegressor

# predict the WEIGHT of a fruit from its color and size
X = np.column_stack((colors, sizes))
y = weights_g                       # a number, not a label

X_scaled = scaler.fit_transform(X)

reg = KNeighborsRegressor(n_neighbors=3)
reg.fit(X_scaled, y)

print(reg.predict(scaler.transform([[220, 8]])))   # e.g. [165.]
Live Demo — the staircase: raise K and the prediction curve flattens
1
⚠️ KNN regression never extrapolates. Outside the range of the training data the K nearest neighbors stop changing, so the prediction becomes a flat line. A linear regression would keep going; KNN simply repeats what it saw at the edge.
💡 The staircase shape is the signature of KNN regression: the prediction only changes when the set of nearest neighbors changes. With K=1 you get a jagged staircase that hits every point exactly; with K=9 you get one flat line at the overall mean.
