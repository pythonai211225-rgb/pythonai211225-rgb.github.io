Vibe Coding 01 / 06 · The Method
The loop
You stay the engineer — the AI is just very fast at typing
describe → read → run → correct → working code you understand

Vibe coding means describing the outcome you want instead of typing every line to get there. The AI writes the code; you decide whether it is right. That second half is not optional — it is the entire job.

1 · Describe

Say what it should do, not how to code it. Name the inputs, the outputs and the constraints.

2 · Read

Actually look at what came back. If you cannot explain a line, that line is a bug waiting to happen.

3 · Run

Execute it. Does it work? Did it break something that used to work?

4 · Correct

Describe the gap in one sentence and go round again. Small steps beat one giant prompt.

Live Demo — one turn of the loop, as it actually went in class
💡 Small steps. "Build me the whole website" gives you 600 lines you have never read. "Add an endpoint that returns the model parameters as JSON" gives you eight lines you can check in ten seconds. Ask for the eight.
⚠️ It will be confidently wrong sometimes. Not occasionally — regularly. The loop is built around that fact: step 2 and step 3 exist precisely because step 1 cannot be trusted on its own.

Vibe Coding 02 / 06 · The Skill
Writing the prompt
Vague in, vague out
what · with what · how it should behave one change at a time

The model cannot read your mind, and it will never say "I'm not sure what you meant" — it will just guess. Every detail you leave out is a detail it invents.

⚠️ Vague

"make a website for my model"

You get a website. Wrong colours, wrong data, endpoints you never wrote, and 500 lines to untangle.

✅ Specific

"a single page that calls GET /model-summary, draws the fitted curve as an SVG with the 10 observed points on top, and has a slider from 2 to 30 showing the predicted time"

You get something you can check line by line against what you asked for.

A prompt that works usually has four parts. Toggle them below and watch the request fall apart:

The three prompts that actually built the project in lesson 16, in order:

Take poly_pyth.py and add two functions: one that returns the intercept and the coefficients, and one that predicts a running time for a given number of training hours.
Wrap this model in a Flask REST API. I want an endpoint to predict a running time and an endpoint that returns the model parameters as JSON.
Now build a front end in static/ — index.html, styles.css and app.js — that calls those endpoints and looks amazing.
📌 Notice the shape. Each prompt names a file, a verb and a result. None of them says "write good code" — that adds nothing. Specifics do the work.
💡 Correcting is a prompt too. "The y-axis is upside down — larger times should be higher" is a better bug report than "the chart is broken", for exactly the same reason.

Vibe Coding 03 / 06 · The Setup
VS Code + Live Server
One editor, one extension, one real http:// address
Ctrl+Shift+X → Extensions Live Server Live ServerRight-click any .html → Open with Live Server. Serves the folder on 127.0.0.1:5500 and refreshes the browser on every save. → http://127.0.0.1:5500

Everything happens in one window: the files, the terminal, the AI chat and the running site. Four things to install:

InstallWhereWhy
VS Codecode.visualstudio.comThe editor everything else plugs into
Pythonpython.org + the Python extensionRun .py files, pick an interpreter
Live ServerExtensions → "Live Server"A real web server for your HTML, with auto-reload
GitHub CopilotExtensions → "GitHub Copilot"Inline AI completions — next slide
⚠️ Open the folder, not the file. File → Open Folder. The AI assistants read the folder for context, and Live Server needs a root to serve. Opening a lone file cripples both.

The single most common beginner failure — double-clicking the HTML file:

⚠️ file:///C:/…/index.html

Double-clicking the file. The page renders, but the browser treats it as a local file with no origin — so fetch is blocked and every API call fails.

✅ http://127.0.0.1:5500

Live Server. A real HTTP origin, so fetch works — plus the page reloads itself every time you hit save.

📌 For the Flask project we skip Live Server entirely. Flask serves static/index.html itself on port 5000, so the page and the API share one origin — which is also why its fetch calls can use plain relative paths like /health.

Vibe Coding 04 / 06 · The Assistants
Copilot & Claude
One finishes your line, the other writes your file
Tab — accept Ctrl+I — inline chat → code you still have to read
ToolGetting inBest at
GitHub CopilotGitHub account → enable Copilot → install the Copilot + Copilot Chat extensions → sign in. Free for verified students.Finishing the line or function you already started. Ghost text, Tab to accept.
ClaudeAn account at claude.ai — in the browser, or the extension / Claude Code working on your actual folder.A whole file or feature from a sentence. Refactors, redesigns, "why is this broken".

✅ Reach for Copilot when

  • you know exactly what the next line is
  • it is repetitive — a loop, a dict, a test
  • you want to stay in the flow of typing

✅ Reach for Claude when

  • you want a whole file or feature described in words
  • the change touches several files at once
  • you need it explained, not just written
🔒 Never paste secrets into a prompt. API keys, passwords, customer data. Assume anything you type leaves your machine. Secrets belong in environment variables, and .env belongs in .gitignore.
⚠️ Neither one knows your codebase by magic. They see the files you have open and what you tell them. If the answer looks like it ignored your project, it probably could not see it — open the file, or paste the relevant part.

Vibe Coding 05 / 06 · The Front End
HTML + CSS + JS
Structure, appearance, behaviour — three files, three jobs
index.html · styles.css · app.js → one page in the browser

Every web page you have ever seen — the tic-tac-toe game and the regression dashboard included — is these three layers stacked on top of each other:

index.html

Structure. What exists on the page: the heading, the number, the button, the slider.

styles.css

Appearance. Colour, spacing, layout, shadows, animation. Nothing about meaning.

app.js

Behaviour. What happens on click, on drag, and when the API answers.

Live Demo — switch each layer off and watch what survives
localhost:5000
📌 HTML alone still works. Turn off the CSS and the page is ugly but readable — that is the sign your structure is honest. Turn off the JS and the button is still there, it just does nothing.
💡 Why this split matters for vibe coding: when something is wrong you can say which layer. "The button does nothing" is a JS problem. "The button is invisible" is a CSS problem. "There is no button" is HTML. That one word saves a whole round of the loop.

Vibe Coding 06 / 06 · The Contract
What is a REST API
A function you can call over the internet
VERB + PATH → JSON + STATUS verb The HTTP verbWhat kind of action this is. GET reads, POST creates or submits, PUT replaces, DELETE removes. → a status code and a body

An API is a function someone else can call. A REST API is one where the call is an ordinary web request: a verb, a path, and JSON coming back. Your browser already makes hundreds of them a day.

GET  http://localhost:5000/predict-running-time?x=10
PartIn our projectMeans
the verbGET"I want to read something, don't change anything"
the hostlocalhost:5000which machine and which port Flask is listening on
the path/predict-running-timewhich function to run
the query?x=10the argument
the response{"input": 10.0, "prediction": 57.6…}JSON — the return value

The four verbs you will meet. We only needed the first two:

VerbJobBody?Safe to repeat?
GETRead. Everything in the URL.noyes
POSTSend data. Carries a JSON body.yesnot necessarily

Appendix A1 · Reference
Status codes
The first thing to look at when something breaks

Every HTTP response carries a three-digit code. The first digit tells you who has the problem:

RangeMeaningWhose fault
2xxSuccessnobody — it worked
3xxRedirect — look somewhere elsenobody
4xxThe request was wrongthe caller
5xxThe server brokethe server
200
OK
Here is your answer.
201
Created
Your POST made something new.
400
Bad Request
Your input was malformed — ?x=abc.
401
Unauthorized
You did not say who you are.
403
Forbidden
I know who you are; you still may not.
404
Not Found
No route matches that path. Check the spelling.
405
Method Not Allowed
Right path, wrong verb — a POST to a GET-only route.
500
Internal Server Error
Python raised an exception. Read the terminal.
📌 The two you will hit most. 404 — Flask has no route with that path, so check for a typo or a missing leading slash. 500 — your Python threw; the real traceback is in the terminal running app.py, not in the browser.
⚠️ Return the honest code. Answering 200 with {"error": "..."} inside is a trap: res.ok is true, so every caller sails straight past the failure. If it failed, say so in the status.

Appendix A2 · Reference
JSON in 60 seconds
The language both sides speak

Python and JavaScript cannot share objects. They share text in a format both can parse — JSON. It looks like a Python dict and behaves like a JavaScript object, which is exactly why it won.

JSONPythonJavaScript
{"a": 1}dictobject
[1, 2, 3]listarray
"hi"strstring
3.14floatnumber
true / falseTrue / Falsetrue / false
nullNonenull

Four rules that cause every JSON error you will ever see:

⚠️ Not valid JSON

  • {'x': 1} — single quotes
  • {"x": 1,} — trailing comma
  • {x: 1} — unquoted key
  • {"x": True} — Python's True

✅ Valid JSON

  • {"x": 1} — double quotes only
  • {"x": 1} — no trailing comma
  • {"x": true} — lowercase booleans
  • {"x": null} — null, not None
🔥 The NumPy error you will hit. TypeError: Object of type float64 is not JSON serializable. NumPy numbers are not Python numbers, and jsonify does not know them. Convert on the way out:
"intercept": float(model.intercept_)
"coefficients": [float(v) for v in model.coef_]
📌 Both sides do the conversion for you. Python: jsonify(d) out, request.get_json() in. JavaScript: await res.json() in, JSON.stringify(obj) out. You never write a parser.
