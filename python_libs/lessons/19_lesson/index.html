The recipe is identical. Try every feature and every threshold, weight the two children by how many rows they hold, keep the split with the biggest drop in impurity, repeat. Only the word "impurity" changed meaning.

The MSE of a node

A leaf in a regression tree answers with one number, and the best single number to represent a group is its mean:

$$\mu = \frac{1}{n}\sum_{i=1}^{n} x_i$$

the mean of the values in the node

So the impurity of a node is how badly that one number represents everybody in it - the average squared distance from the mean:

$$\text{MSE-to-mean} = \frac{1}{n}\sum_{i=1}^{n}(x_i - \mu)^2$$

this is exactly the variance of the node

In class we wrote it as a one-line helper, and used it for every node:

# MSE
# Mean Squared Error
# Mean + MSE
def mse_avg(arr):
    return np.mean((arr - arr.mean())**2)
Read the two formulas together. Gini asked "how many different classes are in this box?" MSE asks "how far apart are the numbers in this box?" A node holding [40, 40, 40] has MSE 0 - perfectly pure - exactly like a node holding [B, B, B] had Gini 0. Zero impurity always means one answer fits everybody here.

Start at the root, which holds all six rows:

print('root')

print(' MSE:', mse_root, 'AVG:', y.mean())

The weighted MSE is the same formula as weighted Gini, with MSE in place of G:

$$\text{MSE}_{\text{weighted}} = \frac{n_{L}}{n}\,\text{MSE}_{L} + \frac{n_{R}}{n}\,\text{MSE}_{R} = \frac{3}{6}(44.22) + \frac{3}{6}(64.89) = 54.56$$
$$\text{gain} = \text{MSE}_{\text{parent}} - \text{MSE}_{\text{weighted}} = 151.25 - 54.56 = \mathbf{96.69}$$

[10, 12] has mean 11 and MSE 1.0 - almost pure. [25] is a single row, so its mean is 25 and its MSE is exactly 0. Weighted together:

$$\frac{2}{3}(1.0) + \frac{1}{3}(0.0) = \mathbf{0.667}$$
Careful with that last printed line. The notebook prints weighted_mse - weighted_mse2 = 54.556 − 0.667 = 53.889, but those two numbers live on different levels: 54.556 is the weighted MSE of the whole first split, while 0.667 belongs to the left child only. The gain of a split is always measured against its own parent, and this split's parent is the left node with MSE 44.222:
$$\text{gain} = 44.222 - 0.667 = \mathbf{43.556}$$

It does not change which split wins - any positive gain is an improvement - but if you are comparing candidate questions at this node, they must all be scored against the same parent. Worth knowing for the exam.

A single row is always pure. That is why an unpruned tree keeps going until every leaf holds one row: MSE 0 everywhere, a perfect score on the training data, and a model that has memorised it. This is the overfitting the forest in part 3 is built to cure.

R² - scoring the tree

Accuracy makes no sense here - the model will essentially never output exactly the right number. Instead we ask: how much better is this model than just predicting the mean every time? That is R².

First, the error we are measuring. MSE compares the truth to the prediction:

$$\text{MSE} = \frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2$$

note the \(\hat{y}\) - earlier we compared against \(\mu\), here against the model

And R² turns that into a score between 0 and 1 by dividing by the error of the dumbest possible model:

$$R^2 = 1 - \frac{\sum_{i=1}^{n}(y_i - \hat{y}_i)^2}{\sum_{i=1}^{n}(y_i - \bar{y})^2}$$

top: the model's errors. bottom: the errors of always guessing the mean.

For the stump we just fitted, both sums are small enough to do by hand:

A neat coincidence worth noticing. The model's MSE here is 4.0 / 6 = 0.667 - the same number we computed by hand in topic 5 as a weighted MSE. That is not luck: the weighted MSE of a split is the training MSE of the tree that stops at that split. The by-hand arithmetic and sklearn's score are the same quantity, reached from two directions.
R² is also what tree.score(X, y) returns for any regressor - so r2_score(y, y_pred) and tree.score(X, y) give the same number.

Why one tree is not enough

Second notebook. We have now built trees twice, and both times the same weakness appeared: left alone, a tree splits until every leaf is pure and has memorised the training rows. Single trees suffer from:

Overfitting

The tree learns the data too well and does not generalise to new data.

Feature tunnel vision

At every split an ordinary tree takes the single best feature, so one strong column dominates the whole model.

Instability

Change a few rows and you get a completely different tree - the splits are greedy, so one change at the top cascades down.

The example from the board. Predicting whether a customer gets credit, from age and salary: a single tree can build extremely precise rules for the customers you already have, and still be wrong about the next one who walks in.

The fix is not a better tree - it is many trees:

Instead ofone tree
built on all the rows, using all the features at every split.
Buildmany trees
each on a different random part of the data and a different random part of the features.
Thencombine
classification takes a majority vote; regression takes the mean.
$$\textbf{classification:}\quad \text{Prediction}(x) = \text{Majority Vote}\big(T_1(x), T_2(x), \dots, T_K(x)\big)$$ $$\textbf{regression:}\quad \text{Prediction}(x) = \frac{1}{K}\sum_{i=1}^{K} T_i(x)$$
Why averaging works. Each tree is wrong in a different direction, so the individual mistakes cancel and only the shared signal survives. That single sentence is the whole idea of a random forest - everything else is machinery for making the trees different enough.

Bootstrapping

Bootstrapping means building a new sample from the data you already have by drawing rows at random with replacement. Two consequences follow straight away:

A row can be picked twice

It then counts double in that tree, as if that customer had appeared twice.

A row can be missed entirely

That tree never sees it - which topic 12 turns into a free test set.

The example from class: with five rows A, B, C, D, E, one tree might be built on A, B, B, D, E - B twice, C nowhere.

How much of the data does one tree actually see? A given row survives a single draw with probability \(1 - 1/n\), and there are \(n\) draws, so:

$$P(\text{row is left out}) = \left(1 - \frac{1}{n}\right)^{n} \;\longrightarrow\; \frac{1}{e} \approx 0.368$$

So roughly 63% of the rows go into each tree and 37% stay out - and that holds whether you have 20 rows or 20 million.

Where the name comes from. Bagging = Bootstrap Aggregating: bootstrap the rows, aggregate the answers. Set bootstrap=False and every tree gets the identical dataset - the trees become near-copies, the vote stops helping, and out-of-bag scoring becomes impossible because nothing is ever left out.

Random features & voting

Bootstrapping alone is not enough. If one feature is much stronger than the rest, every tree will put it at the root whatever rows it got - and 100 trees that start with the same question make the same mistakes. A vote cannot cancel an error they all share.

So the forest adds a second dose of randomness: at every split, only a random subset of the features may be considered. Not once per tree - a fresh draw at every node.

This is the "random" in random forest. Two independent sources of randomness stacked on top of each other: random rows (bootstrapping) and random columns (max_features). Take away the second and you have plain bagging; take away both and you have 100 identical trees and a very slow decision tree.

The full procedure, as we wrote it on the board:

#step
1Draw a random sample with replacement from the data (bootstrapping)
2At every split, choose a random subset of features
3About 63% of the rows enter each tree - roughly 37% never appear in it at all
4Grow the tree to the end (no pruning)
5Repeat to build many trees
6Final prediction by majority vote or mean
Step 4 is not a typo. Unlike a single tree, you normally leave max_depth=None in a forest. The forest wants deep overfitting trees, because averaging is what cures the overfitting - and a deep tree has low bias, which averaging cannot fix.

Out-of-Bag score

Topic 9 left something on the table. When you bootstrap, about 37% of the rows never make it into a given tree. From that tree's point of view those rows are unseen data - a test set created for free, by accident, and different for every tree.

The out-of-bag idea is simply to use it:

Step 1Grow
each tree trains on its bootstrap sample and remembers nothing about the rest.
Step 2Grade
row i is predicted only by the trees for which it was out of bag - about a third of them.
Step 3Score
oob_score_ is the accuracy of those predictions across all the rows.
Read oob_score_, not the accuracy. Test accuracy was 1.00 on six rows; out-of-bag accuracy was 0.93, computed across all 14 training rows using only the trees that had not seen each one. The second number rests on more than twice the evidence. When a 6-row test set and a 14-row OOB estimate disagree, believe the OOB.
train_test_splitoob_score_
rows used for training70-80% of themall of them
extra costyou lose a chunk of your datafree - it falls out of bagging
works whenalwaysonly with bootstrap=True and enough trees
It needs enough trees. With only a handful, some rows have no grader at all and the score jumps around. In practice you want at least ~50 trees before you trust it; sklearn warns with "Some inputs do not have OOB scores" when the forest is too small.

MinMaxScaler - normalization

Third notebook, and a change of subject. Trees never needed scaling - they only compare a value to a threshold. But KNN, which we are about to use, measures distances, and a distance is decided by whichever column has the biggest numbers.

Normalization rescales a feature to a fixed range, typically [0, 1]:

$$X_{normalized} = \frac{X - X_{min}}{X_{max} - X_{min}}$$

subtract the minimum, then divide by the span

The numbers for this sample. The 100 values run from -2.395 to 87.046, so every value becomes (X + 2.395) / 89.441. The smallest lands exactly on 0.0 and the largest exactly on 1.0. The shape of the histogram does not change - only the numbers on the axis. That is the point: relative distances inside the column are preserved and only the units are thrown away.
Its weakness: one outlier. Because the formula uses only the minimum and the maximum, a single extreme value owns the whole scale. Push one value to 500 and the other 99 get crushed into the bottom fifth of [0, 1].

StandardScaler - standardization

Standardization transforms data to have zero mean and unit variance. Subtract the mean, divide by the standard deviation:

$$X_{standardized} = \frac{X - \mu}{\sigma}$$

\(\mu\) is the mean of the feature, \(\sigma\) the standard deviation

and the standard deviation itself is:

$$\sigma = \sqrt{\frac{1}{N}\sum_{i=1}^{N}(x_i - \mu)^2}$$

N is the number of samples, \(x_i\) each value, \(\mu\) their mean

from sklearn.preprocessing import StandardScaler

np.random.seed(42)
original_data = np.random.normal(loc=50, scale=20, size=100)

# Apply standardization
scaler = StandardScaler()
standardized_data = scaler.fit_transform(original_data.reshape(-1, 1)).flatten()

plt.subplot(1, 2, 2)
plt.hist(standardized_data, bins=20, alpha=0.7)
plt.title('Standardized Data (Z-score)')
plt.show()

The result is a z-score: "how many standard deviations from average is this value?" - a question you can ask of any column in any unit and get comparable answers.

The empirical rule - 68-95-99.7. For anything roughly normal, about 68% of values fall within ±1σ, about 95% within ±2σ, and about 99.7% within ±3σ. A z-score past ±3 is a genuine rarity, which is why |z| > 3 is the most common outlier rule there is. On this sample the split comes out 65% / 95% / 100%.

The mistake to avoid. A scaler is a model - it learns parameters from data. Fit it on the training set only, then transform the test set with those same numbers: scaler.fit_transform(X_train) then scaler.transform(X_test). Calling fit_transform on the test set leaks test statistics into your model and quietly inflates every score you report.

K-fold cross-validation

A single train_test_split gives you one number from one arbitrary slice. With 9 rows and a 30% test set, that number is decided by three fruits - change the seed and it changes.

Cross-validation rotates the test set through the whole dataset: cut the data into K folds, then run K times, holding out a different fold each round and training on the rest. Each round gives a score, and the answer is their mean.

SplitK folds
the dataset is cut into K equal pieces.
LoopK models
each round holds out one fold and trains on the other K−1.
Combinethe mean
every row is tested exactly once, by a model that never saw it.

The number of folds decides the split of every round:

cvtraintestvalid?
cv=1——✗ nothing left to train on
cv=250%50%✓
cv=366.7%33.3%✓ what we used today
cv=475%25%✓
cv=580%20%✓ the usual default

In general each round trains on \(1 - 1/K\) of the data and tests on \(1/K\) of it.

Why cv=1 is illegal. One fold means that fold is the test set and there is nothing left to train on. sklearn refuses it: ValueError: k-fold cross-validation requires at least one train/test split by setting n_splits=2 or more. If you want a single split, that is train_test_split - a different function for a different job.
For a classifier, cv=3 is quietly StratifiedKFold(3) - sklearn keeps each class's proportion the same in every fold. On data sorted by class, as the fruit table is, plain KFold would put all three apples in one fold and test a model on a class it never trained on. Stratification is what stops that.

k_range = [1, 2, 3, 4, 5, 6]
cv_scores = []

# 9 samples:
# Each iteration = 8 training + 1 testing
# Approximately 90% / 10%
loo = LeaveOneOut()

print("--- Cross-Validation Results ---")

for k in k_range:

    model = KNeighborsClassifier(n_neighbors=k)

    scores = cross_val_score(
        model,
        X_scaled,
        y,
        cv=3,
        scoring='accuracy'
    )

    mean_score = scores.mean()
    cv_scores.append(mean_score)

    print(f"k = {k} | Average Accuracy: {mean_score:.2f}")


# Train final model using best K
best_k = k_range[np.argmax(cv_scores)]

print(f"\nBest K: {best_k}")

model = KNeighborsClassifier(n_neighbors=best_k)
model.fit(X_scaled, y)

# Plot K vs Cross-Validation Accuracy
plt.figure(figsize=(8, 5))
plt.plot(k_range, cv_scores, marker='o')
plt.xlabel("K - Number of Neighbors")
plt.ylabel("Cross-Validation Accuracy")
plt.title("Choosing the Best K")
plt.xticks(k_range)
plt.grid(True)
plt.show()

Why the accuracy collapses as k grows. There are only 9 fruits, 3 of each, and cv=3 holds out 3 - so each model trains on 6 rows, 2 per class. At k=3 the three nearest neighbours cannot all be the right class, because only 2 of that class exist in the training set. By k=6 every prediction looks at the whole training set and returns the same class every time, so accuracy pins at 0.33 - pure chance with three classes. The curve is not saying "small k is better"; it is saying the dataset is tiny.
Spot the loose end. The code creates loo = LeaveOneOut() with a comment about 8 training rows and 1 test row - and then passes cv=3 and never uses loo. The printed numbers are the cv=3 numbers. Swap in cv=loo and they change:

And the scaling actually mattered. Run the same loop on the raw X instead of X_scaled and k=1 falls from 1.00 to 0.89, k=3 from 0.78 to 0.67. weight spans 65 units while size spans 7, so unscaled KNN is very nearly a weight-only classifier.
Reading the plot - the elbow. That "Choosing the Best K" chart is an elbow plot. Here accuracy has a real maximum so np.argmax is the right tool. But when a metric only ever improves - like K-Means inertia, which falls all the way to 0 when every point is its own cluster - there is no maximum to take, and you instead pick the bend: the point where the curve stops dropping steeply and flattens. Before the bend each step buys a lot; after it you pay complexity for nothing. The Scaling & CV deck has a live elbow demo.
