What SVM is

SVM - Support Vector Machine is a supervised learning method: you hand it labelled examples and it learns a rule. It is used to classify, and with a different loss it can also do regression.

Find the boundary that separates the groups with the largest possible gap.

Note the two words doing the work: not just a boundary that separates - the boundary that separates by the most. Infinitely many lines can split two clouds of points; SVM picks the one with the widest empty corridor around it.

Step 1Separate
a line in 2D, a plane in 3D, a hyperplane in n dimensions.
Step 2Measure
the distance from the boundary to the closest point of each group.
Step 3Maximize
keep the boundary whose closest point is the furthest away.

The points that end up sitting on the edge of that corridor are the support vectors:

  • They are the points closest to the separating surface.
  • They are the points that fix where the surface sits.
  • Move a point that is far away - the line does not move.
  • Move a support vector - the line does move.
Why "vector" and not "point"? In linear algebra every point is also a vector from the origin - [3, 4] is both the point (3,4) and the arrow that reaches it. These particular vectors support the position of the surface, so: support vectors.
Where SVM is used. Handwriting and OCR, image classification, face recognition, medical prediction, sentiment analysis in text. It is especially strong when you have many features and not many rows.
Interactive version. The SVM deck opens with a slider that rotates the boundary through every angle so you can watch the margin number peak. Worth two minutes.

The hyperplane equation

The separating surface always has the same equation, whatever the number of features:

$$w^{T}x + b = 0$$

In 2D that is a line, in 3D a plane, in nD a hyperplane. Same formula.

symbolnamewhat it is
wweight vectorthe direction of the surface - perpendicular to it
xthe pointany point in the space (a row of features)
wᵀxdot productthe plain scalar product w₁x₁ + w₂x₂ + …
bbiashow far the surface sits from the origin

The 2D example from the board - with w = [2, -3] and b = 6:

$$2x_1 - 3x_2 + 6 = 0$$

And the whole classification rule is just the sign of the left-hand side:

value of wᵀx + bwhere the point is
> 0on one side of the surface
< 0on the other side
= 0exactly on the surface
That is the whole prediction step. Once w and b are trained, classifying a new point costs one dot product, one addition and one look at the sign. Compare with KNN, which has to measure the distance to every training point at predict time.

Distance to a hyperplane

Given a hyperplane \(w_1x_1 + w_2x_2 + \dots + w_nx_n + b = 0\) and a point \(x = (x_1, x_2, \dots, x_n)\), there are two formulas. They differ by exactly one pair of bars:

$$\textbf{Distance}(x) = \frac{|\,w \cdot x + b\,|}{\sqrt{w_1^2 + w_2^2 + \dots + w_n^2}}$$

Absolute - never negative, just "how far".

$$\textbf{SignedDistance}(x) = \frac{w \cdot x + b}{\sqrt{w_1^2 + w_2^2 + \dots + w_n^2}}$$

Signed - which side and how far, in one number.

partmeaning
numeratorsubstitute the point into the plane equation
denominatorthe length of w - in Python this is np.linalg.norm(w)
with barsdrop the sign → a plain distance
without barskeep the sign → this is what decision_function returns
Why divide by ‖w‖? Because 2x − 3y + 6 = 0 and 4x − 6y + 12 = 0 are the same line, but the second gives numerators twice as big. Dividing by the length of w cancels that out, so the answer is a real distance in the units of the axes.

The function we wrote for two features:

def get_signed_distance(point, w1, w2, b):
    x1, x2 = point
    numerator   = x1 * w1 + x2 * w2 + b
    denominator = np.sqrt(w1**2 + w2**2)   # = np.linalg.norm([w1, w2])
    vec_dist = numerator / denominator
    return vec_dist

def get_abs_distance(point, w1, w2, b):
    return np.abs(get_signed_distance(point, w1, w2, b))
Note the comment we left in the cell. np.sqrt(w1**2 + w2**2) and np.linalg.norm(np.array([w1, w2])) are the same number. The norm version scales to any number of features without adding a term by hand - which is exactly what we needed for the 4D exercise.

Exercise 1 - P3 by hand

We work in 4-dimensional space with features \((x_1, x_2, x_3, x_4)\). The separating hyperplane is:

$$2x_1 - x_2 + x_3 + x_4 - 4 = 0$$

so the weight vector and bias are \(w = (2, -1, 1, 1)\) and \(b = -4\).

The denominator is the same for every point, so we computed it once:

$$\|w\| = \sqrt{2^2 + (-1)^2 + 1^2 + 1^2} = \sqrt{4+1+1+1} = \sqrt{7} \approx 2.6458$$

Then the point \(P_3 = (1, 1, 1, 1)\). This is the scratch cell exactly as we typed it in class:

# P3 = (1, 1, 1, 1)

# w = (2, -1, 1, 1), b = -4
# 2x1 - x2 + x3 + x4 - 4 = 0
# mehane = sqrt(7)
# 2*1 -1*1 +1*1 +1*1 -4 = -1

# abs-distance    = +1 / sqrt(7) = 0.378
# signal-distance = -1 / sqrt(7) = ~ -0.378

# is below the hyperplane

$$2(1) - 1 + 1 + 1 - 4 = -1$$

$$\text{Distance}(P_3) = \frac{|-1|}{\sqrt7} \approx 0.378 \qquad \text{SignedDistance}(P_3) = \frac{-1}{\sqrt7} \approx -0.378$$

The minus is the whole point. P3 is 0.378 units away, below the hyperplane. The absolute version tells you the distance but not the class - only the signed version can predict.

Find the line that separates group A from group B with the biggest possible margin. No sklearn. Fix w2 = -1 so every line is y = w1*x + b, then search a grid of w1 and b.

Exercise 2 - the search loop

The plan we wrote as comments before writing any code:

Step 1Validity
every group A point negative, every group B point positive. One mismatch and the line is thrown away.
Step 2Closest point
collect all eight distances and take the min.
Step 3Keep the max
remember the line whose minimum is the largest so far.
def get_signed_distance(point, w1, w2, b):
    x1, x2 = point
    numerator   = x1 * w1 + x2 * w2 + b
    denominator = np.sqrt(w1**2 + w2**2)   # = np.linalg.norm
    return numerator / denominator

w1 = np.linspace(-5, 5, 100)
# w2 will be -1
b = np.linspace(-10, 20, 100)

largest_distance_from_min = -1   # the largest distance from the closest point
best_w1 = None
best_b = None

for w1_current in w1:
    for b_current in b:
        # step 1 check if all points are on the correct side
        # if label == 0 --> get_signed_distance (negative)
        # if label == 1 --> get_signed_distance (positive)
        # if 1 point does not match --> continue
        distances = []
        valid = True

        for point in group_a:
            dist = get_signed_distance(point, w1_current, -1, b_current)
            # should be negative, if positive -- the line is invalid
            if dist >= 0:
                valid = False
                break
            else:
                distances.append(abs(dist))
        if not valid:
            continue

        for point in group_b:
            dist = get_signed_distance(point, w1_current, -1, b_current)
            # should be positive, if negative -- the line is invalid
            if dist <= 0:
                valid = False
                break
            else:
                distances.append(abs(dist))
        if not valid:
            continue

        # step 2 - find the closest point to this surface
        closest_point_distance = min(distances)
        if closest_point_distance > largest_distance_from_min:
            largest_distance_from_min = closest_point_distance
            best_w1 = w1_current
            best_b = b_current

print('w1', best_w1)
print('w2', -1)
print('b', best_b)
print(largest_distance_from_min)
Outputw1 3.787878787878787 w2 -1 b -10.0 1.005548803070833
Why w2 = -1 and not something else? Any non-vertical line can be written y = w1*x + b, which is w1*x - 1*y + b = 0. Fixing w2 = -1 removes the scaling freedom (remember: doubling w and b gives the same line) and turns a three-number search into a two-number one. The price is that a perfectly vertical line can never be represented.
Two things went wrong here, and they are worth more than the answer.

1 · The sign convention picked the wrong family of lines. With w2 = -1, a negative signed distance means the point is above the line. So this code demanded that group A (lower-left) sits above the line and group B (upper-right) sits below it. Only a steep, positively-sloped line threading diagonally between the clusters can do that - which is why the answer is y = 3.788x − 10 and not the intuitive north-west-to-south-east separator. Flip the two comparisons and re-run, and the search returns w1 = -1.768, b = 10.909, margin 1.442 - which is essentially what SVC will give us.

2 · The winner landed on the edge of the grid. b = -10.0 is the very first value of np.linspace(-10, 20, 100). When the best candidate sits on the boundary of the search space, the search did not converge - it ran out of room. Widen the grid and it just keeps walking away.

That last row is the exercise's whole point. The corridor SVC finds is 45% wider than the one 10 000 guesses found, and it takes two lines of code. The small gap between rows 2 and 3 is pure grid resolution - the true optimum has slope −1.667, which simply is not one of the 100 values in np.linspace(-5, 5, 100).
See the answer this search was reaching for. The SVM deck opens with a slider that rotates the boundary through every angle and reports the margin for each one - so you can watch the number peak at exactly the value SVC returns, without searching a grid at all.

Read the offset line carefully - it is the only real maths in the cell. largest_distance_from_min is a perpendicular distance, but we are shifting the line vertically. To move a line by d perpendicularly you shift its intercept by d · ‖w‖, and here ‖w‖ = √(w1² + 1). That is exactly np.sqrt(best_w1**2 + (-1)**2).

$$\text{vertical shift} = \text{perpendicular distance} \times \sqrt{w_1^2 + w_2^2}$$

A steep line needs a much bigger vertical shift to move the same real distance.

Check it with our numbers: 1.0055 × √(3.788² + 1) = 1.0055 × 3.918 = 3.940. So the two dashed lines sit at b = −10 ± 3.940, that is −6.06 and −13.94.

A detail in the plot. line_x = np.linspace(0, 10, 10) only produces ten points, but a straight line needs just two - matplotlib joins them with segments and a straight line stays straight. For a curve you would want 100 or more.

The margin follows straight from w:

$$\|w\| = \sqrt{0.58824^2 + 0.35294^2} = 0.68599 \qquad \text{margin} = \frac{2}{\|w\|} = 2.9155$$

Half of that, 1.4577, is the distance from the boundary to each support vector.

Check the two support vectors by hand.
(2.5, 3.5) → 0.58824(2.5) + 0.35294(3.5) − 3.70588 = −1.000
(5, 5)     → 0.58824(5) + 0.35294(5) − 3.70588 = +1.000
Exactly ±1. That is not a coincidence - SVM fixes the scale of w and b so that the support vectors land on ±1, which is why the margin comes out as 2/‖w‖.
Bonus: rebuild w from dual_coef_. The weight vector is nothing but a weighted sum of the support vectors - w = Σ αᵢyᵢxᵢ, and dual_coef_ holds exactly those αᵢyᵢ numbers. Try it:
−0.23529 × (2.5, 3.5) + 0.23529 × (5, 5) = 0.23529 × (2.5, 1.5) = (0.58824, 0.35294)
which is coef_, to the last digit. Six of the eight points contributed nothing at all.
Scale your features before SVC. The margin is measured in the raw units of your columns, so a column running 0–100000 completely drowns out a column running 0–1 - the same problem MinMaxScaler solved for KNN. Use StandardScaler inside a Pipeline. Our toy data gets away with it only because both axes already span roughly 1 to 7.

So the boundary is y = −1.667x + 10.5, and the two dashed margin lines are the same line shifted vertically by ±2.833.

Why the margin lines are always ±1. With brute force we had to compute the offset from the actual distance. With sklearn we do not - the solver defines the scale so that the support vectors satisfy wᵀx + b = ±1. Setting the equation to 1 and solving for y gives exactly +1/w[1], so the shift is free.
facecolors="none" with edgecolors="black" is the standard trick for circling the support vectors: a scatter marker with no fill and a visible outline drawn on top of the coloured points.
Compare the two plots side by side. Brute force drew a steep line climbing left to right; sklearn drew a line falling from top-left to bottom-right. Both separate the eight points perfectly - but only one of them has the widest possible corridor.

import matplotlib.pyplot as plt
from sklearn.svm import SVC
from sklearn.metrics import confusion_matrix, accuracy_score, classification_report

# ---------- the data ----------
group_a = np.array([[1, 2], [1.5, 3], [2, 2.5], [2.5, 3.5]])
group_b = np.array([[5, 5], [5.5, 6], [6, 5.5], [6.5, 6.5]])
points = np.vstack([group_a, group_b])
labels = np.array([0, 0, 0, 0, 1, 1, 1, 1])

# ---------- brute force ----------
def get_signed_distance(point, w1, w2, b):
    x1, x2 = point
    return (x1 * w1 + x2 * w2 + b) / np.sqrt(w1**2 + w2**2)

best = {'m': -1, 'w1': None, 'b': None}
for w1_current in np.linspace(-5, 5, 100):
    for b_current in np.linspace(-10, 20, 100):
        distances, valid = [], True
        for point in group_a:
            d = get_signed_distance(point, w1_current, -1, b_current)
            if d >= 0:
                valid = False
                break
            distances.append(abs(d))
        if not valid:
            continue
        for point in group_b:
            d = get_signed_distance(point, w1_current, -1, b_current)
            if d <= 0:
                valid = False
                break
            distances.append(abs(d))
        if not valid:
            continue
        m = min(distances)
        if m > best['m']:
            best = {'m': m, 'w1': w1_current, 'b': b_current}

print(f"brute force : y = {best['w1']:.3f}x + {best['b']:.3f}   margin = {best['m']:.4f}")

# ---------- sklearn ----------
clf = SVC(kernel='linear')
clf.fit(points, labels)

w = clf.coef_[0]
b = clf.intercept_[0]
norm = np.linalg.norm(w)

print(f"SVC         : y = {-(w[0]/w[1]):.3f}x + {(-b/w[1]):.3f}   margin = {1/norm:.4f}")
print('w', w)
print('b', b)
print('support vectors\n', clf.support_vectors_)
print('support indices', clf.support_)

# ---------- evaluation ----------
y_pred = clf.predict(points)
print("prediction:", y_pred)
print("true:      ", labels)        # <- fixed: was y_pred in class
print("Confusion matrix:\n", confusion_matrix(labels, y_pred))
print("Accuracy:", accuracy_score(labels, y_pred))
print(classification_report(labels, y_pred))

# ---------- plot both ----------
line_x = np.linspace(0, 8, 100)

# brute force line + its margin
bf_y = best['w1'] * line_x + best['b']
offset = best['m'] * np.sqrt(best['w1']**2 + 1)
plt.plot(line_x, bf_y, 'purple', label='brute force')
plt.plot(line_x, bf_y + offset, 'purple', ls='--', lw=1)
plt.plot(line_x, bf_y - offset, 'purple', ls='--', lw=1)

# sklearn line + its margin
sk_y = -(w[0]/w[1]) * line_x + (-b/w[1])
plt.plot(line_x, sk_y, 'k', label='SVC')
plt.plot(line_x, sk_y + 1/w[1], 'k--', lw=1)
plt.plot(line_x, sk_y - 1/w[1], 'k--', lw=1)

plt.scatter(group_a[:, 0], group_a[:, 1], color='red')
plt.scatter(group_b[:, 0], group_b[:, 1], color='blue')
plt.scatter(clf.support_vectors_[:, 0], clf.support_vectors_[:, 1],
            edgecolors='black', facecolors='none', s=140)
plt.xlim(0, 8); plt.ylim(0, 8)
plt.grid(True, alpha=0.3); plt.legend()
plt.show()
