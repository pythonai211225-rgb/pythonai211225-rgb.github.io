Nothing to scale today. No MinMaxScaler, no StandardScaler. A decision tree only ever compares a value to a threshold, and that comparison does not care about units - so unlike KNN and SVM, a tree needs no preprocessing at all.

What a decision tree is

A decision tree is a supervised learning algorithm that imitates the way people make decisions. The algorithm splits the data into smaller and smaller pieces based on the values of specific features, and builds a structure shaped like a tree.

Inner nodesFeatures
each internal node represents a property of the data - a question about one feature.
BranchesThe rules
the edges leaving a node carry the yes/no answer to its question.
LeavesThe result
the final nodes hold the outcome - the predicted class.

Two examples from the board:

questionthe tree
Should I accept this job offer?salary ≥ $50,000? → commute over 1 hour? → free coffee? → accept / decline
Is this fruit an apple or a pear?width < 7.35? → height < 7.4? → apple / pear
The main advantage of decision trees is that they are simple - you can read the model, interpret it, and display it visually. The main disadvantage is the tendency to overfit: low accuracy on predictions, and a bias when handling unbalanced datasets.
Notice what the fruit example draws. Two cuts - one horizontal at width 7.35, one vertical at height 7.4 - split the plane into rectangles. Every question is feature ≤ number, so a tree can only ever draw boundaries parallel to the axes. It can never draw the diagonal line that SVM found last lesson.
See it move. The deck opens with the same six-row dataset being carved one split at a time, so you can watch the rectangles appear.

The vocabulary

Every one of these words appears in the sklearn documentation and in the output of export_text, so they are worth learning properly:

Root node

The single node at the top. It holds all the training rows before any question is asked.

Decision node

Any internal node. Holds a question and has exactly two children.

Leaf node

A node with no children. Holds the answer - the predicted class.

Edge

The line from a parent to a child. Carries the yes/no result of the parent's question.

Parent / child

The node above, and the two directly below it.

Subtree

A node together with everything hanging below it. A subtree is itself a valid tree.

Depth

How far a node sits below the root. The root is depth 0.

Height

The longest path down to a leaf, in edges. Every leaf has height 0.

Depth and height run in opposite directions. Depth counts downwards from the root; height counts upwards from the leaves. The root has depth 0 and height equal to the depth of the deepest leaf. max_depth in sklearn limits the first of the two.
in sklearnwhat it gives you

clf.get_n_leaves()how many leaves the tree has

clf.tree_.featurewhich feature each node splits on (-2 = leaf)
clf.tree_.thresholdthe number each node compares against
clf.tree_.impuritythe Gini value of every node - the array we printed

Pruning

Pruning is a technique that reduces the size of a decision tree by removing sections that provide little power to classify instances. The goal is to reduce complexity and prevent overfitting.

When a subtree is pruned it is typically replaced with a leaf node representing the average value (for regression) or the majority class (for classification) of the original subtree's leaves.

1 · Pre-pruning (early stopping). We stop the tree from growing too deep by setting limits before it is grown:
  • max_depth - maximum depth of the tree
  • min_samples_split - minimum number of samples to allow a split
  • min_samples_leaf - minimum samples required at a leaf node
2 · Post-pruning. Grow the full tree first, then cut back branches that do not improve generalization. This is less commonly used in scikit-learn and more common in academic contexts - though sklearn does offer it as ccp_alpha.
Why this matters more for trees than for anything else. Nothing stops a tree from splitting until every leaf holds a single row. When that happens, training accuracy is exactly 1.0 and the model has memorized the data instead of learning the pattern. Every accuracy of 1.0 you will see on this page is that effect, not evidence of a good model.
Watch it happen. The deck has a noisy dataset with max_depth and min_samples_leaf sliders, showing train and test accuracy side by side as the tree grows.

Gini impurity

To choose which question to ask, the tree needs to score how mixed a group of rows is. That score is the Gini impurity. The formula as written on the board:

$$G(Q) = \sum_{c \in C} p_c\,(1 - p_c)$$

symbolmeaning
Qa particular node in the decision tree
G(Q)the Gini impurity value of that node
Cthe set of categories (classes) in the node
pcthe probability that an object in the node belongs to category c
1 − pcthe probability that an object does not belong to category c
Σthe sum over all categories in the node

Multiply out the sum and you get the equivalent form that everybody actually uses:

$$G(Q) = 1 - \sum_{c \in C} p_c^{\,2}$$

And for a binary classification - two categories only - it simplifies to:

$$G(Q) = 1 - \bigl[(p_1)^2 + (p_2)^2\bigr]$$

The worked example from the board. A dataset of 10 samples: 7 belong to category A, 3 to category B:

$$G(Q) = 1 - \bigl[(7/10)^2 + (3/10)^2\bigr]$$

$$G(Q) = 1 - [0.49 + 0.09]$$

$$G(Q) = 1 - 0.58 = \mathbf{0.42}$$

Read Gini as a bet. Pull one row out of the node at random, then guess its class by drawing a second row at random. Gini is the probability that you guess wrong. A pure node can never be wrong, so it scores 0.

Look at cases 5 and 6. The more classes there are, the higher Gini can climb. With k equally sized classes the maximum is exactly:

$$G_{\max} = 1 - \frac{1}{k}$$

0.5 for two classes, 0.667 for three, 0.75 for four. Gini is not capped at 0.5 - that is only the binary case.

The starting point - the root node holds all six rows, 3 A and 3 B:

$$G(\text{root}) = 1 - \bigl[(3/6)^2 + (3/6)^2\bigr] = 1 - [0.25 + 0.25] = \mathbf{0.5}$$

The worst possible value for two classes - a perfect 50/50 mix.

And this is the cell that set up the exercise:

START

Option 1: x1 > 3
Option 2: x2 <= 2

To score either option we need two more formulas. The weighted Gini combines the two children, weighting each by how many rows it holds:

$$G_{\text{split}} = \frac{n_{\text{yes}}}{n}\,G(\text{yes}) + \frac{n_{\text{no}}}{n}\,G(\text{no})$$

And the Gini gain is how much impurity the question removed:

$$\text{Gain} = G(\text{parent}) - G_{\text{split}}$$

Bigger gain = better question. A gain of 0 means the question told us nothing.

Where those counts come from:

branchrowsclassesGini
Yes — X1 > 33, 4, 5 → (4,3)=B, (5,1)=A, (6,2)=BA: 1  B: 24/9 ≈ 0.444
No — X1 ≤ 30, 1, 2 → (1,3)=A, (2,1)=A, (3,2)=BA: 2  B: 14/9 ≈ 0.444

Both sides hold 3 rows, so the weighting is even:

$$G_{\text{split}} = \tfrac{3}{6}\,(0.444) + \tfrac{3}{6}\,(0.444) = 0.444$$

$$\text{Gain} = 0.5 - 0.444 = \mathbf{0.056}$$

0.056 is a small gain, but it is not nothing - both children lean slightly toward one class where the parent was perfectly balanced. Now do option 2 and compare.

Option 2 — X2 ≤ 2 — the answer

This is the question the notebook left open. Split the same six rows on X2 <= 2:

branchrowsclassesGini

No — X2 > 20, 3 → A, BA: 1  B: 11 − [0.25 + 0.25] = 0.5

This time the sides are uneven - 4 rows against 2 - so the weights matter:

$$G_{\text{split}} = \tfrac{4}{6}\,(0.5) + \tfrac{2}{6}\,(0.5) = 0.5$$

$$\text{Gain} = 0.5 - 0.5 = \mathbf{0}$$

Option 1 wins. Option 2 has a gain of exactly zero: both of its children are still perfectly 50/50, so the question separated nothing at all. Asking it would produce two nodes just as confused as the one we started with.
But neither option is the best. The tree does not pick from two hand-written options - it tries every threshold on every feature. On these six rows there are only seven candidates, and two of them score far better:
splitleft groupright groupweighted Ginigain
X1 ≤ 1.5AA B B A B0.4000.100
X1 ≤ 2.5A AB B A B0.2500.250 ← best
X1 ≤ 3.5A A BB A B0.4440.056 ← option 1
X1 ≤ 4.5A A B BA B0.5000.000
X1 ≤ 5.5A A B B AB0.4000.100
X2 ≤ 1.5A AA B B B0.2500.250 ← tie
X2 ≤ 2.5A B A BA B0.5000.000 ← option 2
Why the thresholds are all halves. The tree only tries the midpoints between neighbouring values. X1 takes the values 1,2,3,4,5,6, so the candidates are 1.5, 2.5, 3.5, 4.5, 5.5 - five of them, not infinitely many. Any threshold between two data points splits the rows identically, so the midpoint stands in for all of them. That is why export_text prints X1 <= 2.50 and never X1 <= 2.
Two splits tie at 0.250. X1 ≤ 2.5 and X2 ≤ 1.5 are equally good and sklearn has to break the tie somehow - it uses random_state. With random_state=42 this data gives X1 <= 2.50 as the root. That is exactly why you should always set that argument.

What the split actually produced with random_state=42:

The splittrain (6 rows): [1,2]→0 [8,8]→0 [3,1]→0 [5,4]→1 [4,5]→1 [7,6]→1 test (2 rows): [2,3]→0 [6,7]→1
Notice the last leaf. X2 > 7.00 → class 0 catches exactly one row: [8,8], the deliberate odd one out - a point in the far corner labelled 0 while all its neighbours are 1. The tree grew an entire branch for that single row. That is overfitting caught in the act, visible in the printed rules.
A test set of two rows is not evidence either. One row flipping takes you from 100% to 50%. This is a teaching example - on real data you want hundreds of test rows, and for small datasets you use cross_val_score, which scores every row exactly once across several folds.

The whole thing in one script

Copy-paste and run - the Gini calculations done by hand and by sklearn side by side, so you can see they agree:

import numpy as np
import pandas as pd
from sklearn.tree import DecisionTreeClassifier, export_text
from sklearn.metrics import accuracy_score, confusion_matrix, classification_report
from sklearn.model_selection import train_test_split

# ---------- Gini by hand ----------
def gini(labels):
    labels = list(labels)
    n = len(labels)
    if n == 0:
        return 0.0
    return 1 - sum((labels.count(c) / n) ** 2 for c in set(labels))

# the six cases from the board
print('A5 B5  ', gini(list('AAAAABBBBB')))        # 0.5
print('A10 B0 ', gini(list('AAAAAAAAAA')))        # 0.0
print('A7 B3  ', gini(list('AAAAAAABBB')))        # 0.42
print('A2B2C2 ', gini(list('AABBCC')))            # 0.6667
print('3 each ', gini(list('AAABBBCCCDDD')))      # 0.75

# ---------- the exercise dataset ----------
X = np.array([[1, 3], [2, 1], [3, 2], [4, 3], [5, 1], [6, 2]])
y = np.array(['A', 'A', 'B', 'B', 'A', 'B'])

print('\nroot gini =', gini(y))                   # 0.5

# score any split by hand
def score(feature, thr):
    mask = X[:, feature] <= thr
    left, right = y[mask], y[~mask]
    w = len(left) / len(y) * gini(left) + len(right) / len(y) * gini(right)
    return w, gini(y) - w

# the two options from the board
w1, g1 = score(0, 3)      # X1 <= 3   is the same split as "X1 > 3"
w2, g2 = score(1, 2)      # X2 <= 2
print(f'option 1  X1 <= 3 : weighted={w1:.4f}  gain={g1:.4f}')
print(f'option 2  X2 <= 2 : weighted={w2:.4f}  gain={g2:.4f}')

# every candidate the tree would actually try
print('\nall candidate splits:')
for f, name in [(0, 'X1'), (1, 'X2')]:
    vals = sorted(set(X[:, f]))
    for a, b in zip(vals, vals[1:]):
        thr = (a + b) / 2
        w, g = score(f, thr)
        print(f'  {name} <= {thr:<4} weighted={w:.4f}  gain={g:.4f}')

# ---------- the same thing with sklearn ----------
clf = DecisionTreeClassifier(criterion='gini', random_state=42)
clf.fit(X, y)

print('\nsklearn picked:')
print(export_text(clf, feature_names=['X1', 'X2'], show_weights=True))
print('impurity  ', clf.tree_.impurity)
print('feature   ', clf.tree_.feature)      # -2 means leaf
print('threshold ', clf.tree_.threshold)
print('depth     ', clf.get_depth(), ' leaves', clf.get_n_leaves())
print('accuracy  ', accuracy_score(y, clf.predict(X)))
