Distance by hand, before any code

We started on paper. Three known points p, one new point q = (4, 5), and the plain Pythagoras distance between them.

$$d(p, q) = \sqrt{\sum_{i=1}^{n} (p_i - q_i)^2}$$

Subtract, square, add up, square root. One extra feature is just one more ( )² inside.

This is the scratch cell exactly as we typed it in class:

# p = (1, 4) (2, 7) (3, 3)
# q   (4, 5)

#     (1, 4)
#     [(3)² + (1)²]
#     [9 + 1]
#     √10 = 3.162

#     (2, 7) = √8 = 2.82
#     (3, 3) = √5 = 2.23
pΔxΔyΔx² + Δy²d
(1, 4)319 + 1 = 10√10 = 3.162
(2, 7)2-24 + 4 = 8√8 = 2.828
(3, 3)121 + 4 = 5√5 = 2.236 <- nearest

In Python you never type the square root yourself - np.linalg.norm is the whole formula:

p = np.array([3, 3])
q = np.array([4, 5])

np.linalg.norm(p - q)     # 2.2360679... = √5
norm = length of a vector. np.linalg.norm([1, 2, 3]) is \(\sqrt{1^2+2^2+3^2}\). The length of p - q is the distance from p to q, in any number of dimensions.

Min-Max by hand

Before scaling anything with sklearn, we did one value on paper. A column that runs from 20 to 250, and the value 200:

$$x_{norm} = \frac{x - \min(x)}{\max(x) - \min(x)}$$

#         ─────────
#         Xmax - Xmin

Xmax = 250
Xmin = 20

Why we bother. Color runs 20-250, size runs 6-13. Inside one square root the color gap gets squared into the thousands while the size gap contributes single digits - so without scaling, KNN only ever looks at color. Scaling puts every column on the same 0-1 ruler.

Step 2 - normalize the new fruit with the same scaler

This is the line people get wrong. The new fruit must be measured with the ruler we already built:

######################### STEP 2 - normalize the fruit with the same scaler
new_fruit = pd.DataFrame({'Weight': [155], 'Color': [220], 'Size': [8]})

# transform - scale only
new_fruit_norm = min_max_scaler.transform(new_fruit[['Weight', 'Color', 'Size']])
print('new_fruit_norm', new_fruit_norm)
Outputnew_fruit_norm [[0.61538462 0.86956522 0.28571429]]

Check it by hand - the three numbers are just the Min-Max formula three times:

Featurecalculationresult
Weight(155 - 115) / (180 - 115) = 40 / 650.61538462
Color(220 - 20) / (250 - 20) = 200 / 2300.86956522
Size(8 - 6) / (13 - 6) = 2 / 70.28571429
Never call fit_transform on the new fruit. It has one row, so that row would become its own min and its own max - every value turns into 0 and all the distances are garbage. fit_transform on the training data once, transform on everything after.

Step 3 - distance to all nine fruits

Loop over the rows, subtract, and take the norm of the difference:

######################### STEP 3 - find dist between the new_fruit and ALL other fruits
distances = []
for i in range(len(df_norm)):
    diff_arr = df_norm.iloc[i][['Weight', 'Color', 'Size']] - new_fruit_norm[0]
    dist = np.linalg.norm(diff_arr)   # [1,2,3] = √[(1)² + (2)² + (3)²]
    distances.append( (i, dist, df_norm.iloc[i]['Fruit']) )
Read the three lines. df_norm.iloc[i][[...]] is one fruit as three numbers · subtracting new_fruit_norm[0] gives the gap per feature · np.linalg.norm squares them, adds them and takes the root. Each loop appends a tuple (index, distance, label).

Worked out for the very first row - apple #0, normalized (0.5385, 0.7826, 0.1429):

$$d = \sqrt{0.0769^2 + 0.0870^2 + 0.1429^2} = \sqrt{0.0339} = 0.18408$$

The same number Python prints for index 0.

Step 4 - sort by distance and take the first five

sorted has no idea which slot of the tuple is the distance, so we tell it with key:

######################### STEP 4 - sort by distance + choose first 5
sorted(distances, key=lambda item: item[1])[:5]

# d = [{'id': 1, 'dist': 3}, {'id': 2, 'dist': 2}]
# sorted(d, key=lambda item: item['dist'])
Output[(0, 0.18408356716879312, 'Apple'), (4, 0.20169747536206847, 'Orange'), (3, 0.2849983119390297, 'Orange'), (2, 0.3672697794960086, 'Apple'), (5, 0.4125863746131085, 'Orange')]
key=lambda item: item[1] means "for each element, compare this". Our elements are tuples (i, dist, label), so slot [1] is the distance. With dictionaries you would write key=lambda item: item['dist'] - the commented lines at the bottom of the cell.
If your output looks different: on NumPy 2.x the same list prints as [(0, np.float64(0.18408356716879312), 'Apple'), ...]. The numbers are identical - only the way NumPy shows a single float changed. Unpack the tuple and format it yourself to avoid the noise: 
for i, d, label in sorted(distances, key=lambda item: item[1])[:5]:
    print(f'{label:7s} index={i}  d={d:.5f}')

The same thing with KNeighborsClassifier

Everything above in four sklearn lines. Build the matrix, scale it, fit, predict:

# Fruit data
colors = np.array([200, 50, 220, 240, 250, 230, 30, 40, 20])
sizes = np.array([7, 7, 6, 9, 8, 9, 12, 13, 11])
weights = np.array([150, 160, 140, 170, 165, 180, 120, 130, 115])
fruit_types = np.array(['apple', 'apple', 'apple',
                        'orange', 'orange', 'orange',
                        'banana', 'banana', 'banana'])

# Create feature matrix
X = np.column_stack((colors, sizes, weights))
y = fruit_types

# Normalize data
scaler = MinMaxScaler()          # create
X_scaled = scaler.fit_transform(X)   # activate

k = 3   # number of neighbors
# weights = uniform  -- All points in each neighborhood are weighted equally
# weights = distance -- weight points by the inverse of their distance.
#                       closer neighbors of a query point will have a greater
#                       influence than neighbors which are further away.
model = KNeighborsClassifier(n_neighbors=k, weights='distance')

model.fit(X_scaled, y)   # store the points

# New fruit to classify
new_fruit = np.array([[220, 8, 155]])
new_fruit_scaled = scaler.transform(new_fruit)

prediction = model.predict(new_fruit_scaled)
probabilities = model.predict_proba(new_fruit_scaled)
print(model.classes_)
print(probabilities)

# Output result
print(f"Prediction: The new fruit is a {prediction[0]}")
Output['apple' 'banana' 'orange'] [[0.39084138 0. 0.60915862]] Prediction: The new fruit is a orange
Careful with the column order. Here X is built as (colors, sizes, weights) and the new fruit as [[220, 8, 155]] - color, size, weight. The manual version used Weight, Color, Size. The order only has to be consistent between fit and predict; mix them up and you are comparing a weight to a color.
fit does no maths. It just stores the points. All the work - all nine distances - happens inside predict. That is why KNN is called a lazy learner.

Reading predict_proba

Two prints, and they belong together:

Output['apple' 'banana' 'orange'] [[0.39084138 0. 0.60915862]]
classes_probabilitymeaning
apple0.39084138one of the 3 neighbors
banana0.00000000no banana in the top 3 at all
orange0.60915862two of the 3 neighbors - wins
Always read the probabilities against model.classes_. sklearn sorts the labels alphabetically - apple, banana, orange - not in the order they appear in your data. Assuming your own order is how you end up reporting the wrong class.

Because we passed weights='distance', each neighbor votes with \(1/d\) instead of 1. That is where the exact numbers come from:

neighborclassd1 / d
#0apple0.184085.4323
#4orange0.201704.9579
#3orange0.285003.5088
total weight13.8990

$$P(\text{apple}) = \frac{5.4323}{13.8990} = 0.3908 \qquad P(\text{orange}) = \frac{4.9579 + 3.5088}{13.8990} = 0.6092$$

Exactly the two numbers sklearn printed.

With weights='uniform' the same three neighbors would give a blunter 0.3333 / 0 / 0.6667 - one vote each. The prediction stays Orange either way.

The whole thing in one script

Copy-paste and run - manual version and sklearn version side by side, so you can check that they agree:

import numpy as np
import pandas as pd
from sklearn.preprocessing import MinMaxScaler
from sklearn.neighbors import KNeighborsClassifier

# ---------- the data ----------
df = pd.DataFrame({
    "Fruit": ["Apple", "Apple", "Apple",
              "Orange", "Orange", "Orange",
              "Banana", "Banana", "Banana"],
    "Weight": [150, 160, 140, 170, 165, 180, 120, 130, 115],
    "Size": [7, 7, 6, 9, 8, 9, 12, 13, 11],
    "Color": [200, 50, 220, 240, 250, 230, 30, 40, 20]
})

# ---------- manual KNN ----------
min_max_scaler = MinMaxScaler()
df_norm = df.copy()
df_norm[['Weight', 'Color', 'Size']] = min_max_scaler.fit_transform(
                                           df_norm[['Weight', 'Color', 'Size']])

new_fruit = pd.DataFrame({'Weight': [155], 'Color': [220], 'Size': [8]})
new_fruit_norm = min_max_scaler.transform(new_fruit[['Weight', 'Color', 'Size']])

distances = []
for i in range(len(df_norm)):
    diff_arr = df_norm.iloc[i][['Weight', 'Color', 'Size']] - new_fruit_norm[0]
    dist = np.linalg.norm(diff_arr)
    distances.append( (i, dist, df_norm.iloc[i]['Fruit']) )

top5 = sorted(distances, key=lambda item: item[1])[:5]
for i, d, label in top5:
    print(f'{label:7s} index={i}  d={d:.5f}')

# ---------- sklearn KNN ----------
X = np.column_stack((df['Color'], df['Size'], df['Weight']))
y = df['Fruit'].values

scaler = MinMaxScaler()
X_scaled = scaler.fit_transform(X)

model = KNeighborsClassifier(n_neighbors=3, weights='distance')
model.fit(X_scaled, y)

q = scaler.transform(np.array([[220, 8, 155]]))
print(model.classes_)
print(model.predict_proba(q))
print('Prediction:', model.predict(q)[0])
OutputApple index=0 d=0.18408 Orange index=4 d=0.20170 Orange index=3 d=0.28500 Apple index=2 d=0.36727 Orange index=5 d=0.41259 ['Apple' 'Banana' 'Orange'] [[0.39084138 0. 0.60915862]] Prediction: Orange
Both halves agree. The hand-written loop and KNeighborsClassifier pick the same three neighbors and produce the same probabilities - which is the point of writing it twice.
