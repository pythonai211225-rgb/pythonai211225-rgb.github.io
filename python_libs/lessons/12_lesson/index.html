The 4-feature apartment data

We predict an apartment price from four features: area (m²), number of rooms, age (years) and distance from the center (km). Ten apartments, no random code - everyone gets the same numbers.

import numpy as np
from sklearn.linear_model import LinearRegression
from sklearn.metrics import mean_squared_error, r2_score
from sklearn.model_selection import train_test_split

#              area  rooms  age  dist
X = np.array([[ 70,   3,    15,   5],
              [ 90,   4,    10,   7],
              [ 60,   2,    20,   3],
              [120,   5,     5,  10],
              [ 80,   3,    12,   6],
              [110,   4,     8,   8],
              [100,   4,     7,   5],
              [ 75,   3,    18,   4],
              [ 95,   4,     9,   6],
              [130,   5,     3,  12]])

Y = np.array([1200, 1500, 1100, 1800, 1300, 1650, 1750, 1250, 1550, 1900])
Four features means the model learns four weights (β₁, β₂, β₃, β₄) plus the bias β₀ - one number per column, exactly like the 3-feature case from Lesson 11.

First attempt - fit on ALL the data

The naive approach: train on every row, then score on those same rows.

model = LinearRegression()
model.fit(X, Y)          # train on all 10 apartments
y_pred = model.predict(X)

print('model.intercept_ =', model.intercept_)
print('model.coef_      =', model.coef_)
print('R² =', r2_score(Y, y_pred))
print('mse=', mean_squared_error(Y, y_pred))

$$\hat{y} = 740.66 + 11.31\,\text{area} + 40.11\,\text{rooms} - 15.69\,\text{age} - 41.38\,\text{dist}$$

R² = 0.988 looks fantastic... but we tested on the very data we trained on.

The trap: a model always looks good on the data it memorized. Scoring on the training set is like grading students on the exact questions they already saw. We need to test on data the model has never seen.

train_test_split - hide some data

train_test_split from sklearn.model_selection randomly cuts the data into a training set (the model learns from it) and a test set (kept secret, used only to grade).

X_train, X_test, Y_train, Y_test = train_test_split(
    X, Y,
    test_size=0.2,      # 20% goes to the test set (2 of 10 apartments)
    random_state=42)    # a fixed seed → the same split every run

model = LinearRegression()
model.fit(X_train, Y_train)      # ← learn ONLY from the training rows

print(model.intercept_)          # 728.62
print(model.coef_)               # [12.17  32.18  -16.03  -46.50]
ArgumentMeaning
X, YThe full features and target to be split
test_size=0.2Fraction kept for testing - here 20% → 8 train rows, 2 test rows
random_state=42Seed for the random shuffle - a fixed number means a reproducible split
The function returns four things in this exact order: X_train, X_test, Y_train, Y_test. Mix up the order and everything downstream breaks.

Overfitting revealed

Now score the model twice - once on the training rows it learned from, once on the hidden test rows.

# predict on both sets
y_pred_train = model.predict(X_train)
y_pred_test  = model.predict(X_test)

# R²
r2_train = r2_score(Y_train, y_pred_train)
r2_test  = r2_score(Y_test,  y_pred_test)

# mse
mse_train = mean_squared_error(Y_train, y_pred_train)
mse_test  = mean_squared_error(Y_test,  y_pred_test)

print('R² train =', r2_train)
print('R² test  =', r2_test)
print('mse train', mse_train)
print('mse test' , mse_test)

A negative R² is a red alarm. Remember \(R^2 = 1 - \frac{SSE}{SST}\). If our model's error SSE is larger than the error of simply always guessing the mean SST, the fraction exceeds 1 and R² drops below 0.

This is overfitting. With only 8 training rows and 4 features, the model has almost enough freedom to memorize the training set perfectly - so it fits the noise, not the pattern. It shines on training data (0.99) and falls apart on anything new (−1.17).
The lesson: never trust a score measured on the training data. Always keep a test set the model never sees, and judge it there.

Why we need Adjusted R²

Plain R² has a dangerous flaw: it can never go down when you add a feature.

Add a completely useless feature - say, using a person's shoe size to predict their annual income - and R² will either stay the same or creep up by pure chance. It will never decrease. So a naive reading of R² tempts you to keep piling on random columns, making the model look mathematically better on paper while it becomes useless on real, future data.

This is exactly the overfitting we just saw. More features → higher training R² → but worse predictions on unseen data.

Adjusted R² acts as an honest referee. It balances two competing forces:

Reward ↑ It rises if a new feature genuinely improves the predictions.
Penalty ↓ It falls if a new feature adds no real value - you pay a fee just for adding complexity.
Net effect Only features that pull their own weight survive.

The Adjusted R² formula

$$R^2_{adj} = 1 - \left[\frac{(1 - R^2)(n - 1)}{n - p - 1}\right]$$

The variance explained by the model, penalized for every extra predictor.

Every symbol:

SymbolNameMeaning
\(R^2\)R-squaredThe standard coefficient of determination - the proportion of variance the model explains
\(n\)samplesThe number of observations (rows) in the dataset
\(p\)predictorsThe number of independent variables (features) in the model
\(1\)constantAdjusts for degrees of freedom in the sample statistics

Reading the fraction: as \(p\) grows, the denominator \(n - p - 1\) shrinks, which inflates the penalty term and drags Adjusted R² down. A new feature only pays off if it raises \(R^2\) enough to overcome that shrinking denominator.

Adjusted R² is always ≤ R². The gap between them grows with the number of features - a big gap warns that some of your features may be dead weight.

Adjusted R² in code

Way 1 - write the formula ourselves. X.shape hands us (n, p) in one line - here the training set has 8 rows and 4 features.

def adjusted_r2(y_train, y_pred, X):
    r2 = r2_score(y_train, y_pred)
    n, p = X.shape          # of train: 8 rows, 4 features
    return 1 - (1 - r2) * (n - 1) / (n - p - 1)

print(adjusted_r2(Y_train, y_pred_train, X_train))
0.9795210017107552

Way 2 - use the dmba library. Same result, one import. Note it takes the fitted model (it reads the feature count from it).

# !pip install dmba
from dmba import adjusted_r2_score

adj_r2 = adjusted_r2_score(Y_train, y_pred_train, model)
print('adjusted R2 score', adj_r2)
adjusted R2 score 0.9795210017107552
$$R^2_{adj} = 1 - \frac{(1 - 0.99122)(8 - 1)}{8 - 4 - 1} = 1 - \frac{0.00878 \times 7}{3} = \boxed{0.97952}$$
Both ways give the identical 0.97952 - proof that dmba's function is just the formula. It sits a little below the raw training R² of 0.99122, the penalty for using 4 features on only 8 rows.

When a straight line simply fails

A straight line misses the real pattern

An R² of 0.285 is a failing grade - not because sklearn is broken, but because we forced a straight line through data that curves. No line can be low in the middle and high on both ends.
The cure is polynomial regression - letting the model use x², x³, … so the fitted shape can bend. That is the whole subject of the new Polynomial Regression deck.

Degrees of a polynomial

A polynomial is an equation where the variable x is raised to whole-number powers. The degree is the highest power that appears - and it decides how many times the curve can bend.

NameHighest powerShapeBends
Linear\(x^1\)A straight line0
Quadratic\(x^2\)A parabola (single U or ∩)1
Cubic\(x^3\)An S-shaped curve2
Quartic\(x^4\)A W / M-shaped curve3
$$y = a_n x^n + \dots + a_2 x^2 + a_1 x + a_0$$

The general polynomial of degree \(n\). Set every coefficient above \(a_1\) to zero and it collapses back into a straight line.

The naming is Latin: quadratic comes from quadratus = "square" (because \(x^2\) is x-squared), and cubic from cubus = "cube" (\(x^3\) is x-cubed). A quartic is the one whose highest power is genuinely 4.

Plotting a quadratic

Before fitting one, let's just draw a quadratic so its shape is familiar. Pick coefficients, sweep x with np.linspace, and plot.

import numpy as np
import matplotlib.pyplot as plt

# Coefficients
a, b, c = 1.0, -3.0, 2.0        # y = x² - 3x + 2
x = np.linspace(-10, 10, 400)
y = a * x**2 + b * x + c

plt.figure()
plt.plot(x, y)
plt.axhline(0, linewidth=1)
plt.axvline(0, linewidth=1)
plt.xlabel('x')
plt.ylabel('y')
plt.title('y = x² - 3x + 2')
plt.grid(True, which='both', linestyle='--', alpha=0.3)
plt.show()
$$y = x^2 - 3x + 2 \qquad (a = 1,\; b = -3,\; c = 2)$$

A parabola is a single bend

The single bend is the whole point. Because the highest power is x², the curve turns exactly once - a valley here. That one bend is what lets a quadratic follow the U-shaped running-times data that defeated the straight line.
np.linspace(-10, 10, 400) makes 400 evenly-spaced x-values so the plotted curve looks smooth; a * x**2 + b * x + c is vectorised - it computes all 400 y-values at once.
