Logistic Regression 01 / 11 · The Function
The sigmoid
Any number in the world, squeezed into 0 … 1
sigma = 1 / (1 + np.exp(-z)) z z — the scoreThe linear part, \(\beta_0 + \beta_1 x\). Any real number from −∞ to +∞. → a probability in [0, 1]

A straight line can output 1.7 or -0.4, and there is no such thing as a probability of 170%. The sigmoid fixes that: feed it any real number and it returns something strictly between 0 and 1.

The e inside is Euler's number, ≈ 2.71828 — a constant like π. If it is new to you, read Appendix A1 — Euler's number e first, and Appendix A2 explains where the name "logistic regression" comes from.

$$\sigma(z) = \frac{1}{1 + e^{-z}}$$

In a model, z is never a bare number — it is the line \(z = \beta_0 + \beta_1 x\). Substitute it and you get the formula the code below actually computes:

$$\sigma(x) = \frac{1}{1 + e^{-(\beta_0 + \beta_1 x)}}$$

Line up the two forms and the code stops looking mysterious — np.exp(-(b0 + b1*x)) is \(e^{-(\beta_0 + \beta_1 x)}\):

python — draw the S
import numpy as np

b0, b1 = -4.0, 1.0
x = np.linspace(-10, 10, 500)

denom   = 1 + np.exp( -(b0 + b1 * x) )     # e is here
sigmoid = 1 / denom

plt.plot(x, sigmoid, linewidth=3)

Logistic Regression 02 / 11 · The Model
One feature → n features
Keep the line inside, wrap the sigmoid outside
z = β₀ + β₁x₁ + … + βₙxₙ β₀ β₀ — interceptThe bias. Shifts the whole S left or right. In sklearn: model.intercept_. βⱼ βⱼ — one weight per featureControls how strongly feature j pushes toward class 1. In sklearn: model.coef_. → p̂ = σ(z)

With one feature the model is the line you already know, wrapped in the sigmoid:

$$P(y = 1 \mid x) = \frac{1}{1 + e^{-(\beta_0 + \beta_1 x)}}$$

Adding features changes nothing about the sigmoid — only the inside grows, one weight per column, exactly like multiple linear regression:

$$P(y = 1 \mid X) = \frac{1}{1 + e^{-(\beta_0 + \beta_1 x_1 + \beta_2 x_2 + \dots + \beta_n x_n)}}$$

It reads more cleanly in two steps — a score \(z\), then the squash:

$$z = \beta_0 + \sum_{j=1}^{n}\beta_j x_j = \beta_0 + \boldsymbol{\beta}^{T}\mathbf{x} \qquad\Longrightarrow\qquad \hat{p} = \sigma(z)$$
SymbolNameMeaning
xⱼfeatureOne measured input column (age, income, hours…)
β₀intercept / biasShifts the S — model.intercept_
βⱼcoefficient / weightHow steeply feature j pushes toward class 1 — model.coef_
zlogit / scoreThe linear part, any real number
p̂probabilityAlways in [0, 1] — model.predict_proba
📈 β₁ > 0 — the S rises: bigger x → higher chance of class 1.
📉 β₁ < 0 — the S falls: bigger x → lower chance of class 1.
💡 Why it is a "linear classifier": z is always a straight-line combination of the features. One feature → the boundary is a point; two features → a line on the plane; n features → a flat hyperplane. The S-shape lives in the output, never in the boundary.
🧠 Scale your columns. If one feature runs 0–60 and another 0–2000, the raw weights are not comparable and the solver works harder. StandardScaler before fit is standard practice once you leave toy data.
Logistic Regression 03 / 11 · The Simple Idea
Decision boundary
The probability required before the answer becomes True
probability below threshold → False probability at/above threshold → True → compare p with a percentage

First the sigmoid calculates a probability. Then we compare that probability with a chosen threshold. If the threshold is 70%, a probability of 69% returns False, while 70% or 85% returns True. The threshold is a percentage—it is not the input \(x\).

Input xProbability from sigmoidCompare with 70%Answer
2511.9%11.9% < 70%False
5050.0%50.0% < 70%False
6576.9%76.9% ≥ 70%True
8594.3%94.3% ≥ 70%True
🚪 Think of 70% as the door. The sigmoid must produce at least 70% before the prediction may walk through and become True. Moving the threshold changes the decision rule, not the sigmoid curve.
python — probability first, threshold second
def probability(x):
    z = -4 + 0.08 * x
    return 1 / (1 + np.exp(-z))

def is_true(x, threshold=0.70):
    p = probability(x)
    return p >= threshold

print(probability(50))       # 0.500 → 50.0%
print(is_true(50, 0.70))     # False
print(probability(65))       # 0.769 → 76.9%
print(is_true(65, 0.70))     # True

Appendix · A5 / A6 · The Mathematics
Decision boundary mathematics
The full sigmoid, score, and threshold derivation
ŷ = 1 if p̂ ≥ 0.5 else 0 threshold thresholdThe probability at which you switch your answer from 0 to 1. Default 0.5 — but it is a business choice, not a mathematical one. → x = −β₀ / β₁

Eventually somebody needs a yes or a no. We get it by comparing the probability to a threshold, by default 0.5:

$$\hat{y} = \begin{cases} 1 & \hat{p} \ge 0.5 \\[4pt] 0 & \hat{p} < 0.5\end{cases}$$

Why does the default boundary use \(z=0\)? The default rule changes from class 0 to class 1 when the predicted probability reaches \(0.5\). Now substitute \(z=0\) into the sigmoid:

$$\begin{aligned} \sigma(z)&=\frac{1}{1+e^{-z}}\\ \sigma(0)&=\frac{1}{1+e^{-0}}\\ &=\frac{1}{1+e^0}\\ &=\frac{1}{1+1}\\ &=\frac{1}{2}=0.5 \end{aligned}$$

So \(z=0\) is not chosen randomly. It is the raw score that the sigmoid converts to exactly \(0.5\). Because the sigmoid always increases:

Raw scoreProbabilityDefault prediction
\(z<0\)\(\hat p<0.5\)Class 0
\(z=0\)\(\hat p=0.5\)The switching point
\(z>0\)\(\hat p>0.5\)Class 1
🚪 The decision boundary is the switching point. On one side the model predicts class 0; on the other side it predicts class 1. With the default probability threshold \(0.5\), that switch occurs at \(z=0\).

The score is \(z=\beta_0+\beta_1x\). Therefore, to find the input \(x\) located exactly on the boundary, set its score to 0 and solve:

$$\beta_0 + \beta_1 x = 0 \quad\Longrightarrow\quad x = -\frac{\beta_0}{\beta_1}$$

Want a different cut-off, say 70%? Invert the logit and solve for x:

$$x_{(p)} = \frac{\ln\!\left(\frac{p}{1-p}\right) - \beta_0}{\beta_1}$$
python — the x behind any probability
def x_for_probability(p, b0, b1):
    """The x at which the model predicts probability p."""
    return (np.log(p / (1 - p)) - b0) / b1

print(x_for_probability(0.50, b0, b1))   # 25.36  ← the boundary
print(x_for_probability(0.70, b0, b1))   # 42.90

Worked example — at what age is the risk exactly 70%? Using the fitted battery model \(\beta_0 = -1.2249\), \(\beta_1 = 0.0483\), work backwards through the sigmoid in four steps.

StepWhat we doResult
1 · the targetWe want \(p = 0.70\)p = 0.70
2 · to odds\(\dfrac{p}{1-p} = \dfrac{0.7}{0.3}\)2.3333 ("7 to 3")
3 · to log-odds\(z = \ln(2.3333)\)0.8473
4 · solve the line\(\beta_0 + \beta_1 x = 0.8473\)x = 42.90 months

Step 4 in full — isolate x and put the numbers in:

$$x = \frac{\ln\!\left(\frac{0.7}{0.3}\right) - \beta_0}{\beta_1} = \frac{0.8473 - (-1.2249)}{0.0483}$$
$$x = \frac{2.0722}{0.0483} = 42.90 \text{ months}$$

Check it forwards — feed 42.90 back into the sigmoid and 0.70 must come out:

$$z = -1.2249 + 0.0483 \times 42.90 = 0.8473$$
$$\sigma(0.8473) = \frac{1}{1 + e^{-0.8473}} = \frac{1}{1 + 0.4286} = \frac{1}{1.4286} = 0.70 \;\checkmark$$
python — the same example, both directions
# backwards: which age gives 70%?
x70 = (np.log(0.7 / 0.3) - b0) / b1
print(f'70% at {x70:.2f} months')          # 70% at 42.90 months

# forwards: check that age really gives 70%
z = b0 + b1 * x70
print(f'z        = {z:.4f}')                # z        = 0.8473
print(f'sigma(z) = {1 / (1 + np.exp(-z)):.4f}')  # sigma(z) = 0.7000

# and sklearn agrees
print(model.predict_proba([[x70]]))        # [[0.3 0.7]]
💡 Why 2.3333 and not 0.7? The line lives on the log-odds scale, not the probability scale. You cannot plug 0.70 straight into \(\beta_0 + \beta_1 x\) — you must convert probability → odds → log-odds first. That conversion is exactly what steps 2 and 3 do, and it is why the odds appendix matters.

Three ways to ask the same question about a 33-month battery — by hand, as a class, and as probabilities:

Logistic Regression 06 / 11 · Training Algorithms
Solvers
Six routes to the same goal — finding weights that make better predictions
solver='lbfgs' method used during model.fit → fitted intercept_ and coef_

When you call model.fit(X, y), sklearn must repeatedly adjust the model's weights until its predictions are as good as possible. A solver is simply the method it uses to find those weights. Think of six people trying different routes to reach the bottom of the same valley.

✅ Beginner rule: use lbfgs. You usually do not need to select a solver yourself. Read the rest of this page so you recognize the names and know when a different choice becomes useful.

First: what are L1, L2, and Elastic-Net?

🎓 The prediction task is: will this student pass the exam—YES or NO?

The model receives three columns about each student:
1. Study hours — probably useful.
2. Attendance — probably useful.
3. Uses a blue notebook — probably unrelated to passing.

Suppose the training class is tiny, and by coincidence every student with a blue notebook passed. The model may incorrectly learn, “Blue notebooks cause success!” L1 and L2 help prevent the model from trusting accidental patterns like this too strongly.

What is a weight?

A weight is the number multiplied by a column. A larger positive weight gives that column more influence on the PASS score:

$$\text{PASS score} = (\text{study hours}\times 2) + (\text{attendance}\times 1.5) + (\text{blue notebook}\times 3)$$

For the blue-notebook column, YES is stored as 1 and NO as 0. With weight 3, a blue notebook adds \(1\times3=3\) points—even though notebook color should not decide whether someone passes.

Training ruleStudy-hours weightAttendance weightBlue-notebook weightWhat happened?
None+8+6+5The model became too confident and trusted notebook color
L2+2.0+1.5+0.3All three weights became smaller; notebook color has little effect
L1+2.3+1.70Notebook color now adds exactly nothing to the score
Elastic-Net+2.0+1.50Useful weights became smaller and notebook color became zero

These numbers are a made-up teaching example. Real weights are learned from your own data.

L2 = make all weights smaller
Study hours, attendance, and notebook color all remain in the calculation, but none can receive an enormous weight. Notebook color might still add a tiny amount.
L1 = allow some weights to become exactly 0
If the notebook weight becomes 0, then blue_notebook × 0 = 0. Blue and non-blue notebooks produce no difference in the prediction. That is what “ignore the column” means.
Elastic-Net = use both rules
It can make the notebook weight exactly 0 like L1, while also keeping the study and attendance weights smaller like L2.
None = do not limit the weights
The model may learn very large weights from coincidences in the training students and then make poor predictions for new students.

When should we make a weight smaller, and when should we make it zero?

Choose L2 when you want to KEEP the columns.

Example: your model uses study hours, attendance, and previous grade. All three clearly relate to passing. You want the model to use all three—but not become too confident about any one of them. L2 keeps every column and makes the weights more reasonable.

Simple meaning: “Keep every employee, but do not let anyone become the boss of everything.”
Choose L1 when you WANT the model to REMOVE some columns.

Example: an email model has 10,000 word columns: “meeting,” “prize,” “banana,” “invoice,” and thousands more. Many words may be useless. L1 can give useless words a weight of 0, so they no longer affect the prediction.

Simple meaning: “Keep the useful employees; send unnecessary employees home.”
Choose Elastic-Net when you want BOTH behaviors.

Example: a survey has 500 questions. You want the model to remove questions that add no value, but you also want the remaining question weights kept under control. Elastic-Net can make some weights zero and make the remaining weights smaller.

Simple meaning: “Send unnecessary employees home, then stop the remaining employees from taking over.”
🤖 You do not manually choose which column becomes zero. You choose L1, then sklearn studies the training data and decides which weights to reduce to zero. Always test the finished model on new data: with too little data, L1 can accidentally remove a useful column.
What do you want?Choose
Keep all columns, but reduce overconfidenceL2

You are a beginner or are unsureL2 — the default
✅ What should a beginner choose? Do nothing. LogisticRegression() already uses L2. Use L1 only when you deliberately want the model to switch some columns off. Elastic-Net is for later, when you understand why you need both behaviors.

C only controls how strongly sklearn applies this rule. For now, leave it at its normal value: C=1.0.

lbfgs — start here
It makes careful, reliable adjustments without using too much memory. It works well for ordinary small and medium datasets and is sklearn's default.
liblinear — small binary problems
It works well when there are only two classes and not many rows. It is also one of two choices that can make weights exactly zero with L1.
newton-cg — careful but costly
It studies the shape of the error before choosing each move. This can reach a precise answer, but each move takes more computation.
newton-cholesky — many rows, few columns
It examines all weight relationships at once. This is fast when columns are few, but memory use rises very quickly as columns and classes increase.
sag — learn from small batches
Instead of processing every row for every move, it updates using rows gradually. This can be fast on huge datasets when columns are scaled similarly.
saga — SAG with more options
It is designed for large data and is the only solver supporting the L1/L2 mixture. It can also ignore unhelpful features by making weights zero.

Quick choice guide

Scaling means converting columns with different units to similar numerical ranges. For example, age might be 18–90 while yearly income is 20,000–500,000. StandardScaler prevents the large income numbers from dominating the solver's steps.

python — practical solver choices
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

# dependable default
default_model = LogisticRegression(solver='lbfgs', max_iter=1000)

# large data: scaling is essential for sag and saga
large_model = make_pipeline(
    StandardScaler(),
    LogisticRegression(solver='saga', penalty='l2', max_iter=2000)
)

# L1: allow the model to ignore columns by setting their weights to zero
sparse_model = make_pipeline(
    StandardScaler(),
    LogisticRegression(solver='saga', penalty='l1', C=0.5, max_iter=2000)
)

# Elastic-Net: combine zeroing some weights with gently shrinking the rest
elastic_model = LogisticRegression(
    solver='saga', penalty='elasticnet',
    l1_ratio=0.5, max_iter=2000  # 50% L1 + 50% L2
)
⚠️ If sklearn says the model did not converge: it stopped before finding a stable answer. First scale the columns and increase max_iter, which means “allow more adjustment rounds.” Only then consider changing the solver.

Multinomial & softmax
The sigmoid's big brother
softmax(z)_c = e^{z_c} / Σ e^{z_j} OvR vs multinomial → k probabilities summing to 1

Binary = exactly two labels. Multinomial = three or more mutually exclusive labels — a plant is wilted or green or flowering, never two at once.

BinaryMultinomial

predict_proba2 columnsone column per class
Squashing functionsigmoidsoftmax

sklearn can reach a multi-class answer two different ways:

🔁 One-vs-Rest (OvR) — train k separate binary models ("wilted vs everything else", …) and keep the loudest. Simple, but the k probabilities do not naturally sum to 1. liblinear can only do this.
🎯 Multinomial (softmax) — one model with k score-lines trained together, then one softmax. Better calibrated, and what the default lbfgs solver uses automatically for 3+ classes.

With k classes there is one z per class, each with its own row of weights:

$$z_c = \beta_{0,c} + \beta_{1,c}x_1 + \dots + \beta_{n,c}x_n \qquad c = 1 \dots k$$

Softmax turns those raw scores into probabilities: exponentiate each (making it positive), divide by the total (making them sum to 1).

$$P(y = c \mid \mathbf{x}) = \frac{e^{z_c}}{\displaystyle\sum_{j=1}^{k} e^{z_j}}$$

For k = 2, softmax collapses back into the plain sigmoid — the binary case is not a different model:

$$\frac{e^{z_1}}{e^{z_0} + e^{z_1}} = \frac{1}{1 + e^{-(z_1 - z_0)}} = \sigma(z_1 - z_0)$$
🧠 Not multi-label. Multinomial = pick exactly one of k. Multi-label = a photo can be "cat" and "outdoors" and "night" at once — a different problem, solved with k independent binary models.
⚠️ The cost generalises too: binary log loss becomes categorical cross-entropy, \(J = -\frac{1}{m}\sum_i\sum_c y_{i,c}\ln(\hat{p}_{i,c})\), where \(y_{i,c}\) is 1 only for the true class of row i.

Logistic Regression 09 / 11 · The Metrics
Precision & recall
Four numbers, four metrics, one famous trap
classification_report(y_true, y_pred) accuracy can lie → precision · recall · F1
🎉 The Dog Party Problem: ten guests enter a dogs-only party: 6 dogs 🐶 and 4 cats 🐱 wearing fake moustaches. A robot must shout “CAT!” whenever it sees a cat.
REAL GUESTS: 🐱 🐱 🐱 🐱 🐶 🐶 🐶 🐶 🐶 🐶 ROBOT SHOUTS CAT: 🐱 🐱 🐱 🐱 🐶 ↑ one innocent dog!

The robot caught all 4 cats, but falsely accused 1 dog. The same result can look excellent or annoying depending on the question. That is why one metric is not enough.

📊 Accuracy: “How many total guesses were correct?”
The robot handled 10 guests and was correct about 9. Accuracy = 9 ÷ 10 = 90%.

Use it when both mistakes matter about equally and the groups are not extremely uneven.
🚨 Precision: “When the robot shouted CAT, how often was it right?”
It shouted CAT 5 times; only 4 were cats. Precision = 4 ÷ 5 = 80%.

Care about precision when false alarms are painful. Imagine airport security opening five suitcases and finding a sandwich in only one—everyone is late and grumpy.
🕵️ Recall: “Of all the cats that entered, how many did it find?”
There were 4 real cats and it found all 4. Recall = 4 ÷ 4 = 100%.

Care about recall when missing one is dangerous: disease screening, smoke alarms, or fraud detection. A false alarm may be better than missing the real danger.
⚖️ F1: “Are precision and recall both behaving?”
Shouting CAT at everybody gives perfect recall but terrible precision. Shouting only once may give perfect precision but miss three cats. F1 becomes high only when both scores are reasonably high.
🔢 Support is not a grade. It is simply the number of real examples. Cat support is 4; dog support is 6. A perfect score based on 2 examples is less convincing than one based on 20,000.

$$\text{Accuracy} = \frac{\text{all correct guesses}}{\text{all guesses}}$$
$$\text{Precision} = \frac{\text{correct alarms}}{\text{all alarms}}$$
$$\text{Recall} = \frac{\text{real dangers found}}{\text{all real dangers}}$$

🌼 What about three classes? Ask the same questions one class at a time. For “flowered,” pretend flowered is CAT and everything else is NOT CAT. Then repeat for “green” and “wilted.” That is why classification_report prints one row for each class.
⚠️ The accuracy trap: imagine 100 suitcases and only 1 contains a forbidden banana 🍌. A lazy robot says “SAFE” to every suitcase. It gets 99 answers right, so accuracy is 99%—but it misses the only banana! Its recall for bananas is 0%. A big accuracy number is not automatically a useful model.
🧠 One final fairness rule: test the model on rows it did not study. Testing on its training rows is like giving a student the same exam they memorized. Use train_test_split, then calculate the scores from y_test.

Appendix · A2 / A6 · The Name
Why "logistic regression"?
Two confusing words, both with a good reason
courbe logistique — Verhulst, 1845 logit — Berkson, 1944 → a regression on the log-odds

Start with the simple answer: logistic regression produces a probability, such as “there is a 70% chance this email is spam.” We can then turn that probability into a class such as spam or not spam.

📈 Why “logistic”? The method uses the logistic function, the S-shaped curve also called the sigmoid. It turns any number into a value between 0 and 1, so it is useful for probabilities.
$$p = \frac{1}{1 + e^{-z}}$$

Read it in words: first, the model looks at the input information and combines it into one number called \(z\)
For example, when predicting whether a student will pass, the model may combine study hours, attendance, and previous grades into this one number. This number \(z\) is called the raw score. It summarizes whether the information points more toward class 0 or class 1, but it is not a probability yet. The sigmoid formula then squeezes \(z\) into a probability \(p\). A very negative \(z\) gives a probability near 0, \(z=0\) gives 0.5, and a very positive \(z\) gives a probability near 1.

📐 Why “regression”? Before making the S-shaped probability, the model calculates a straight-line score, just like linear regression:
$$z = \beta_0 + \beta_1 x$$
🔢 What is the score \(z\)? It is the model’s first calculation: one number that summarizes the evidence from the input. It is sometimes called the raw score or linear score. It is not a probability yet, so it may be any number—negative, zero, or positive.

For example, suppose \(z=-2+0.5x\). If \(x=6\), then \(z=-2+0.5(6)=1\). Now put \(z=1\) into the sigmoid formula:

$$p=\frac{1}{1+e^{-z}} =\frac{1}{1+e^{-1}} \approx\frac{1}{1+0.368} =\frac{1}{1.368} \approx0.731$$

So the conversion is: \(z=1\) → \(e^{-1}\approx0.368\) → \(1+0.368=1.368\) → \(1\div1.368\approx0.731\). Therefore, the raw score 1 becomes a probability of about 73.1%.

Score \(z\)What it suggestsProbability after sigmoid
negativeMore evidence for class 0Below 0.5
0The model is exactly in the middleExactly 0.5
positiveMore evidence for class 1Above 0.5

Here \(x\) is the input, \(\beta_1\) controls how strongly the input changes the score, and \(\beta_0\) is the starting score when \(x=0\). Then the sigmoid turns \(z\) into \(p\). Finally, we may predict class 1 when \(p \ge 0.5\): input → raw score \(z\) → probability \(p\) → class.

Appendix · A1 / A6 · The Constant
Euler's number e
2.718281828… — a constant, exactly like π
math.e · np.exp(z) e e — Euler's numberA fixed constant ≈ 2.71828, pronounced "Oiler's number". Not a variable, not something the model learns. → always positive

Start here: \(e\) is simply a fixed number, approximately 2.718. It is pronounced “Euler” like Oiler. It is not a variable, and the model does not learn it. Just as \(\pi\) naturally appears with circles, \(e\) naturally appears when something grows or shrinks continuously.

$$e \approx 2.718 \qquad e^2 \approx 7.389 \qquad e^0 = 1 \qquad e^{-2}=\frac{1}{e^2}\approx0.135$$

What does the small raised number mean? It is an exponent. \(e^2\) means \(e\times e\). A negative exponent means “take the reciprocal,” so \(e^{-2}=1/e^2\). In Python, np.exp(z) means \(e^z\).

🪜 Optional deeper idea: where does 2.718… come from? Imagine starting with $1 and earning 100% interest. If interest is added once, you finish with $2. If it is divided into more and more tiny payments during the year, the result gets closer and closer to $2.718.
$$e = \lim_{n \to \infty}\left(1 + \frac{1}{n}\right)^{n} \approx 2.718281828459045$$

Read the limit formula in words: \(n\) is the number of compounding steps. “\(n\to\infty\)” means try larger and larger values of \(n\)—10, 1,000, one million, and so on. A limit is the value the results approach. We never need to reach infinity; we watch the numbers settle closer and closer to \(2.71828\).

Appendix · A4 / A6 · The Interpretation
Odds & log-odds
The straight line hiding inside the S
odds = p / (1 − p) logit = ln(odds) → eᵝ = odds multiplier

Probability and odds are two ways to describe the same chance. Probability asks, “Out of all cases, how many succeed?” Odds ask, “How many successes are there for each failure?”

🎲 Example: if 8 out of 10 students pass, the probability of passing is \(8/10=0.8\). There are 8 passes and 2 failures, so the odds are \(8/2=4\), spoken as “4 to 1.”
$$\text{odds}=\frac{\text{probability of success}}{\text{probability of failure}} =\frac{p}{1-p}$$

Why is the bottom \(1-p\)? The two possible outcomes have probabilities that add to 1. If \(p=0.8\), failure has probability \(1-0.8=0.2\), so the odds are \(0.8/0.2=4\).

What are log-odds? Log-odds are simply the result of taking the natural logarithm of the odds. It is a new way to write the same probability—not a new prediction and not a different kind of chance.

$$\text{log-odds}=\ln(\text{odds})=\ln\!\left(\frac{p}{1-p}\right)$$
🧮 One complete example: suppose \(p=0.8\). First calculate the odds: \(0.8/(1-0.8)=0.8/0.2=4\). Then take the natural logarithm: \(\ln(4)\approx1.386\). Therefore, probability 0.8, odds 4, and log-odds 1.386 all describe the same chance.
ProbabilityOddsLog-oddsSimple meaning
0.200.25−1.386Class 0 is more likely

0.804+1.386Class 1 is more likely

Why do we use log-odds? A straight-line calculation such as \(\beta_0+\beta_1x\) may produce any number: \(-5\), \(0\), \(8\), and so on. A probability cannot do that; it must stay between 0 and 1. Therefore, we cannot directly say that an unrestricted straight line is a probability.

🌉 Log-odds provide the bridge. Probability is restricted to 0–1, but log-odds can be any number from very negative to very positive. That means the model can use a simple straight line for the log-odds, and the sigmoid can safely convert that line back into a probability.

The direction is easy to remember: a negative log-odds value means \(p<0.5\); log-odds 0 means \(p=0.5\); and a positive log-odds value means \(p>0.5\).

$$\begin{aligned} \text{inputs} &\longrightarrow \text{straight-line score }z=\text{log-odds}\\ &\longrightarrow \text{sigmoid}\longrightarrow \text{probability }p \end{aligned}$$

What does \(\ln\) do here? Odds range from just above 0 to extremely large positive numbers. The logarithm rearranges that range around 0: odds below 1 become negative, odds of 1 become 0, and odds above 1 become positive. This produces the unrestricted scale needed by the straight-line score.

So logistic regression represents the log-odds with a straight line:

$$\underbrace{\ln\!\left(\frac{p}{1-p}\right)}_{\text{log-odds}} =\underbrace{\beta_0+\beta_1x}_{\text{straight-line score }z}$$
🧠 Advanced connection: the raw score \(z\) and the log-odds are the same number. $$\ln\!\left(\frac{p}{1-p}\right)=z=\beta_0+\beta_1x$$

The history, if you are curious: Pierre François Verhulst used an S-shaped “logistic curve” in 1845 to describe population growth that slows near a maximum. Joseph Berkson later formed the word logit from “logistic unit.” Here, a logistic unit means one value on the logistic model’s transformed scale—the log-odds scale. It is not a physical unit such as a meter or a kilogram. For example, probability \(p=0.5\) has logit 0, while \(p\approx0.731\) has logit 1. The word logit was created by joining logistic and unit.

📊 How to read the graph above: the horizontal x-axis is the probability \(p\), from almost 0 on the left to almost 1 on the right. The vertical y-axis is the corresponding log-odds. It is not the true label \(y\).

The curve always goes upward: a larger probability means larger odds, so it also means larger log-odds. At \(p=0.5\), the log-odds are 0. Moving left toward \(p=0\) makes the log-odds very negative; moving right toward \(p=1\) makes them very positive.
Why is the graph so low near \(p=0\)? The graph actually begins at \(p=0.01\), not at exactly 0. At \(p=0.01\): $$\text{odds}=\frac{0.01}{0.99}\approx0.0101 \qquad \text{log-odds}=\ln(0.0101)\approx-4.60$$ The probability is extremely small, so the odds are also extremely small. The logarithm writes that strong evidence for class 0 as a large negative number. As \(p\) gets closer to 0, the log-odds keep falling toward \(-\infty\). At exactly \(p=0\), \(\ln(0)\) is not a finite number.
🔁 Why do we call \(z\) a score? First, the model multiplies each input by its learned coefficient and adds the results: $$z=\beta_0+\beta_1x_1+\beta_2x_2+\cdots$$ This final weighted total is called the raw score. The word “score” is only a name for the model’s number before it becomes a probability. A positive \(z\) is evidence toward class 1, a negative \(z\) is evidence toward class 0, and \(z=0\) is the middle.

Where does \(z\) appear in the sigmoid? The exponent of \(e\) is actually \(-z\), not \(z\): $$z\;\longrightarrow\;p=\frac{1}{1+e^{-z}}$$ The minus sign is essential. When \(z\) becomes larger, \(-z\) becomes smaller, \(e^{-z}\) becomes smaller, and the final probability becomes larger: $$\begin{aligned} z=-1&:\quad p=\frac{1}{1+e^{1}}\approx0.269\\ z=0&:\quad p=\frac{1}{1+e^{0}}=0.500\\ z=1&:\quad p=\frac{1}{1+e^{-1}}\approx0.731 \end{aligned}$$ So \(z\) is the score produced by the linear model; \(-z\) is the exponent used by this particular way of writing the sigmoid.

Log-odds perform the reverse conversion: $$p\;\longrightarrow\;z=\ln\!\left(\frac{p}{1-p}\right)$$

Why is the connection between \(p\) and \(z\) useful? The model performs its simple straight-line calculation on the \(z\) scale, but people usually want a probability on the \(p\) scale. The graph connects those two views. It lets us see what a raw model score means as a probability—for example, \(z=0\) means \(p=0.5\), while \(z\approx1.386\) means \(p=0.8\).

What does this graph teach us? It is a conversion map between the internal score \(z\) and the probability \(p\). It does not show accuracy, loss, time, or the true label. It shows that every probability corresponds to one score:

✅ Why is the loss function needed? It is how the model learns. The loss tells the model whether its current coefficients produce good or bad predictions. The training algorithm repeatedly changes the coefficients to make the loss smaller.

Does the loss find the correct \(z\)? Indirectly, yes—but the model does not learn a separate \(z\) by itself. It learns the coefficients \(\beta_0,\beta_1,\ldots\). For each input row, those coefficients produce its score \(z\). Changing the coefficients changes \(z\), which changes the probability, which changes the loss.

$$\begin{aligned} \text{coefficients }\beta &\longrightarrow \text{score }z\\ &\longrightarrow \text{probability }\hat p\\ &\longrightarrow \text{loss}\\ &\longrightarrow \text{adjust the coefficients} \end{aligned}$$

The training loop, step by step:

StepWhat happens
1Start with temporary values for the coefficients \(\beta\).
2Use them to calculate a score \(z=\beta_0+\beta_1x\) for every training row.
3Use the sigmoid to convert each \(z\) into a predicted probability \(\hat p\).
4Compare each prediction with the true answer and calculate the loss.
5Adjust the coefficients in a direction that lowers the loss, then repeat.

When does training stop? It stops when further coefficient changes no longer reduce the loss very much, or when the solver reaches its allowed number of steps. The coefficients are what the model stores. Later, it uses those coefficients to calculate the appropriate \(z\) for any input it receives.

What exactly is loss? It is a number that measures how wrong a probability prediction is. Small loss is good; large loss is bad. During prediction on new data, the model only calculates \(z\), probability, and class—the true answer is unknown, so loss is mainly used during training and evaluation.

🎯 Suppose the true answer is 1. Predicting 0.9 is good, predicting 0.5 is unsure, and predicting 0.01 is confidently wrong. Log loss gives them a tiny, medium, and very large penalty.

For one example there are only two cases. The symbol \(\hat p\), pronounced “p-hat,” means the model’s predicted probability for class 1:

If the truth is \(y=1\):
loss \(=-\ln(\hat p)\)
The loss approaches 0 when \(\hat p\) approaches 1.
If the truth is \(y=0\):
loss \(=-\ln(1-\hat p)\)
The loss approaches 0 when \(\hat p\) approaches 0.

Why a logarithm? It gives a small penalty for a correct, confident prediction and a rapidly growing penalty for a wrong, confident prediction.

What is \(J\)? Each training row receives its own loss. \(J\) is the average loss across all training rows. It gives the model one overall number describing how bad its current predictions are.

📉 The direction is important: when predicted probabilities move toward the correct answers, their losses decrease, so \(J\) decreases. Training tries to make \(J\) as small as possible. The theoretical ideal \(J=0\) is approached when every prediction approaches the correct answer with 100% confidence.

Now combine both label cases. The following formula selects the correct loss rule for every row, adds all row losses, and divides by the number of rows to produce \(J\):

$$J = -\frac{1}{m}\sum_{i=1}^{m}\Big[\, y_i \ln(\hat{p}_i) + (1 - y_i)\ln(1 - \hat{p}_i)\,\Big]$$

Symbol guide: \(J\) is the average loss; \(m\) is the number of training rows; \(\sum\) means “add”; \(i\) identifies one row; \(y_i\) is its true label (0 or 1); and \(\hat p_i\) is its predicted probability. If \(y_i=1\), the second term becomes zero. If \(y_i=0\), the first term becomes zero.

🧮 Example showing \(J\) decreasing: imagine two rows whose true labels are \([1,0]\).

Predictions \([0.60,0.40]\) give \(J=[-\ln(0.60)-\ln(1-0.40)]/2\approx0.511\).

Better predictions \([0.90,0.10]\) move toward the true labels and give \(J=[-\ln(0.90)-\ln(1-0.10)]/2\approx0.105\).

The predictions improved, so \(J\) fell from \(0.511\) to \(0.105\). The solver keeps adjusting the coefficients in order to create this downward movement.
