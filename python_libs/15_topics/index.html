TOPICS 01 / 09 · The Problem
Why scaling matters
Whichever column has the biggest numbers wins the argument

Here is the fruit dataset from the lesson. Three features, three completely different units:

fruitcolor (0–255)size (cm)weight (g)
apple200, 50, 2207, 7, 6150, 160, 140
orange240, 250, 2309, 8, 9170, 165, 180
banana30, 40, 2012, 13, 11120, 130, 115
range20 → 250 (span 230)6 → 13 (span 7)115 → 180 (span 65)

KNN, SVM, K-Means and every other distance-based model measure how far apart two rows are with the Euclidean distance:

$$d(a, b) = \sqrt{(a_{\text{color}} - b_{\text{color}})^2 + (a_{\text{size}} - b_{\text{size}})^2 + (a_{\text{weight}} - b_{\text{weight}})^2}$$

Every feature is squared and added into the same sum — so a column that moves in hundreds contributes hundreds of times more than a column that moves in single digits. Size can never matter, no matter how well it separates the fruit. Pick any two fruits and watch who actually owns the distance between them:

Live Demo — where the distance between two fruits actually comes from

banana #6
⚖️ This is not a rounding detail — it decides the prediction. Run the notebook's KNN on the raw fruit table and cross-validation gives 0.89 at k=1. Scale it first and the same model gives 1.00. Nothing changed except the units, and units are not information.
🎯 Which models care? Anything that measures a distance or fits a weight per feature: KNN, SVM, K-Means, PCA, linear and logistic regression with regularisation, neural networks. Anything that only ever asks "is this value bigger than that number?" does not: decision trees, random forests, gradient boosting. That is why decks 14 and 15 could skip scaling entirely and this one cannot.
TOPICS 02 / 09 · Normalization
MinMaxScaler
Squeeze every column into the same [0, 1] box
from sklearn.preprocessing import MinMaxScaler → every column in [0, 1]

Normalization rescales features to a specific range, typically [0, 1]. Take a column, subtract its smallest value so the minimum sits at zero, then divide by its span so the maximum lands on one:

$$X_{normalized} = \frac{X - X_{min}}{X_{max} - X_{min}}$$

Nothing about the shape of the data changes — it is a straight line stretch, so the histogram is identical except for the numbers on the axis. That is the whole point: the relative distances inside a column are preserved, and only the units are thrown away.

import numpy as np
import matplotlib.pyplot as plt
from sklearn.preprocessing import MinMaxScaler

# Generate sample data
np.random.seed(42)
original_data = np.random.normal(loc=50, scale=20, size=100)

# Apply normalization
scaler = MinMaxScaler()
normalized_data = scaler.fit_transform(original_data.reshape(-1, 1)).flatten()

# Visualization
plt.figure(figsize=(12, 6))
plt.subplot(1, 2, 1)
plt.hist(original_data, bins=20, alpha=0.7)
plt.title('Original Data')

plt.subplot(1, 2, 2)
plt.hist(normalized_data, bins=20, alpha=0.7)
plt.title('Normalized Data (Min-Max)')

plt.tight_layout()
plt.show()
📐 The numbers for this sample. The 100 values run from -2.395 to 87.046. So X_min = -2.395, X_max - X_min = 89.441, and every value becomes (X + 2.395) / 89.441. The smallest lands exactly on 0.0, the largest exactly on 1.0, and the mean moves from 47.92 to 0.563 — not to 0.5, because the data is not symmetric inside its own range.
⚠️ Now drag the slider. One value pushed out to 500 and the other 99 are crushed into the bottom fifth of the range. MinMax gives you a guaranteed [0, 1] output, and it pays for that guarantee by handing the entire scale over to the two most extreme rows in the column. Panel 04 is about exactly this.
TOPICS 03 / 09 · Standardization
StandardScaler
Re-centre on zero, then measure everything in standard deviations
from sklearn.preprocessing import StandardScaler → mean 0, std 1

Standardization transforms data to have zero mean and unit variance. Subtract the column's mean, then divide by its standard deviation:

$$X_{standardized} = \frac{X - \mu}{\sigma}$$

where \(\mu\) is the mean of the feature and \(\sigma\) is the standard deviation, computed as:

$$\sigma = \sqrt{\frac{1}{N}\sum_{i=1}^{N}(x_i - \mu)^2}$$

with \(N\) the number of samples, \(x_i\) each individual value and \(\mu\) the mean of the values. The result is called a z-score: it answers "how many standard deviations from average is this?", which is a question you can ask of any column in any unit and get a comparable answer.

import numpy as np
import matplotlib.pyplot as plt
from sklearn.preprocessing import StandardScaler

# Generate sample data
np.random.seed(42)
original_data = np.random.normal(loc=50, scale=20, size=100)

# Apply standardization
scaler = StandardScaler()
standardized_data = scaler.fit_transform(original_data.reshape(-1, 1)).flatten()

plt.figure(figsize=(12, 6))
plt.subplot(1, 2, 1)
plt.hist(original_data, bins=20, alpha=0.7)
plt.title('Original Data')

plt.subplot(1, 2, 2)
plt.hist(standardized_data, bins=20, alpha=0.7)
plt.title('Standardized Data (Z-score)')

plt.tight_layout()
plt.show()
📊 The empirical rule — 68-95-99.7. Once a column is in z-scores you can read it at a glance, because for anything roughly normal: about 68% of values fall within ±1σ, about 95% within ±2σ, and about 99.7% within ±3σ. A z-score beyond ±3 is a genuine rarity — roughly 3 in 1000 — which is why |z| > 3 is the most common outlier rule there is. On the notebook's actual sample the split comes out 65% / 95% / 100%, which is the empirical rule doing its job on 100 draws.
🔢 Two details worth knowing. ① sklearn divides by N, not N−1 — it uses the population standard deviation, so a hand-computed np.std(x, ddof=1) will differ slightly. ② The output is not bounded. Standardizing does not put your data in a box; it only recentres and rescales it, so a value can legitimately come out at −4 or +7.

Which scaler when
One outlier is all it takes to tell them apart

✅ If you only remember one rule. Default to StandardScaler. Reach for MinMaxScaler when something downstream genuinely requires a bounded range, or when you know the column has hard natural limits (a percentage, a pixel, an exam grade out of 100) and no outliers. If your data has real outliers and you need robustness, there is a third option — RobustScaler, which uses the median and the interquartile range instead of μ and σ, so extreme values barely move it at all.
⚠️ Whatever you pick, scale the features and not the target. y stays in its own units for a classifier, and for a regressor you only scale it if you have a specific reason and remember to invert the transform before you report anything.
TOPICS 05 / 09 · The Trap
fit vs transform
The mistake that quietly inflates every score you report
.fit(X)Learn the statistics — min/max, or μ/σ. Changes the scaler, returns nothing useful.
.transform(X)Apply the statistics it already learned. Changes the data.
.fit_transform(X)Both, in one call. Convenient — and the source of the bug.

A scaler is a model. It has parameters, it learns them from data, and — exactly like every other model — it must learn them from the training set only. The test set has to be transformed with the training set's numbers, even when that pushes it outside [0, 1].

Live Demo — a test set that drifts higher than the training set
8

❌ Wrong

  1. fit_transform on the test set gives it its own min and max.
  2. The drift disappears — the test set always looks like a well-behaved [0, 1].
  3. Test statistics have leaked into the preprocessing, so your score is optimistic.
  4. In production there is no "test set" to fit on. The pipeline cannot even run.

✅ Right

  1. fit_transform on train, transform on test.
  2. Test values may land outside [0, 1] — that is information, not a bug.
  3. The score you measure is the score you will get on new data.
  4. One saved scaler works forever on whatever arrives next.
✗ wrong — leaks the test set
scaler = MinMaxScaler()
X_train = scaler.fit_transform(X_train)
X_test  = scaler.fit_transform(X_test)    # ← refits! the train stats are gone

# also wrong — scaling before the split lets test rows
# influence the min/max the training data will use
X_all = scaler.fit_transform(X)
X_train, X_test = train_test_split(X_all, ...)
✓ right — split first, fit on train only
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=42)

scaler = MinMaxScaler()
X_train = scaler.fit_transform(X_train)   # learn AND apply
X_test  = scaler.transform(X_test)        # apply only

print(scaler.data_min_, scaler.data_max_)   # what it learned
🕳️ Why this one is so easy to miss. It never raises an error and it never looks wrong — it just makes your reported accuracy a little too high, every single time. The bug only surfaces in production, when the model does worse than the number you promised. Appendix A2 shows the fix that makes it impossible to get wrong: put the scaler in a Pipeline.
🔁 And it matters even more inside cross-validation. If you scale the whole dataset once and then cross-validate, every fold's "test" rows already helped decide the min and max. The leak happens K times over. Panel 06 explains the folds; A2 shows how to scale inside them.
TOPICS 06 / 09 · The Method
Cross-validation
K folds, K models, every row tested exactly once
cross_val_score(model, X, y, cv=5) → an array of K scores

A single train_test_split gives you one number from one arbitrary slice of your data. With 9 rows and a 30% test set, that number is decided by three fruits — change the random seed and it changes. Cross-validation fixes this by rotating the test set through the whole dataset.

Split the data into K equal folds. Then run K times: hold out fold 1 and train on the rest, hold out fold 2 and train on the rest, and so on. Each run gives a score, and the answer is their mean.

Live Demo — 12 rows, cut K ways. Green is the test fold.

The number of folds decides the train/test split of every round — and this is the table the lesson slide shows:

cvtraintestvalid?

In general each round trains on \(1 - 1/K\) of the data and tests on \(1/K\) of it. So bigger K means more training data per model, more models to fit, and a smaller test fold each time.

🚫 Why cv=1 is not a thing. One fold means the single fold is the test set and there is nothing left to train on. sklearn refuses it outright: ValueError: k-fold cross-validation requires at least one train/test split by setting n_splits=2 or more. If you want a single split, that is train_test_split — a different function for a different job.

📏 Read the spread, not just the mean. cross_val_score hands back an array. scores.mean() is the headline, but scores.std() tells you how much to trust it — folds of [1.0, 1.0, 1.0] and folds of [0.4, 1.0, 1.0] both average well above chance, and only one of them is a model you would ship.
TOPICS 07 / 09 · The Code
CV with KNN
Nine fruits, six values of k, and one honest way to choose

Now both halves of the deck come together. Scale the fruit data with MinMaxScaler, then use cross_val_score to pick k — the number of neighbours — without ever touching a test set.

python — choosing k with cross-validation
import numpy as np
import matplotlib.pyplot as plt

from sklearn.neighbors import KNeighborsClassifier
from sklearn.preprocessing import MinMaxScaler
from sklearn.model_selection import cross_val_score, LeaveOneOut

# Fruit data
colors  = np.array([200, 50, 220, 240, 250, 230, 30, 40, 20])
sizes   = np.array([7, 7, 6, 9, 8, 9, 12, 13, 11])
weights = np.array([150, 160, 140, 170, 165, 180, 120, 130, 115])

fruit_types = np.array([
    'apple', 'apple', 'apple',
    'orange', 'orange', 'orange',
    'banana', 'banana', 'banana'
])

X = np.column_stack((colors, sizes, weights))
y = fruit_types

# Normalize data
scaler = MinMaxScaler()
X_scaled = scaler.fit_transform(X)

# Test different K values
k_range = [1, 2, 3, 4, 5, 6]
cv_scores = []

print("--- Cross-Validation Results ---")

for k in k_range:
    model = KNeighborsClassifier(n_neighbors=k)
    scores = cross_val_score(model, X_scaled, y, cv=3, scoring='accuracy')
    mean_score = scores.mean()
    cv_scores.append(mean_score)
    print(f"k = {k} | Average Accuracy: {mean_score:.2f}")

# Train final model using best K
best_k = k_range[np.argmax(cv_scores)]
print(f"\nBest K: {best_k}")

model = KNeighborsClassifier(n_neighbors=best_k)
model.fit(X_scaled, y)

# Plot K vs Cross-Validation Accuracy
plt.figure(figsize=(8, 5))
plt.plot(k_range, cv_scores, marker='o')
plt.xlabel("K - Number of Neighbors")
plt.ylabel("Cross-Validation Accuracy")
plt.title("Choosing the Best K")
plt.xticks(k_range)
plt.grid(True)
plt.show()

TOPICS 08 / 09 · The Bend
The elbow method
Find where the curve stops paying for itself

The plot at the end of panel 07 is an elbow plot, and the technique has a name. You have a parameter you must choose — the number of neighbours k, the number of clusters k, the number of components — and a score that keeps improving as you turn it up. So "pick the best score" gives you a useless answer: turn it up forever.

The elbow method says: plot the metric against the parameter, and pick the point where the curve stops dropping steeply and flattens out. Before the bend, each extra unit buys you a lot. After it, you are paying complexity for almost nothing. The graph looks like a bent arm, and you want the elbow.

📌 Where you meet it. The classic case is K-Means, where nobody tells you how many clusters exist. The metric is inertia — also called WCSS, the within-cluster sum of squares:
$$\text{inertia} = \sum_{i=1}^{n} \big\| x_i - \mu_{c(i)} \big\|^2$$
the total squared distance from every point to the centre of its own cluster. It always falls as you add clusters — at k = n every point is its own centre and inertia is exactly 0 — so the minimum is worthless and the bend is everything.
Live Demo — 60 points, K-Means run for every k, elbow on the left and the clustering on the right

1 inertia vs k
2 the clusters at this k

Read the drops rather than the values. Going from 1 cluster to 2 removes 2774 of inertia; 2 to 3 removes another 968. Then 3 to 4 removes just 13. The bend is unmistakable, and moving the slider confirms it: at k=3 the three blobs each get their own centre, and every k after that just cuts a blob in half for no real gain.

python — the elbow plot for K-Means
import matplotlib.pyplot as plt
from sklearn.cluster import KMeans
from sklearn.datasets import make_blobs

X, _ = make_blobs(n_samples=60, centers=3,
                  cluster_std=0.9, random_state=42)

inertias = []
k_range = range(1, 9)

for k in k_range:
    km = KMeans(n_clusters=k, n_init=10, random_state=42).fit(X)
    inertias.append(km.inertia_)
    print(f"k={k}  inertia={km.inertia_:.2f}")

plt.plot(k_range, inertias, marker='o')
plt.xlabel("k - number of clusters")
plt.ylabel("Inertia (WCSS)")
plt.title("The Elbow Method")
plt.grid(True)
plt.show()

📐 How to find the bend without squinting. Draw a straight line from the first point of the curve to the last (the dashed line in the demo), then take the point that sits furthest below that line. That is the whole of the kneedle algorithm, and the kneed package implements it: KneeLocator(k_range, inertias, curve='convex', direction='decreasing').elbow. It turns a judgement call into a number, which matters when you are choosing k inside a script rather than by eye.
⚠️ Be honest about its limits. ① Sometimes there is no elbow. On data without well-separated clusters the curve is a smooth slide with no bend, and the method simply has no answer — that is a real result, not a failure to look hard enough. ② It is subjective when the bend is gentle; two people read two different k. ③ For clustering, the silhouette score is a better-behaved alternative: it has an actual maximum you can take an argmax of, because it measures how well-separated the clusters are rather than just how tight they got. Use both and be suspicious when they disagree.
🔬 Why the demo and the printed output drift apart at large k. K-Means only ever finds a local optimum — the answer depends on where the centres start. n_init is the number of random restarts it tries before keeping the best one, and it defaults to 10. Both this demo and sklearn are just reporting the best of their own restarts, so past k=5 they land on slightly different answers in either direction: at k=6 the demo finds 49.32 against sklearn's 49.74, and at k=7 it finds 43.75 against sklearn's 42.53. Around the elbow the two agree to the decimal, because with three obvious blobs every restart converges to the same answer. If your inertia curve moves between runs, that is the algorithm telling you it is not confident — raise n_init.
🎯 Back to KNN for a moment. The same reading applies to the "Choosing the Best K" plot, with one difference: KNN accuracy is a score you maximise, not a cost you minimise, so there is a genuine best point and you can just take the argmax — which is what np.argmax(cv_scores) in panel 07 does. You reach for an elbow when the metric has no best point because it improves forever. Inertia is that kind of metric; accuracy is not.

APPENDIX A1 · The Splitters
More CV splitters
How the folds get cut matters as much as how many there are

Passing cv=3 is a shorthand. What sklearn actually does depends on your estimator: for a classifier it quietly uses StratifiedKFold, and for anything else plain KFold. On sorted data that difference is the whole ballgame — the fruit table lists three apples, then three oranges, then three bananas.

Live Demo — the same 9 fruits, cut three different ways. Colour = the class being tested.
StratifiedKFold(3)
💣 Slide it to KFold(3) and look at what happens. Because the data is sorted by class, the three folds come out as all apples, all oranges, all bananas. Every model is then trained on two classes and tested exclusively on the third one it has never seen — accuracy 0.00, three times over. This is the single most common cause of "my cross-validation score is inexplicably terrible", and the fix is either stratification or shuffle=True.
KFold(n_splits=5)

Cuts the rows into K contiguous blocks, in the order they arrive. Add shuffle=True, random_state=0 unless the row order is meaningful. The default for regression.

StratifiedKFold(n_splits=5)

Keeps each class's proportion the same in every fold. The default for classifiers, and what you want essentially always — especially with imbalanced classes.

LeaveOneOut()

K = n. Each row takes a turn as a one-row test set. Maximum training data, zero waste — and n model fits, so it is only practical on small data. The 9 fruits are exactly the right size for it.

ShuffleSplit(n_splits=10, test_size=.2)

Ten independent random splits. Folds may overlap and some rows may never be tested — useful when you want many repeats but do not need every row covered exactly once.

GroupKFold(n_splits=5)

Guarantees that rows sharing a group id never land on both sides of a split. Essential when you have several rows per patient, per user, or per session — otherwise the model recognises the individual, not the pattern.

TimeSeriesSplit(n_splits=5)

Always trains on the past and tests on the future. For anything with a time axis, the ordinary splitters let the model train on tomorrow to predict yesterday.

APPENDIX A2 · The Fix
Pipeline
Scaling inside cross-validation, made impossible to get wrong

Panels 05 and 07 leave one loose end. Look again at the notebook's code:

✗ subtly wrong — the scaler saw every fold
scaler = MinMaxScaler()
X_scaled = scaler.fit_transform(X)          # ← fitted on ALL 9 rows

scores = cross_val_score(model, X_scaled, y, cv=3)

The scaler was fitted on the whole dataset before the folds were cut. So in every one of the three rounds, the three "unseen" test fruits had already contributed to the min and max used to scale the training data. It is the panel-05 leak, happening once per fold.

The fix is a Pipeline: chain the scaler and the model into one object. cross_val_score then refits the entire chain inside each fold, so the scaler only ever sees that fold's training rows.

✓ right — the scaler is refitted inside every fold
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import MinMaxScaler
from sklearn.neighbors import KNeighborsClassifier
from sklearn.model_selection import cross_val_score

for k in [1, 2, 3, 4, 5, 6]:
    pipe = make_pipeline(
        MinMaxScaler(),
        KNeighborsClassifier(n_neighbors=k)
    )
    # cross_val_score refits the whole pipeline per fold:
    # scaler.fit(train fold) -> transform(train) -> transform(test)
    scores = cross_val_score(pipe, X, y, cv=3)      # ← raw X, not X_scaled
    print(f"k = {k} | Average Accuracy: {scores.mean():.2f}")
✅ Note what disappeared: X_scaled. You hand cross_val_score the raw X and let the pipeline do the scaling at the right moment. Once preprocessing lives inside the estimator, there is no longer a variable lying around that was fitted on the wrong rows — the mistake becomes unexpressible rather than merely discouraged.
🔎 Will the numbers change? On these 9 fruits, barely — MinMax only depends on the min and max of each column, and dropping 3 of 9 rows usually leaves those intact. That is precisely why this bug is so persistent: it rarely changes the answer enough to notice, until the day it does. The habit is what protects you, not the size of the difference on any one dataset.

The same object then works for hyper-parameter search, with the scaler still safely inside every fold:

python — pipeline + grid search, the standard shape
from sklearn.model_selection import GridSearchCV

pipe = make_pipeline(MinMaxScaler(), KNeighborsClassifier())

# step name + '__' + parameter name
grid = {'kneighborsclassifier__n_neighbors': [1, 2, 3, 4, 5, 6]}

search = GridSearchCV(pipe, grid, cv=3, scoring='accuracy')
search.fit(X, y)

print("best params:", search.best_params_)
print("best score :", search.best_score_)

# search.best_estimator_ is a fitted pipeline — hand it a raw
# row and it scales, then predicts, with the training statistics
print(search.best_estimator_.predict([[210, 7, 155]]))
🎁 The quiet payoff. best_estimator_ is a single object that carries the scaler and the model together. Pickle it, ship it, and at prediction time it applies the exact training statistics to whatever raw row arrives. No separate scaler file to keep in sync, and no chance of loading yesterday's model with today's scaler — which is a genuine production incident, not a hypothetical one.
