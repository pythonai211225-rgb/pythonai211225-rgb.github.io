SVM 01 / 07 · The Algorithm
The idea
Not just a line that separates — the line that separates by the most
SVC(kernel='linear') margin margin — the empty corridorThe width of the strip around the boundary that contains no training point. SVM maximizes it. → a class label

SVM (Support Vector Machine) is a supervised learning method. You give it labelled examples, it learns a rule. It is used for classification — and, with a different loss, for regression too.

The goal in one sentence: find the boundary that separates the classes with the largest possible gap.

1 · Separate

Find a line (2D), a plane (3D), a hyperplane (nD) that puts every class on its own side.

2 · Measure

For each candidate, measure the distance to the closest point of either class.

3 · Maximize

Keep the candidate whose closest point is the furthest away. That is the SVM.

🎯 Why the widest gap? A boundary that scrapes past a training point is fragile — nudge that point a little and the prediction flips. A boundary with a wide empty corridor on both sides survives noise. Wide margin = confident, general classifier.

The points sitting exactly on the edge of the corridor are the support vectors. They are the only points that matter:

  • Move a point that is far from the boundary — nothing changes.
  • Move a support vector — the whole boundary moves.
  • Delete every non-support-vector and refit — you get exactly the same model.
📌 Why "vector" and not "point"? In linear algebra every point in space is a vector from the origin: [3, 4] is both the point (3,4) and the arrow that reaches it. The points closest to the boundary support its position — hence support vectors.

SVM 02 / 07 · The Mathematics
The hyperplane
One equation, any number of dimensions
w @ x + b = 0 w w — the weight vectorPoints perpendicular to the surface. It sets the direction of the boundary, never a position. b b — the biasSlides the surface along w without turning it. In sklearn this is intercept_. → one number: +, − or 0

A hyperplane is the flat separating surface. In 2D it is a line, in 3D a plane, in n dimensions a hyperplane. It is always the same equation:

$$w^{T}x + b = 0 \qquad\Longleftrightarrow\qquad w_1x_1 + w_2x_2 + \dots + w_nx_n + b = 0$$
symbolnamewhat it is
\(w\)weight vectorThe direction of the surface — perpendicular to it (the normal)
\(x\)the pointAny point in the space; a row of features
\(w^{T}x\)dot productThe plain scalar product \(w_1x_1 + w_2x_2 + \dots\)
\(b\)biasWhere the surface cuts the axes — how far it sits from the origin

A concrete 2D example, exactly as on the class slide — with w = [2, -3] and b = 6:

$$2x_1 - 3x_2 + 6 = 0$$

And the whole classification rule falls out of the sign:

$$w^{T}x + b > 0 \;\Rightarrow\; \text{one side}\qquad w^{T}x + b < 0 \;\Rightarrow\; \text{the other side}\qquad w^{T}x + b = 0 \;\Rightarrow\; \text{exactly on it}$$
📐 That is the entire prediction step. Once w and b are trained, classifying a new point is one dot product, one addition and one look at the sign. No distances to every training point (unlike KNN), no loops.

⚠️ w is a direction, not a place. Doubling w and b together gives the exact same surface — 4x₁ − 6x₂ + 12 = 0 draws the same line. Only the ratio matters. SVM pins that freedom down with a convention: it scales w and b so the closest point of each class lands at exactly wᵀx + b = ±1, which is why coef_ comes back with the particular numbers it does.
SVM 03 / 07 · The Mathematics
Distance to a hyperplane
Plug the point in, divide by the length of w
(w @ x + b) / np.linalg.norm(w) → signed float abs() → the plain distance

Given a hyperplane \(w_1x_1 + w_2x_2 + \dots + w_nx_n + b = 0\) and a point \(x = (x_1, x_2, \dots, x_n)\), there are two formulas — and they differ by exactly one pair of bars:

$$\textbf{Distance}(x) = \frac{|\,w \cdot x + b\,|}{\|w\|}$$
$$\textbf{SignedDistance}(x) = \frac{w \cdot x + b}{\|w\|}$$
$$\|w\| = \sqrt{w_1^2 + w_2^2 + \dots + w_n^2}$$
partmeaning
numerator \(w\cdot x + b\)Substitute the point into the plane equation. Zero means it is on the plane.
denominator \(\|w\|\)The length of the weight vector — np.linalg.norm(w). It normalizes away the scale freedom.
the bars \(|\cdot|\)Drop the sign → a plain, never-negative distance.
no barsKeep the sign → which side plus how far, in one number. This is decision_function.
💡 Why divide by ‖w‖ at all? Because 2x − 3y + 6 = 0 and 4x − 6y + 12 = 0 are the same line, but the second one gives numerators twice as big. Dividing by ‖w‖ cancels that out, so the answer is a real geometric distance in the units of the axes.

In code — the function we wrote in class, for two features:

python — signed and absolute distance
import numpy as np

def get_signed_distance(point, w1, w2, b):
    x1, x2 = point
    numerator   = x1 * w1 + x2 * w2 + b
    denominator = np.sqrt(w1**2 + w2**2)    # = np.linalg.norm([w1, w2])
    return numerator / denominator

def get_abs_distance(point, w1, w2, b):
    return np.abs(get_signed_distance(point, w1, w2, b))

python — copy, paste, run
import numpy as np
from sklearn.svm import SVC

# ---------- the points ----------
group_a = np.array([ [1, 2], [1.5, 3], [2, 2.5], [2.5, 3.5] ])
group_b = np.array([ [5, 5], [5.5, 6], [6, 5.5], [6.5, 6.5] ])

# ---------- X and y ----------
points = np.vstack([group_a, group_b])          # shape (8, 2) - one row per point
labels = np.array([0, 0, 0, 0, 1, 1, 1, 1])   # 0 = group A, 1 = group B

# ---------- train ----------
clf = SVC(kernel='linear')
clf.fit(points, labels)

w = clf.coef_[0]          # the weight vector
b = clf.intercept_[0]     # the bias

print('w', w)
print('b', b)
print('support vectors', clf.support_vectors_)

# ---------- predict a new point ----------
print('predict (1, 2)  ->', clf.predict([[1, 2]]))
print('predict (6, 6)  ->', clf.predict([[6, 6]]))

Appendix A1 · The Trick
Why kernels
No straight line works? Change the room, not the ruler.
SVC(kernel='rbf') just the idea — no maths on this slide

Everything so far assumed one thing: that a straight boundary can do the job. Very often it cannot. A ring of one class around a blob of another, two interleaving crescents, a checkerboard — no line, no plane, nothing flat will ever separate those.

❓ The problem, in one picture. Put class A near zero on a number line and class B far out on both sides. There is no single cut-off that puts all of A on one side and all of B on the other. The data is simply not linearly separable in that space.

The trick is not to bend the boundary. It is to move the data into a bigger space where a flat boundary is enough, and let SVM do exactly what it already does well.

1 · Lift

Give every point extra coordinates computed from the ones it already has.

2 · Separate

In the bigger space the classes come apart, and a plain flat hyperplane splits them.

3 · Look back

Project that flat cut back down. In the original space it looks like a curve.

Live Demo — drag the lift. At 0 the points are on one line and nothing separates them.
0%
class A (middle) class B (outside) a flat boundary
✨ And here is why it is called a trick. Building those extra coordinates is expensive — some useful lifts have thousands of dimensions, some are infinite. SVM never builds them. Everything in the maths only ever needs to know how similar two points are in the big space, and a kernel is a small function that answers that directly from the original coordinates. You get the power of the huge space for the price of the small one.

Which lift you get is chosen by the kernel= argument. The four that ship with SVC:

kernel='linear'

↳ Problem: none — the classes are already separable by a straight cut.
↳ What it does: no lift at all. The plain hyperplane from the main deck.

Fastest, and the only kernel where coef_ exists, so it is the only one you can read as "feature 3 mattered this much". Reach for it first with lots of features and few rows — text, for example.

kernel='poly'

↳ Problem: the frontier between the classes is curved but smooth — a parabola, an ellipse, a bowl.
↳ What it does: adds products and powers of the original features as new coordinates, so a flat cut up there is a smooth curve down here.

Controlled by degree (2 = gentle bends, 5 = wild) and coef0. Degree 2 or 3 is almost always the useful range; higher degrees overfit fast and train slowly.

kernel='rbf' the default

↳ Problem: the classes form blobs, islands and rings with no simple shape at all — one class completely surrounded by the other.
↳ What it does: gives every training point a bubble of influence that fades with distance, and builds the boundary out of those bubbles. It can wrap around anything.

Controlled by gamma — how tight each bubble is. Small gamma = broad, smooth, almost linear. Large gamma = tiny bubbles that hug individual points, and the model memorizes the training set. This is the most powerful kernel and the easiest one to overfit with.

kernel='sigmoid'

↳ Problem: historical — it mimics the activation used in a two-layer neural network.
↳ What it does: produces boundaries in a similar family to a small neural net.

Included for completeness and rarely the best answer in practice. It is also the one kernel that is not always a valid similarity measure for every setting of its parameters, so it can behave oddly. Try rbf first.

📌 Practical order: start with linear — if it is good enough, it is fast, interpretable and hard to overfit. If the score is poor, go to rbf and tune C and gamma together with a grid search. Try poly when you have a reason to believe the frontier is a smooth curve. Go to appendix A2 and see all four at once.

🧪 Three experiments worth doing right now:
1 · circles + linear — accuracy stalls around 64% and nearly every point becomes a support vector, because no straight line can wrap around a ring. Switch to rbf and it snaps to 100% with a handful of SVs.
2 · xor + linear — stuck at 75%: three quadrants right, one always wrong. Now switch to poly with degree = 2 and it hits 100% using only 6 support vectors — a clean cross-shaped boundary.
3 · moons + rbf — at the default gamma you get ~93% with about 24 support vectors. Push gamma all the way right: accuracy climbs to ~98%, but the support-vector count jumps to 51 of 56 and the boundary breaks into islands hugging individual points. Higher score, worse model. That is overfitting, live.
💡 C and gamma interact. They are almost never tuned separately — a big gamma with a big C memorizes the data, a small gamma with a small C underfits. In real work you search them together on a log grid: GridSearchCV(SVC(), {'C': [0.1, 1, 10, 100], 'gamma': [0.001, 0.01, 0.1, 1]}).

SVM 06 / 07 · The Verdict
Pros & cons
When to reach for SVM, and when to walk away

✅ Advantages

  1. Works in very high dimensions — even when you have more features than rows, which breaks most other models.
  2. Memory-light at prediction time — only the support vectors are stored, often a small fraction of the data.
  3. One global optimum — convex problem, so no random seeds, no local minima, reproducible every run.
  4. Kernels are a genuine superpower — swap one string and you get curved, ring-shaped or island boundaries.
  5. Margin maximization resists overfitting better than a boundary that merely separates.

❌ Disadvantages

  1. Scales badly with rows — training cost grows roughly between n² and n³. Beyond ~100k samples it becomes painful.
  2. No probabilities out of the box — probability=True runs an extra internal cross-validation and is slow.
  3. Very sensitive to feature scaling — forget the scaler and the result is garbage.
  4. C and gamma must be tuned — the defaults are rarely the best, and a grid search costs time.
  5. Hard to interpret with a kernel — with rbf there is no coef_, so you cannot say which feature drove the decision.
  6. Sensitive to outliers near the boundary — a single mislabelled point can drag the corridor.
⚖️ Honest verdict. SVM is excellent on small-to-medium, clean, well-scaled datasets — especially wide ones like text and gene expression. On big tabular data with hundreds of thousands of rows, gradient-boosted trees will usually be both faster and more accurate. Learn SVM anyway: the margin idea and the kernel trick show up everywhere in machine learning.
use SVM when…use something else when…
Fewer than ~50k rowsHundreds of thousands of rows → SGDClassifier / LightGBM
Many features, few samples (text, genomics)You need calibrated probabilities → logistic regression
Clear separation between classesHeavy class overlap and noise → trees / boosting
The boundary is curved but the data is cleanYou must explain each prediction to a regulator

SVC parameters
Every knob on the class, and which two actually matter
python — the signature, with defaults
SVC(C=1.0, kernel='rbf', degree=3, gamma='scale', coef0=0.0,
    shrinking=True, probability=False, tol=0.001, cache_size=200,
    class_weight=None, max_iter=-1, decision_function_shape='ovr',

parameterdefaultwhat it does
C1.0Tune this. The price of letting a point sit inside the corridor. Big = strict and narrow, small = forgiving and wide.
kernel'rbf''linear', 'poly', 'rbf', 'sigmoid', or your own callable.
gamma'scale'Tune this for rbf/poly/sigmoid. How tightly each point's influence is felt. 'scale' = 1/(n_features·X.var()), 'auto' = 1/n_features.
degree3Only used by 'poly'. Ignored by every other kernel.
coef00.0The constant term in 'poly' and 'sigmoid'. Ignored by linear and rbf.
class_weightNone'balanced' reweights classes by inverse frequency — the first thing to try on imbalanced data.
probabilityFalseEnables predict_proba via internal 5-fold Platt scaling. Slow to fit, and can disagree with predict.
decision_function_shape'ovr'Shape of the decision_function output for multi-class. Cosmetic — the underlying fit is always one-vs-one.
tol / max_iter1e-3 / −1Stopping rules. max_iter=-1 means run until converged. Raise tol if a big fit will not finish.
cache_size200MB of kernel cache. Raising it to 1000 can genuinely speed up a large fit.
🔢 Multi-class with SVC. SVM is binary at heart. Give SVC three or more classes and it silently trains one classifier per pair — n·(n−1)/2 of them — and votes. Ten classes means 45 models, which is why SVC gets slow on many-class problems. decision_function_shape='ovr' only reshapes the output; it does not change how the fitting is done.
python — the shape you should actually write
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import train_test_split, GridSearchCV
from sklearn.svm import SVC

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.25,
                                                    random_state=42, stratify=y)

pipe = make_pipeline(StandardScaler(), SVC(kernel='rbf'))

grid = GridSearchCV(pipe, {
    'svc__C':     [0.1, 1, 10, 100],
    'svc__gamma': [0.001, 0.01, 0.1, 1],
}, cv=5, n_jobs=-1)

grid.fit(X_train, y_train)
print(grid.best_params_, grid.best_score_)
print('test:', grid.score(X_test, y_test))
✅ The scaler goes inside the pipeline, not before the split. Fitting a scaler on the full dataset lets test-set statistics leak into training. Inside a pipeline, GridSearchCV refits the scaler on each training fold only — which is the whole point.
